       Motivation 
 Agent workflows often involve non-linear conversation patterns where context from previous turns becomes obsolete after summarization. Traditional KV cache management cannot efficiently handle these patterns, leading to: 
 
 Unnecessary memory consumption from stale conversation history 
 Reduced throughput due to memory pressure 
 Inefficient cache utilization 
 Lack of visibility into cache performance metrics 
 
 This PR implements  semantic-aware KV cache pruning  for SGLang's radix cache, enabling efficient handling of multi-round conversations with explicit semantic events ( start  and  reset ). Additionally, it adds comprehensive  KV cache metrics and monitoring  infrastructure to provide visibility into cache performance. 
 Acknowledgments 
 This work builds upon foundational contributions from other community members: 
 
   @dougyster   (Doug Yang, Harvard): Initial KV cache endpoint infrastructure ( 8210284a2 ,  48cd09ff0 ) that provided groundwork for KV cache monitoring. 
 
 Modifications 
 Part 1: Semantic-Aware KV Cache Pruning 
 Core Data Structures 
 
   io_struct.py  : Added  semantic_event  field to  GenerateReqInput  and  TokenizedGenerateReqInput  
   protocol.py  : Added  semantic_event  field to OpenAI API request models 
 
 OpenAI API Endpoints 
 
   serving_completions.py  : Pass  semantic_event  to internal request 
   serving_chat.py  : Pass  semantic_event  to internal request 
 
 Tokenizer & Request Processing 
 
   tokenizer_manager.py  : Fixed  session_params  handling; Empty dict  {}  now creates  SessionParams()  instead of  None  
 
 Scheduler & Session Management 
 
   scheduler.py  : Auto-create session when  semantic_event  provided; Pass  semantic_event  to  Req  object; Return  session_id  in response metadata 
 
 Scheduling Policy 
 
   schedule_policy.py  :
 
 Added  _prioritize_reset_requests()  method to prioritize reset requests in waiting queue 
 Modified  calc_priority()  to call prioritization at the beginning 
 Reset requests are processed before normal requests for faster memory cleanup 
 
 
 
 Output Processing 
 
   scheduler_output_processor_mixin.py  :
 
 Implemented  deferred batch pruning  with three phases:
 
  Collect : Gather all reset requests that finished in the batch 
  Unlock : Release locks for all collected requests (decrement  lock_ref ) 
  Prune : Perform pruning for all collected requests 
 
 
 Added semantic event handling in both prefill and decode batch processing 
 Eliminates race conditions where multiple reset requests share parent nodes 
 
 
 
 Radix Cache 
 
   radix_cache.py  :
 
 Added  prune_from_node()  method for semantic-aware pruning 
 Added  _node_exists()  method for safety checks 
 Added comprehensive safety checks:
 
 Double-free protection (prevent pruning already-deleted nodes) 
 Root protection (prevent pruning root or its immediate children) 
 Child constraint checks (prevent pruning nodes with children) 
 
 
 
 
 
 Part 2: KV Cache Metrics and Monitoring 
 Metrics Collection 
 
   a4e22d249  : Add KV cache slot utilization tracking and metrics 
   724ba9b29  : kvcache states as prometheus metrics 
   a98047c34  : kv cache logging metrics computation 
   192b60d49  : grafana label support 
 
 Infrastructure 
 
   6ad408c51  : Fix dev.Dockerfile: add setuptools and fix syntax error 
   e5fdb20bf  : Update sglang submodule URL to use forked repository 
 
 Part 3: Documentation 
 
   function_design.md  : Comprehensive documentation of design, implementation, problems encountered, solutions, and performance impact 
 
 Usage 
 Backward Compatibility 
  The usual pattern is fully preserved . Existing applications continue to work without any changes: 
   # Standard usage - no semantic_event needed 
 response   =   client . chat . completions . create (
     model  =  "seed-oss-36b-instruct" ,
     messages  = [
        { "role" :  "user" ,  "content" :  "Hello" }
    ]
)  
 Semantic-Aware Pruning 
  Semantic events are only triggered when explicitly specified  in the request payload: 
   # Start a new conversation session 
 response   =   client . chat . completions . create (
     model  =  "seed-oss-36b-instruct" ,
     messages  = [
        { "role" :  "user" ,  "content" :  "Let's start a conversation" }
    ],
     extra_body  = {
         "semantic_event" :  "start"    # Auto-creates session 
    }
)
 session_id   =   response . extra_body . get ( "session_id" )

 # ... multiple conversation rounds ... 

 # Reset conversation after summarization 
 response   =   client . chat . completions . create (
     model  =  "seed-oss-36b-instruct" ,
     messages  = [
        { "role" :  "user" ,  "content" :  "Summarize our conversation" }
    ],
     extra_body  = {
         "semantic_event" :  "reset"    # Prunes old history 
    }
)  
 Session Management 
 Sessions can also be managed explicitly: 
   # Create session with explicit ID 
 response   =   client . chat . completions . create (
     model  =  "seed-oss-36b-instruct" ,
     messages  = [
        { "role" :  "user" ,  "content" :  "Hello" }
    ],
     extra_body  = {
         "session_params" : {
             "id" :  "my-session-123" 
        }
    }
)  
  Key Points:  
 
  No breaking changes : Existing code works without modification 
  Opt-in feature : Semantic pruning only activates when  semantic_event  is specified 
  Flexible : Can use auto-created sessions or explicit session IDs 
  Efficient : Reset requests are prioritized for faster memory cleanup 
 
 Accuracy Tests 
 This PR does not affect model outputs (no changes to kernels or model forward code). All changes are in: 
 
 Request handling and metadata management 
 Scheduling and batch processing 
 KV cache pruning and memory management 
 Metrics collection and monitoring 
 
 No accuracy tests are required as model inference behavior remains unchanged. 
 Benchmarking and Profiling 
 Test Configuration

This commit implements several critical improvements to the semantic-aware KV cache
pruning system to handle concurrent requests more efficiently and safely.

## Key Changes

### 1. Reset Request Prioritization (schedule_policy.py)
- Added `_prioritize_reset_requests()` method to prioritize reset requests in the waiting queue
- Modified `calc_priority()` to call prioritization at the beginning of scheduling
- Reset requests are now processed before normal requests, enabling faster memory cleanup

### 2. Deferred Batch Pruning (scheduler_output_processor_mixin.py)
- Implemented three-phase pruning: collect, unlock, prune
- Phase 1: Collect all reset requests that finished in the batch
- Phase 2: Release locks for all collected requests (decrement lock_ref)
- Phase 3: Perform pruning for all collected requests
- Eliminates race conditions where multiple reset requests share parent nodes

### 3. Safety Checks in Pruning (radix_cache.py)
- Added `_node_exists()` method to check if a node is still in the tree
- Added double-free protection to prevent pruning already-deleted nodes
- Added root protection to prevent pruning root or its immediate children
- Added child constraint checks to prevent pruning nodes with children

### 4. Documentation Updates (function_design.md)
- Documented all new features and changes
- Added performance impact analysis
- Documented three additional problems and their solutions:
  - IndexError in tokenizer manager (concurrent requests)
  - Race condition with concurrent reset requests
  - Double-free and root protection issues

## Performance Impact

- Eviction rate: Lower (more efficient cache management)
- Average TTFT: Decreased (faster time to first token)
- Available slots: 4% → 3% (time-averaged, tighter utilization)
- Evictable ratio: 8.99% → 8.76% (more aggressive pruning)
- New prefill tokens: 16.9% decrease (more cache hits)

- test_kv_cache_session.py
- test_kv_cache_session_openai_client.py
- test_kv_cache_session_concurrent.py
