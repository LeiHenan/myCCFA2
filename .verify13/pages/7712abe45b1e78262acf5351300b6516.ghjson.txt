       … caching

Anthropic SDK clients (e.g. Claude Code) include an
`x-anthropic-billing-header` block in the system prompt that contains a
per-request conversation context hash (`cch=...`). Because this block is
the first system prompt entry and changes on every request, it produces a
different token prefix each time, defeating RadixAttention prefix caching
for the entire conversation.

By stripping this metadata block (which carries no semantic meaning for
the model), consecutive requests from the same conversation now share a
stable token prefix. In testing with Claude Code + Kimi-K2.5 (MLA,
262K context), this improved prefix cache hits from ~4,800 tokens to
~20,800+ tokens — reducing per-turn prefill from ~18 seconds to
near-instant.
