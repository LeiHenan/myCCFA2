 Motivation 
 Follow-up correctness fix for the session-reference support in #29173 , not a new retention policy. 
 When a hybrid FULL+MAMBA request reuses an existing prefix but finishes without a new usable Mamba checkpoint ( None or zero), terminal insertion can return the root. cache_finished_req replaces the request's prior reusable leaf with that root before session registration. Registration excludes the root, so the valid earlier prefix receives no FULL or MAMBA session reference and loses its session-aware eviction protection. 
 Modifications 
 Only replace req.last_node when terminal insertion supplies a non-root device leaf. Existing request locks, stale-generation rejection, abort handling, session close and ordinary eviction are unchanged. This does not pin KV or add a new memory-allocation policy. 
 Extend the existing registered session-cache unit module with a native FULL+MAMBA allocator/tree fixture covering missing/zero/new checkpoints, no prior prefix, abort, no-insert and stale-generation cases. The new regression explicitly tests the Python tree implementation; it does not claim independent Rust-tree qualification. 
 Accuracy Tests 
 No kernel/model arithmetic changes. The following tests cover cache ownership 
and allocator correctness; no new task-accuracy measurement is claimed. 
 Base: 7763f666f348d99e28a3dc839e99adf5cd7e1861 ; candidate: 5299ea2035488f82dbfcf87764bf6f6cc46ec76d . 
 Actual registered module: 5 tests pass , including seven new subcases and recovery of all 2,048 allocated KV slots after session close/eviction. 
 Negative control removing only this production guard: exactly the missing-checkpoint and zero-checkpoint subcases fail; no test errors. Restoring the patch makes the entire module pass. 
 Repository pre-commit and git diff --check pass. 
 PYTHONPATH=python:test/registered/unit/mem_cache \
SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=python \
python -m unittest test_session_unified_radix_cache -v 
 The tests ran against the actual native cache/pool implementations in an isolated ROCm environment; no model was loaded. Maintainer CPU CI and cache-owner review remain welcome; keeping this draft while those reviews are pending. 
 Speed Tests and Profiling 
 No new serving speedup is claimed. This is a correctness repair to existing 
session-reference registration, not a new retention or eviction algorithm. 
 Checklist 
 Narrow production change with native regression coverage. 
 Negative control demonstrates the defect on the tested main revision. 
 Existing session-ref feature credited rather than claimed as new. 
 AI assistance disclosed: implementation and tests developed with Codex; human maintainer review requested.
