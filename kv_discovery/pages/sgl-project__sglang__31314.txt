Motivation

This PR avoids a redundant KV index tensor copy when inserting finished or unfinished requests into the Mamba radix cache.

The change reduces unnecessary device-memory allocations and helps prevent gradual HBM growth under sustained Mamba workloads.

Code Review

This pull request introduces a take_value_ownership parameter to the insert and _insert_helper methods in MambaRadixCache to avoid cloning the value tensor when ownership is transferred from the caller, and adds a corresponding unit test. The reviewer suggests further optimizing this by completely bypassing the clone() operation when take_value_ownership is True, regardless of whether total_prefix_length is zero, because the memory footprint of the 1D tensor is small and the overhead of a CUDA clone is relatively high.

Since value is a 1D tensor of int64 indices, its memory footprint is extremely small (typically less than 64 KB even for very long sequences). The overhead of a CUDA clone() operation (which involves a new allocation from PyTorch's caching allocator and launching a copy kernel) is significantly higher than the negligible memory saved by freeing the matched prefix indices.

Therefore, we can avoid cloning entirely when take_value_ownership is True, even if total_prefix_length > 0. This further reduces CUDA allocation overhead and improves performance.
