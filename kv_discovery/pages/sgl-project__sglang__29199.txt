Summary

This PR adds the first experimental slice of agent-aware KV cache support.

Changes include:

- Add optional agent_hints request metadata for OpenAI-compatible chat and completion requests.

- Propagate agent_hints through request normalization, tokenizer manager, scheduler request construction, and session request handling.

- Annotate radix-cache nodes with optional agent metadata such as workflow ID, agent ID, step ID, parent step ID, TTL, expected tool duration, and reuse hint.

- Add an experimental agent_aware radix eviction policy.

- Add unit coverage for protocol parsing, request normalization, radix metadata annotation, and eviction priority behavior.

Motivation

Agentic workloads often issue multi-step requests where KV reuse value depends on workflow context, expected tool latency, and future reuse likelihood.

This PR keeps the implementation intentionally narrow:

- Existing behavior is unchanged by default.

- agent_hints is optional metadata.

- The new eviction behavior is only used when the experimental agent_aware policy is selected.

- TTL and reuse hints are soft eviction-ranking signals, not hard pinning.

References

SGLang / RadixAttention: motivates KV-cache reuse for structured, multi-call language model programs. This PR builds on that idea by attaching optional workflow metadata to radix-cache nodes.

PagedAttention / vLLM: shows that KV-cache memory management is a core bottleneck in LLM serving. This PR adds a small policy hook for metadata-aware cache eviction.

KVFlow: directly motivates workflow-aware KV-cache management for multi-agent workloads, where LRU can evict entries shortly before reuse. This PR implements only a narrow metadata and eviction-ranking subset of that idea.

Mooncake: treats KV cache as a first-class serving resource. This PR follows the same high-level direction, but does not implement distributed KV-cache scheduling or transfer.

LMCache: motivates explicit KV-cache reuse across engines and queries. This PR does not add a KV-cache API, but prepares a small metadata path useful for future cache-control work.

Scope

This PR does not implement:

- Programmatic KV cache APIs

- Router changes

- Distributed cache migration

- HiCache / Mooncake / NIXL integration

- Hard cache pinning

- Cross-worker KV movement

- Shared-prefix routing

Those are larger follow-up areas.
