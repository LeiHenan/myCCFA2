Preserve target KV dtype when draft runners resolve auto

With speculative decoding, the draft worker is initialized with the same published server_args object after the target runner has already recorded any load-time KV dtype into RuntimeContext flags. Because kv_cache_dtype is now retired from dual-apply, that runtime override no longer mutates server_args, and this resolved_view(self.server_args) read only sees the pristine/stashed value (often auto), not the published flag leaf. A draft model whose quant_config.kv_cache_quant_algo is FP8 can therefore enter the auto branch and _record_kv_cache_dtype() overwrites the process-global target flags with the draft dtype before memory pools/backends are initialized, causing target-side readers of get_flags().kv_cache_dtype to use the wrong dtype.
