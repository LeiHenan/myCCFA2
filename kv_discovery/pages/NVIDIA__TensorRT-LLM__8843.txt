[GRAPHQL COMMENT by QiJune assoc=COLLABORATOR at 2025-11-06T13:14:53Z]
Hi @NEWbie0709 ,

>1. What is the effective default KV cache dtype here when using kv_cache_dtype="auto"

The KV cache dtype "auto" means use the value in the hf_quant_config.json, which is defined in https://huggingface.co/nvidia/NVIDIA-Nemotron-Nano-9B-v2-NVFP4/blob/main/hf_quant_config.json#L8.

```
"kv_cache_quant_algo": null,
```

Since the kv_cache_quant_algo is null, which means KV cache is not quantized, the effective KV cache dtype is bfloat16.

> 2. Can I lower the KV cache precision (e.g., FP8) to reduce VRAM and push longer context?

Yes, you can try to FP8 KV cache. Usually, the TRT-LLM attention kernels should support it.

> 3. How do i lower it?

There are 2 ways:
1. modify the `kv_cache_quant_algo` in `hf_quant_config.json`, please set it to `FP8`.

```yaml
"kv_cache_quant_algo":"FP8",
```
2. set it at runtime, you can set it in `extra_llm_api_options.yaml` of `trtllm-serve`

```yaml
kv_cache_config:
  dtype: fp8
  free_gpu_memory_fraction: 0.95
  enable_block_reuse: false
```

```bash
trtllm-serve nvidia/NVIDIA-Nemotron-Nano-9B-v2-NVFP4 --extra_llm_api_options extra_llm_api_options.yaml
```

> 4. Is KV cache dtype configurable at serve time (trtllm-serve) or only at build time (trtllm-build)?

At serve time(trtllm-serve). We don't use `trtllm-build` command in TRT-LLM PyTorch backend any more.


> 5. If only at build time, what are the recommended flags for Blackwell RTX (5090) vs smaller VRAM cards (5060 Ti) to optimize 30k context?

It can be set at runtime.
