Suggestion PR against #53781 (base: feat/hisparse-mla-decode-main). Merge it into that branch or cherry-pick; close it if you disagree.

What

HiSparse currently encodes "this memory lives on the host" three separate ways:

- KVCacheTensor.host_resident

- KVCacheGroupRole.HISPARSE_SOURCE, paired with a nullable block_pool_id

- KVCacheConfig.hisparse_host_num_blocks

Every consumer reconciles them independently, and KVCacheConfig.__post_init__ exists mostly to check that the three agree with each other.

This replaces all three with placement on the block pool:

class KVCachePlacement(str, Enum):
 DEVICE = "device"
 HOST = "host"

@dataclass
class KVCacheBlockPoolSpec:
 num_blocks: int
 placement: KVCachePlacement = KVCachePlacement.DEVICE

KVCacheConfig.block_pools carries them, so block_pool_id becomes a plain int on groups, tensors, blocks and copies, and host_block_pool_id / host_group_ids / host_layer_names answer placement questions directly.

Net effect on this PR's diff vs main: 183 insertions, 204 deletions (-21).

What it collapses

- __post_init__ goes from 35 lines of cross-field validation to 6.

- Every block_pool_id is None / pool_id is not None guard and assert disappears (kv_cache_manager, worker/utils, attn_utils, hisparse_coordinator, nixl, mooncake).

- NIXL stops deriving the host block count from cache.shape[0] // physical_blocks_per_logical_kv_block — it reads block_pools[pool_id].num_blocks like every other group.

- Mooncake and NIXL both ask layer_name in kv_cache_config.host_layer_names instead of threading a tensor_configs map through to reach host_resident. Both local maps are now dead and removed.

- get_unique_kv_cache_group_id is gone; the host group is identified by placement.

- hisparse_coordinator.owns_block becomes block.pool_id == self.host_block_pool_id instead of a bounds-and-identity check against the host pool's block list.

Deliberate scope boundaries

- KVCacheGroupRole is kept, with HISPARSE_INDEXER only. That is a functional role, orthogonal to placement, and it selects offloading groups in offloading/config.py. Expressing it as "device groups with enable_kv_transfer" would also pick up regular (non-MLA) groups when a model has them, which I could not verify, so I left the selection untouched.

- The host pool is still built by HiSparseCoordinator.create_host_block_pool and coordinator.block_pools remains device-only. It now reads its size from block_pools[host_id] rather than a dedicated field. Folding the host pool into the runtime pool list is a larger behavioral change (watermarks, admission tuples) and is not part of this PR.

Behavior changes to review

- KVCacheManager.take_new_block_ids now explicitly skips host groups. Previously host groups fell out of the device bookkeeping implicitly, because their block_pool_id was None.

- Host KVCacheBlockCopy.block_pool_id is now the host pool id rather than None. HiSparseConnector.build_connector_meta filters on that id; test_hisparse_host_cow_copy_is_drained_without_a_gpu_pool was updated to match.

Not duplicating existing work

Checked gh pr list --repo vllm-project/vllm --state open --search "hisparse" and --search "53781 in:body". The open HiSparse PRs (#53782, #55398, #55970, #53592, #52760, #53263) are feature work in other areas. This targets only the placement encoding introduced by #53781, which is untouched by them. It is also deliberately not the KV-cache-planning refactor you already landed in 8645447 and c2e4512 — this sits on top of those.
