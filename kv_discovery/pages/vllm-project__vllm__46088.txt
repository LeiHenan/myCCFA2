## Not reproduced on GLM-5.2 stack (r28 image, AIBoss RTX 5090)

Tested for cross-sequence token bleed under concurrent batching on the local-inference-lab/vllm fork (`dev/gilded-gnosis`, r28 image).

### Test

Model: `malaiwah/GLM-5.2-SIQ-Fruit-Instruct` (GLM-5.2 MLA, 5B, TP1) with `--kv-cache-dtype nvfp4_ds_mla --max-num-seqs 16 --enable-chunked-prefill`.

Sent 5 concurrent completions requests with distinct, unambiguous prompts:
```
"Repeat after me: APPLE. The word is"   → expected "APPLE"
"Repeat after me: BANANA. The word is"  → expected "BANANA"
"Repeat after me: CHERRY. The word is"  → expected "CHERRY"
"Repeat after me: DATE. The word is"    → expected "DATE"
"Repeat after me: ELDERBERRY. The word is" → expected "ELDERBERRY"
```

Also tested mixed-length concurrent requests (short + ~1,250-token long prompts together).

### Result

**No cross-sequence bleed detected.** Each response contained only content from its own prompt's context — no response mentioned another sequence's word. The model (5B instruct) didn't follow the "repeat after me" instruction well (returned generic text), but the outputs were not contaminated with other sequences' content.

The sequential baseline produced the same "wrong" answers as the concurrent batch, confirming the model simply doesn't follow the instruction — it's not a KV isolation bug.

### Note

This test was **without MTP speculative decoding** (Fruit's MTP layer requires a different attention backend configuration that doesn't boot on the single-GPU test setup). The original bug report is specific to MTP + `--kv-cache-dtype auto`. The fork uses `nvfp4_ds_mla` (not `auto`), and the B12X MLA sparse backend handles KV-slot alignment differently from stock FlashInfer. The fork's commit `c653763ac` (spec+structured-output reasoning-boundary fix) also addresses MTP token accounting.
