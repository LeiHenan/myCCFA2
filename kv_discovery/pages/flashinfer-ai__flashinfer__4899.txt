📌 Description

The logits a sparse-attention selector ranks by, over a paged KV cache:

score(row, col) = sum_h max(0, dot(K[col], Q[row, h])) / divisor

There is no softmax and no value aggregation — this is the input to a top-k, not an attention output. Producing it with the existing prefill kernels means materialising an attention output nobody reads.

API and contract

sparse_paged_scores(q, k_cache, page_table, token_to_req, query_positions, sequence_lengths, compress_ratio, divisor, num_columns=None, logits=None, visible_blocks=None)

q is [rows, num_heads, head_dim], float16 or bfloat16, head_dim 64/128/192/256 and at most 16 heads. k_cache is [pages, page_size, head_dim].

A query sees only the compressed entries whose tokens are all behind it. Entries on a page the block table does not map come out as -inf, so a top-k never selects them. Columns past what the query can see are left untouched instead, and the returned count is the number of entries actually scored — what the query can see, capped by the column width — so a top-k bounds itself by that count rather than by the width.

The ReLU applies to a head's completed dot product, so the feature axis is fully accumulated before the heads are summed.

Both staged loads are 128 bits wide. Strides alone do not settle whether every address they form is aligned — a view onto the middle of a tensor keeps its strides and carries a base that is not — so the query includes its base in the test it runs and falls back to an element-wise path, and the cache has a per-element staging path of its own because cp_async has no narrower form.

The kernel needs m16n8k16, so the capability is checked against the device the query is on rather than once against whichever device was current first.

Shape and cache level

A block resolves one cache address per column into shared memory before it stages anything, in the eight bytes a column already spent on the page and the entry, so the staging loop is a shared load and an add per copy rather than a 64-bit page multiply and a divergent branch recomputed by each of the eight threads covering a column. Columns with no page carry the first page's address and a bitmask marks them, so the copy needs no predicate; a cache with no pages at all has no first address to carry, so those launches skip staging outright.

Rows of one request read the same keys and their blocks run together, so the keys are staged with cp.async.ca rather than the cg form that bypasses L1. cp_async gains a CacheMode for this, defaulting to cg so nothing else changes: the SASS of an existing prefill module is identical across the commit that adds it, all 509266 instructions of it.

The launch turns over from one column tile per block to eight at 24 blocks per SM. The single-tile block stages the whole head in one step and has nothing to overlap inside itself, so other blocks on the same SM are what hide its latency and it keeps winning well past a full wave. What it does not scale with is the occupancy: sweeping rows at three shapes, the last block count the single-tile shape wins and the first the eight-tile shape does are 1536 then 2048 at sixteen heads and head dim 128 (7 blocks/SM), 2048 then 4096 at four heads (7 blocks/SM), and 1536 then 2048 at eight heads and head dim 256 (4 blocks/SM). The first and third turn at the same block count with very different occupancy, so a threshold in waves cannot fit them — those windows are (3.1, 4.2], (4.2, 8.4] and (5.5, 7.3] waves, the first two disjoint — while per SM they are (21.9, 29.3], (29.3, 58.5] and (21.9, 29.3], which 24 splits. Four heads at 2048 blocks is the one point that lands on the wrong side, by 1.09x; it and the 2048 of the other two want opposite shapes.

The threshold is measured on SM80 only. It decides which of the two shapes runs, never what either computes, so the worst case elsewhere is a slower choice.

Eight query heads or fewer take mma.m16n8k16 instead of multiplying eight columns of padding, which needs an ldmatrix.x2 the wrapper set did not have. The query fragments are held in registers across the column tiles rather than reloaded per multiply, except at head dim 256 above eight heads, where they do not fit.

Verification

The AOT registration is covered too. The kernel needs m16n8k16, which every SM8-or-newer device has, so the module is registered whenever any target is that new rather than only when an 8.x target is in the build. Restoring the narrower gate fails five of the seven.

Compared against a reference that walks the page table in plain torch and never calls the kernel, across both dtypes, head dimensions 64/128/192/256, one, four, eight, nine and sixteen heads, both launch shapes, a cache with no pages, an unmapped page, a row whose request is invalid, a column width narrower than the query can see, and that a row leaves the columns past its own count as the caller left them. Eight heads and nine straddle the two multiply widths, and sixteen at head dim 256 is the shape that reloads its query fragments.

The launch shapes are pinned against each other as well: enough blocks to fill the device switches from one column tile per block to eight, and scoring the same rows one at a time takes the other shape, so the two are required to agree column for column. Forcing either shape for the whole file passes all 51.

Alignment is pinned in both directions: a query and a cache passed as views with a misaligned base but aligned strides. Removing either base check alone fails its own case with cudaErrorMisalignedAddress, so the tests pin the check rather than the surrounding stride guard.
