Motivation

This PR adds RACER, a training-free speculative decoding method that reuses target verification logits as an additional draft source.

  • Paper: ACL Anthology
  • Code: github.com/hkr04/RACER

Existing NGRAM speculation retrieves continuations from token history. Like NGRAM, RACER retrieves continuations from token history, but uses an Aho-Corasick automaton for retrieval and augments it with top-k alternatives already produced during TARGET_VERIFY.

No draft model, no training, no draft KV cache, and no extra target forward pass for decode-time logits.

Token history ──→ AC retrieval ──────┐
                                     ├──→ draft tree
Past target logits → Logits Tree ────┘

The main goal of this PR is to demonstrate that verification logits are useful reusable speculative-decoding state, and that tree drafts can be assembled from multiple inexpensive sources.

Modifications

  • Add RACER as a training-free speculative algorithm.
  • Reuse SGLang's existing irregular-tree TARGET_VERIFY path.
  • Save target top-k logits from verified nodes into a per-request Logits Tree.
  • Let history retrieval take priority; logits only fill remaining unique draft slots.
  • Warm up both prompt history and prompt logits.
  • Add unit tests for RACER draft generation / unique-budget behavior.

We also tested raw ShareGPT prompts through SGLang's /generate endpoint (K=32, trie depth 10):

Ran with the official SGLang serving benchmark: python -m sglang.benchmark.serving --backend sglang --dataset-name sharegpt (official ShareGPT loader).

This is not a chat-serving benchmark, but it highlights a useful difference between the draft sources: history-only NGRAM becomes much less effective when reusable context patterns are sparse, while RACER can still obtain candidates from target logits.

Accuracy

200 examples / temperature=0 / thinking disabled

Method K Accuracy Accept Eval tok/s
Vanilla — 96.5% — 27.7
NGRAM 16 96.5% 1.92 42.3

RACER K16/K32 preserves the Vanilla 96.5% GSM8K accuracy.

MTP is shown only as a model-specific reference: it is substantially faster when MTP weights are available, while RACER targets the model-agnostic, training-free setting.

Relation to NGRAM

RACER is closely related to NGRAM + logits-assisted expansion. In our experiments, adding a min_match_depth constraint to NGRAM and then filling the remaining tree budget with a Logits Tree produces behavior close to RACER, which may help isolate the value of target-logit reuse from RACER-specific retrieval details. We plan to submit this simpler NGRAM_LOGITS variant separately.

Current limitations

  • Overlap scheduling is not yet supported.
  • Performance evaluation currently focuses on TP=1. TP>1 is supported, but the speculative speedup can be largely offset by additional verification and communication overhead.
  • RACER is ultimately bounded by target verification cost. Unlike trained drafters such as MTP/DFlash, RACER does not directly improve the verifier/drafter quality through training; in our training-free setting, accept length eventually grows more slowly than verification cost as K increases, limiting the achievable end-to-end speedup.

This PR is primarily intended to expose and evaluate the target-logit reuse / multi-source drafting idea; further runtime optimization can be handled independently.
