## 4) Bottom line per engine

1. **NVIDIA TensorRT-LLM** — has a real, shipped, **undocumented** determinism mode: `FORCE_DETERMINISTIC=1` plus `FORCE_{MOE,ATTENTION,ALL_REDUCE}_KERNEL_DETERMINISTIC` and `FORCE_ALLREDUCE_KERNEL_WORKSPACE_SIZE` (`cpp/tensorrt_llm/common/envUtils.{h,cpp}`). It disables multi-block attention (incl. XQA), disables Lamport Reduce+Norm fusion, forces a 1 GB allreduce workspace (vs 64 MiB), and disables KV-cache block/partial reuse. Maintainer `Superjomn` in issue #2474: "`export FORCE_DETERMINISTIC=1` will help. But it may hurt performance, especially for the MoE." Issue #1336 documents batch-size-dependent logits at top_k=1/fixed seed. The typed-API wrapper (PR #13290) was closed unmerged. Docs contain no determinism page, but NVIDIA **NIM** ships `NIM_FORCE_DETERMINISTIC=1` with a public doc page and perf-warning.
2. **llama.cpp** — **nothing shipped**. No `--deterministic` flag, no `GGML_*` determinism env var on master. Upstream *documents* the problem (`tools/server/README.md:587`: logits "not guaranteed to be bit-for-bit identical for different batch sizes") and maintainer `JohannesGaessler` explicitly declined batch-invariance guarantees on PR #16016 ("I don't want to maintain guarantees for bit-for-bit identical results as the batch size is varied"), recommending single-slot + no prompt caching instead. PR #16016 (open, `GGML_DETERMINISTIC=ON`/`--deterministic`) is the unmerged analogue of `VLLM_BATCH_INVARIANT`.
3. **TGI** — **nothing found**; no env var, CLI flag, docs page, or issue/PR on the topic (search totals 0 for `deterministic in:title`, `reproducib`, `"batch invarian"`). It does contain the mechanism (batch-size-dependent kernel selection in `layers/attention/cuda.py:132`) and enabling conditions (global TF32, CUDA-graph batch buckets, default flashdecoding split-K).
4. **LMDeploy** — dormant `enable_deterministic` config field (threaded to ~35 sites, never branched on, never set by `build_backend_config`) plus two explicit "batch-invariant outputs" docstrings in PCG phase-dispatch boundaries (`causal_conv1d.py:66`, `gated_delta_rule.py:295`). No env var, CLI flag, or docs page.
5. **MLC-LLM** — merged PR #897 (uniform seed, seed exposed to REST server) and docs "seed … for deterministic generation" (`rest.rst:230`). Nothing on batch invariance.
6. **DeepSpeed-FastGen / MII** — nothing: zero determinism matches in `deepspeed/inference/` (incl. `v2/`), one unrelated legacy hit in MII, FastGen blogs silent. DeepSpeed inference *generally* has a genuine `stochastic_mode=False` deterministic transformer kernel with a "completely reproducible" vendor claim — BERT-era, not serving batch invariance.
7. **Ollama** — seed-based "Reproducible outputs" docs (`docs/api.md:344`, `:999`), a per-slot deterministic RNG stream with explicit batch-composition intent (`x/mlxrunner/sample/sample.go`), and temp-0 → argmax. No `OLLAMA_*` determinism/batch env var; `batch invariance`/`batch_invariant` → 0 hits. Open issue #12559 (structured output breaks seed determinism); issue #16860 fixed by **disabling** MLX prompt-cache restore.
8. **TensorRT (runtime)** — deterministic **engine-build** tooling only (`--save/--load-timing-cache`, `--save/--load-tactics`, `sampleEditableTimingCache`, `trtexec --setBuildRoute`). No `--use_deterministic*` flag exists. Docs state builds are not bit-deterministic; `IAlgorithmSelector` deprecated (TRT 10.8) and can no longer guarantee determinism. Issue #774 documents INT8 calibration accuracy depending on calibration batch size.
9. **vLLM-Ascend** — the strongest non-vLLM artifact: a shipped **"Batch Invariance" feature guide** (`docs/source/user_guide/feature_guide/batch_invariance.md`), gated on `VLLM_BATCH_INVARIANT=1` at *build* time (custom AscendC operator library via `csrc/build_batch_invariant_ops.sh`) and at *runtime*. It replaces `aten::mm/matmul/addmm/bmm/softmax/_softmax/linear/sum` and patches `npu_fused_infer_attention_score` and `npu_add_rms_norm`; it sets `HCCL_DETERMINISTIC=strict`, `LCCL_DETERMINISTIC=1`, `torch.use_deterministic_algorithms(True)` and forces `weight_nz_mode=0`. Doc states it "Disables certain optimizations that may introduce non-determinism" and "may impact performance". Tracking issue #5487; PRs #5517, #6590, #6696, #10034, #11818 (the last: "Fixed batch invariance not taking effect").
