# E1 — 未提交投机 KV 占比测量（#1 投机 KV 分级的生死判定）

**时间盒**：1 天 ｜ **硬件**：单卡即可 ｜ **前置**：无（`arXiv 2606.29223` 已于 2026-09-11 关闭，见 `EXECUTION_PLAN.md` §3.1）
**预登记**：`notes/prereg/p01-e1-uncommitted-kv.md`

## 1. 测什么

逐步测量：

```
R(t) = 未提交（rejected / 尚未 commit）草稿 token 占用的 KV 字节
       ────────────────────────────────────────────────────
              已提交（committed）token 占用的 KV 字节
```

报告 **p50 与 p95**，并且必须报告**峰值占用**与**占用时长**（见 §4 的陷阱）。

## 2. 为什么是它

- 这是全组合里**唯一能产出有效 V2 型击杀**的探针：1 天成本买到的不是方案，是一个**可信的否定权**。
- 全库**无人测过这个比值**（`docs/evidence/r4_graded_kv_tiers.md` 第 9 条逐字确认），所以**测出来本身就是新数据**。
- #1 的三条已知反向压力都指向"量级可能很小"：SpecMemo 的高精度约束、被拒 KV 本就丢弃、相对已 ship 二值处理只宽一步。E1 就是给这三条一个数字。

## 3. 怎么测（网格）

| 维度 | 取值 |
|---|---|
| 引擎 | vLLM（记录 commit hash 与版本号）+ EAGLE-3 drafter |
| context | 4k / 32k / 128k |
| batch | 1 / 8 / 32 |
| γ (`num_speculative_tokens`) | 3 / 5 / 7 |
| 额外 | **1 个 draft-tree 配置**（非链式） |

- 仪器点：投机路径中草稿 token 的 KV 块分配与释放（`v1` 调度器 + block manager），逐步记录：分配块数、接受长度、回滚释放的块数与释放时刻。
- 采样：每格 ≥3 次重复，报告分布而非单点。
- 全部格子都必须落在一个**真实存在的 HBM 可行点**上（放不下就换配置，不得用"如果放得下"的外推）。

## 4. 陷阱（必须在 summary 里正面回答）

1. **如果草稿 KV 不单独分配块**（与已提交 token 共用同一 pool、reject 后立即回滚），则 R 不能用"分配计数"测量 —— 改用**块级占用时间积分**（`Σ 块数 × 占用步数`）。这本身就是发现，要写进结论。
2. **释放延迟**：reject 后是**同一步**释放，还是**下一步/下一次调度**才释放？后者会让 p95 显著抬高。
3. 不要把"未提交 token 数占比"直接当"KV 字节占比"（层数、GQA、dtype、是否有 MLA 都会改比例）。

## 5. 判据

| 结果 | 动作 |
|---|---|
| 全部 HBM 可行点上 **p95 < 5%** | **#1 按实测定死**，永久归档（写进 `notes/decision_log.md`） |
| 存在 HBM 可行点 **p95 ≥ 10%** 且对应真实部署配置 | 进入机制设计（三态：前沿无损 host 暂存，O(1) 元数据/步） |
| 5% ≤ p95 < 10% | 不结论，先补测释放延迟与峰值占用，再判 |
| **无论落在哪一档**：`R_reserve / R_byte > 2` | 触发 **D3(b) 支线**：以"**消除保守预留**"立项（portfolio 内唯一不依赖 `#6` 的线） |
