 Abstract 
 Test-time compute scaling, the practice of spending extra computation during inference via repeated sampling, search, or extended reasoning, has become a powerful lever for improving large language model performance.
Yet deploying these techniques under finite inference budgets requires a decision that current systems largely ignore: which inputs deserve more compute, and which can be answered cheaply? 
We formalize this as a constrained optimization problem (maximize expected accuracy subject to an average compute budget) and solve it with a two-stage Solve-then-Learn pipeline.
In the solve stage, Lagrangian relaxation decomposes the global constraint into per-instance sub-problems, each admitting a closed-form oracle action that optimally prices accuracy against cost.
We prove that the induced cost is monotone in the dual variable, enabling exact budget targeting via binary search.
In the learn stage, a lightweight classifier is trained to predict oracle actions from cheap input features, amortizing the allocation rule for real-time deployment.
We establish that the task-level regret of the learned policy is bounded by its imitation error times the worst-case per-instance gap, yielding a clean reduction from constrained inference to supervised classification.
Experiments on MATH and GSM8K with three LLMs (DeepSeek-V3, GPT-4o-mini, Qwen2.5-7B) show that our method consistently outperforms uniform and heuristic allocation baselines, achieving up to 12.8% relative accuracy improvement on MATH under matched budget constraints, while closely tracking the Lagrangian oracle upper bound with over 91% imitation accuracy.
 Code is available at https://github.com/zhiyuanZhai20/AdaCompute-LLM .
 1 Introduction
 The dominant recipe for improving large language model (LLM) performance has long been to increase pre-training compute: more parameters, more data, more FLOPs [ 1 , 2 ] .
A striking recent development is that comparable, and sometimes larger, gains can be achieved at inference time , by spending extra computation on each query through techniques such as chain-of-thought reasoning [ 3 ] , self-consistency voting [ 4 ] , tree search [ 5 ] , or process-reward verification [ 6 ] .
This has been termed test-time scaling , and it underpins the capabilities of frontier reasoning systems [ 7 , 8 ] .
 These inference-time techniques, however, are expensive: generating N N chain-of-thought responses for best-of- N N or majority voting multiplies cost linearly, yet many questions are answerable correctly in a single attempt.
In practice, inference budgets are finite.
API costs, GPU availability, latency targets, and throughput requirements impose hard or soft limits on total inference compute, and as agentic AI systems adopt ever-longer multi-step reasoning pipelines [ 7 ] , the gap between per-query cost and per-query necessity will only widen.
The standard approach allocates a uniform budget to every input, applying the same number of samples regardless of difficulty [ 4 , 13 ] .
This is wasteful: easy inputs that a single forward pass can solve still consume the full budget, while hard inputs that would benefit from more compute are starved at the same level.
 The heterogeneity of real workloads creates an opportunity: by redistributing compute from easy inputs to hard ones, the same total budget can yield significantly higher aggregate accuracy.
But which inputs should receive more compute?
Figure 1 illustrates the challenge concretely.
We define the budget b b as the number of independent responses sampled from the LLM, with the final answer determined by majority vote (self-consistency); the cost function C ⁡ ( b ) \mathrm{C}(b) maps each budget level to its resource consumption (e.g., C ⁡ ( b ) = b \mathrm{C}(b)=b when cost is proportional to the number of samples).
Some questions are trivially correct at b = 1 b=1 (a single response), making additional samples purely wasteful; others exhibit steep accuracy gains as b b increases (“responsive”); still others show diminishing returns or remain intractable regardless of budget.
In hindsight, the optimal strategy is clear: assign b = 1 b=1 to easy questions, concentrate high budgets on responsive ones, and avoid wasting resources on intractable ones.
The challenge is to approximate this oracle strategy before observing the outcomes.
Realizing this opportunity requires answering a precise question:
 Given a finite average compute budget shared across a batch of inputs, how should one allocate inference compute to individual inputs to maximize aggregate performance? 
 We observe that this question has the structure of a constrained optimization problem :

The constraint couples all inputs through a shared resource, so the globally optimal solution cannot be found by solving each input independently.
 We propose a two-stage Solve-then-Learn framework.
In the solve stage (§ 3 ), we attach a Lagrange multiplier λ \lambda to the budget constraint.
The resulting relaxation decomposes across inputs: each input’s sub-problem has a closed-form oracle solution b ⋆ ​ ( x , λ ) = arg ​ max b ⁡ [ Acc ⁡ ( x , b ) − λ ​ C ​ ( b ) ] b^{\star}(x;\lambda)=\argmax_{b}[\mathrm{Acc}(x,b)-\lambda\,\mathrm{C}(b)] , which optimally balances the marginal accuracy gain against a “shadow price” λ \lambda for compute.

We summarize the contributions of this paper as follows.
 Contributions.
 • 
 We are the first to formalize input-adaptive test-time compute allocation as a constrained optimization problem (§ 2 ), providing a principled alternative to heuristic rules and enabling systematic study of the accuracy–cost tradeoff under finite inference budgets.
 • 
 We propose a Solve-then-Learn framework (§ 3 –§ 4 ) that decomposes the global constrained problem into per-instance sub-problems via Lagrangian relaxation, then amortizes the oracle allocation into a lightweight classifier for real-time deployment.
 • 
 We establish formal guarantees (§ 4.4 ): cost monotonicity enabling binary search for budget targeting, an imitation regret bound reducing constrained inference to supervised classification, and a primal recovery result ensuring near-feasibility and near-optimality.
 2 Problem Formulation: Budget-Constrained Compute Allocation
 Setup.  
Let 𝒳 \mathcal{X} denote the input space and 𝒟 \mathcal{D} the deployment distribution over 𝒳 \mathcal{X} .
We have a discrete set of compute budgets ℬ = { b 1 , … , b K } \mathcal{B}=\{b_{1},\ldots,b_{K}\} , ordered by cost: C ⁡ ( b 1 ) ≤ ⋯ ≤ C ⁡ ( b K ) \mathrm{C}(b_{1})\leq\cdots\leq\mathrm{C}(b_{K}) .
Each budget b k b_{k} represents a specific operating mode of the inference engine—e.g., generating k k candidate responses and taking the best (best-of- K K ), running self-consistency with k k samples, or allowing a chain-of-thought of length proportional to k k .
For each input x ∈ 𝒳 x\in\mathcal{X} and budget b ∈ ℬ b\in\mathcal{B} , we write Acc ⁡ ( x , b ) ∈ [ 0 , 1 ] \mathrm{Acc}(x,b)\in[0,1] for the expected task utility (e.g., probability of producing a correct answer).
A budget allocation policy is a measurable function π : 𝒳 → ℬ \pi:\mathcal{X}\to\mathcal{B} that assigns a compute budget to each input, inducing two aggregate quantities: the expected accuracy 𝔼 ⁡ [ Acc ⁡ ( x , π ⁡ ( x ) ) ] \mathbb{E}[\mathrm{Acc}(x,\pi(x))] and the expected cost 𝔼 ⁡ [ C ⁡ ( π ⁡ ( x ) ) ] \mathbb{E}[\mathrm{C}(\pi(x))] .
 Given a target average budget B > 0 B>0 , the design problem is the constrained program

 Why is this hard?  
Three features distinguish ( 2 ) from textbook optimization.
 (i) Black-box reward : Acc ⁡ ( x , b ) \mathrm{Acc}(x,b) has no analytic form and can only be estimated by running the model.
 (ii) Functional decision variable : the optimizer is a policy function, not a scalar or vector.
 (iii) Global coupling : the budget constraint links all inputs through a shared resource, so independently maximizing per-input accuracy is infeasible whenever B < C ⁡ ( b K ) B<\mathrm{C}(b_{K}) .
 3 The Lagrangian Oracle
 We now show how Lagrangian duality converts the globally coupled problem ( 2 ) into a collection of independent per-instance sub-problems.
 3.1 Dual Relaxation
 Introducing a Lagrange multiplier λ ≥ 0 \lambda\geq 0 for the budget constraint, the Lagrangian of ( 3 ) is
 ℒ ⁡ ( π , λ ) = 1 N ​ ∑ i = 1 N [ Acc ⁡ ( x i , π ⁡ ( x i ) ) − λ ​ C ​ ( π ⁡ ( x i ) ) ] ⏟ f λ ​ ( x i , π ⁡ ( x i ) ) + λ ​ B . \mathcal{L}(\pi,\lambda)\;=\;\frac{1}{N}\sum_{i=1}^{N}\underbrace{\Big[\mathrm{Acc}\!\big(x_{i},\pi(x_{i})\big)-\lambda\,\mathrm{C}\!\big(\pi(x_{i})\big)\Big]}_{f_{\lambda}(x_{i},\,\pi(x_{i}))}\;+\;\lambda\,B. 
 (4) 
 The crucial observation is that the additive structure of ( 4 ) decouples across inputs: for fixed λ \lambda , maximizing ℒ ⁡ ( π , λ ) \mathcal{L}(\pi,\lambda) over π \pi reduces to independently maximizing f λ ​ ( x i , b ) f_{\lambda}(x_{i},b) over b b for each input x i x_{i} .
 Definition 1 (Oracle allocation) . 
 For dual variable λ ≥ 0 \lambda\geq 0 , the oracle allocation for input x x is 
 b ⋆ ​ ( x , λ ) := arg ​ max b ∈ ℬ ⁡ [ Acc ⁡ ( x , b ) − λ ​ C ​ ( b ) ] . b^{\star}(x;\lambda)\;:=\;\argmax_{b\in\mathcal{B}}\;\big[\mathrm{Acc}(x,b)-\lambda\,\mathrm{C}(b)\big]. 
 (5) 
 The oracle allocation has a transparent economic interpretation.
The quantity f λ ​ ( x , b ) = Acc ⁡ ( x , b ) − λ ​ C ​ ( b ) f_{\lambda}(x,b)=\mathrm{Acc}(x,b)-\lambda\,\mathrm{C}(b) is the net value of assigning budget b b to input x x , where the dual variable λ \lambda acts as a unit price of compute .
The oracle selects the budget that maximizes net value: it spends more on inputs where the marginal accuracy gain justifies the cost, and economizes on inputs where it does not.
When λ = 0 \lambda=0 , compute is free and the oracle assigns the maximum budget to every input.
As λ \lambda increases, the price of compute rises and the oracle progressively shifts to cheaper budgets, starting with the easiest inputs where additional compute yields the smallest accuracy gain.
 3.2 Budget Targeting via Cost Monotonicity
 The oracle allocation induces an average cost that depends on λ \lambda :
 C ¯ ​ ( λ ) := 1 N ​ ∑ i = 1 N C ⁡ ( b ⋆ ​ ( x i , λ ) ) . \bar{C}(\lambda)\;:=\;\frac{1}{N}\sum_{i=1}^{N}\mathrm{C}\!\big(b^{\star}(x_{i};\lambda)\big). 
 (6) 
 The following result shows that C ¯ ​ ( λ ) \bar{C}(\lambda) is well-behaved as a function of λ \lambda .
 Theorem 1 (Cost monotonicity) . 
 For finite ℬ \mathcal{B} , there exists a deterministic tie-breaking rule under which C ¯ ​ ( λ ) \bar{C}(\lambda) is non-increasing in λ \lambda . 
 The proof (in Appendix B ) follows from observing that each pairwise net-value difference f λ ​ ( x , b ) − f λ ​ ( x , b ′ ) f_{\lambda}(x,b)-f_{\lambda}(x,b^{\prime}) is affine and decreasing in λ \lambda whenever C ⁡ ( b ) > C ⁡ ( b ′ ) \mathrm{C}(b)>\mathrm{C}(b^{\prime}) , so each input’s oracle budget can only shift cheaper as λ \lambda grows.

 3.3 Dual Bound and Optimality
 The dual function is G ⁡ ( λ ) := max π ⁡ ℒ ⁡ ( π , λ ) G(\lambda):=\max_{\pi}\mathcal{L}(\pi,\lambda) .
Weak duality gives V ^ ​ ( B ) ≤ G ​ ( λ ) \hat{V}(B)\leq G(\lambda) for all λ ≥ 0 \lambda\geq 0 .
The tightest upper bound is G ⁡ ( λ B ) G(\lambda_{B}) , and the gap G ​ ( λ B ) − V ^ ​ ( B ) G(\lambda_{B})-\hat{V}(B) is the duality gap .
For the empirical problem (3), which is a finite program over N N independent discrete variables with a single coupling constraint, strong duality holds [ 44 , 45 ] :
 Proposition 1 (Strong duality) . 
 The empirical problem (3) has zero duality gap: V ^ ​ ( B ) = min λ ≥ 0 ⁡ G ⁡ ( λ ) \hat{V}(B)=\min_{\lambda\geq 0}G(\lambda) . 
 Since the duality gap is zero, the oracle allocation { b ⋆ ​ ( x i , λ B ) } \{b^{\star}(x_{i};\lambda_{B})\} obtained via binary search is an exact solution to the original constrained problem (3).
A complete proof—including the LP relaxation construction, weak duality, the subgradient characterisation connecting budget targeting to dual minimisation, and the vertex argument establishing strong duality—is given in Appendix C .
 4 Amortized Policy Learning
 Figure 3 : Overview of the Solve-then-Learn pipeline. Solve stage (offline): compute the Acc ⁡ ( x , b ) \mathrm{Acc}(x,b) matrix via API calls, then derive oracle labels via Lagrangian optimisation with binary search over λ \lambda . Learn stage (offline): train a lightweight GBM classifier on oracle labels using cheap text features. Deploy stage (online): predict budget for new questions at inference time. The entire training overhead is < < 1s; only the one-time API data collection is expensive. 
 The oracle labels { y i ⋆ } \{y_{i}^{\star}\} define an optimal budget assignment on the training set, but computing them for a new input x x requires access to Acc ⁡ ( x , b ) \mathrm{Acc}(x,b) for all b ∈ ℬ b\in\mathcal{B} —which is precisely the expensive inference we aim to avoid.
The second stage of our pipeline (Figure 3 ) learns to predict oracle labels from cheap input features, amortizing the allocation rule for deployment.
 4.1 Feature Extraction
 Let ϕ ⁡ ( x ) ∈ ℝ d \phi(x)\in\mathbb{R}^{d} denote a feature vector computed before the expensive inference call.
The framework is agnostic to the choice of features; the only requirement is that ϕ ⁡ ( x ) \phi(x) be inexpensive relative to full inference and informative about the difficulty of x x .
Candidates include lexical statistics (input length, vocabulary diversity, number of sub-questions), embedding-based features (prompt embeddings from a frozen encoder), and cheap inference signals (confidence or entropy from a single draft generation).
 4.2 Policy as Classification

 (7) 
 Training minimizes the cross-entropy loss against oracle labels:

 At inference time, a new input x x is processed in two steps: (1) Route : extract features ϕ ⁡ ( x ) \phi(x) and run π θ \pi_{\theta} to select budget b ^ = π θ ​ ( x ) \hat{b}=\pi_{\theta}(x) ; (2) Execute : run the inference engine once at budget b ^ \hat{b} .

 5 Experiments
 We evaluate the Solve-then-Learn framework on mathematical reasoning benchmarks, demonstrating consistent gains over baselines across multiple LLMs and budget levels.
 5.1 Experimental Setup
 Benchmarks.  
We use two datasets: MATH [ 46 ] , a competition-level mathematics benchmark (200 questions stratified across difficulty levels 2–4), and GSM8K [ 47 ] , a grade-school word problem set (200 questions) serving as an “easy benchmark” control where the base model already achieves > > 94% accuracy.
 Backbones.  
We test three LLMs to demonstrate generality: DeepSeek-V3 [ 48 ] ( deepseek-chat ), a strong open-weight reasoning model; GPT-4o-mini [ 49 ] , OpenAI’s compact model; and Qwen2.5-7B [ 50 ] , Alibaba’s 7B-parameter model. All models are queried with temperature T = 0.7 T=0.7 ; we collect 48 responses per question to evaluate all budget levels with non-overlapping windows.
The budget set is ℬ = { 1 , 2 , 4 , 8 , 16 } \mathcal{B}=\{1,2,4,8,16\} . For each question x i x_{i} and budget b b , we estimate self-consistency accuracy Acc ⁡ ( x i , b ) \mathrm{Acc}(x_{i},b) by partitioning 48 responses into ⌊ 48 / b ⌋ \lfloor 48/b\rfloor non-overlapping windows of size b b , taking majority votes within each window, and averaging.
 Policy and baselines.  
The classifier is a gradient-boosted machine (GBM, XGBoost [ 51 ] ) trained on 16 lightweight text features: lexical statistics (length, word count, sentence count), structural indicators (question marks, numbers, fractions, multi-step keywords), and a normalised entropy estimate from a single-pass LLM call.  6 Discussion and Conclusion
 Existing approaches to adaptive inference allocation rely on hand-designed difficulty metrics or threshold-based rules.
Our framework replaces these with a principled constrained optimization: the oracle labels arise from a Lagrangian relaxation of a well-defined primal problem, and the dual variable λ \lambda is the single knob that controls the accuracy–cost tradeoff.
Our experiments confirm that this principled approach consistently outperforms heuristic baselines (Table 1 ).
The framework is agnostic to the feature representation ϕ ⁡ ( x ) \phi(x) and applies to any setting where performance improves with test-time compute and inputs vary in difficulty.
Our ablation (Appendix H ) confirms that tree-based classifiers significantly outperform linear models, suggesting that allocation boundaries are inherently non-linear.
 Impact.
 As LLM inference becomes a dominant cost in production systems, principled compute allocation offers a practical lever for reducing waste without sacrificing quality.
Our framework can be integrated into any API-served or self-hosted LLM pipeline, enabling providers to serve more queries under fixed GPU budgets and reducing the carbon footprint of large-scale inference.
 Limitations and future work.
 The current framework treats budgets as discrete and requires pre-computing the utility table offline.
Extending to continuous budget spaces, online oracle adaptation, and multi-objective settings (e.g., jointly constraining latency and throughput) are promising directions.
The gap between the learned policy and the oracle (Table 5 ) highlights the need for richer, yet still cheap, difficulty signals.
 Conclusion.
 We presented a principled framework for adaptive test-time compute allocation that reduces the globally coupled budget-constrained program to supervised classification via Lagrangian duality.
The framework enjoys formal guarantees and experiments across three LLMs demonstrate consistent 3–6pp improvements over uniform allocation, tracking the oracle upper bound with over 91% imitation accuracy.

 Appendix A Related Work
 Test-time scaling for LLMs.
 A growing body of work demonstrates that inference-time computation can significantly improve LLM performance.
Chain-of-thought prompting [ 3 , 9 ] encourages step-by-step reasoning; self-consistency [ 4 ] aggregates multiple reasoning paths; tree search [ 5 , 10 , 11 ] explores candidate trajectories; and process reward models [ 6 , 12 ] provide step-level verification.
Repeated sampling alone can substantially boost solve rates [ 13 ] , and step-aware verifiers further improve multi-step reasoning [ 14 ] .
Snell et al. [ 15 ] show that optimally allocated test-time compute can outperform parameter scaling; Wu et al. [ 16 ] study inference scaling laws across strategies; and Liu et al. [ 17 ] demonstrate that small models with scaled test-time compute can match much larger ones.
Agarwal et al. [ 18 ] study how strategy varies with difficulty, and Zhang et al. [ 19 ] provide a comprehensive survey.
Jones [ 20 ] earlier studied train-time vs. test-time tradeoffs in board games.
These works address which test-time strategies to use; we address the orthogonal question of how much compute to allocate to each input.
 Adaptive computation.
 The idea of adapting computation to input difficulty predates LLMs.
Graves [ 21 ] introduced adaptive computation time for RNNs; early-exit networks [ 22 , 23 ] and dynamic neural networks [ 24 ] adapt depth or width at inference; mixture-of-experts [ 25 , 26 ] activate subsets of parameters per input, building on the foundational idea of adaptive expert mixtures [ 27 ] ; conditional computation [ 28 ] and speculative decoding [ 29 ] further reduce unnecessary computation.
In the LLM setting, router-based systems dispatch to models of varying capability [ 30 , 31 , 32 ] , with benchmarks emerging to evaluate them [ 33 ] .
Recent work predicts per-query token budgets [ 34 ] or jointly routes models and reasoning strategies [ 35 ] .
Our framework provides a principled optimization substrate for these heuristic allocation rules.
 Input-adaptive LLM scaling.
 Most closely related, Damani et al. [ 36 ] train a marginal reward predictor to allocate best-of- K K samples in a batch-online setting; Hassid et al. [ 37 ] reallocate generation budgets for code tasks.
Chen et al. [ 38 ] propose FrugalGPT, which cascades LLMs to reduce cost, but focuses on model selection rather than per-input compute allocation within a single model.
Madaan et al. [ 39 ] enable iterative self-refinement but do not budget the number of refinement rounds.
Our approach differs structurally: we solve a constrained program via Lagrangian decomposition, produce explicit oracle supervision, and provide formal regret bounds linking classification error to task performance.
 Budgeted and selective prediction.
 Our constrained formulation connects to budgeted classification [ 40 ] , selective prediction [ 41 ] , and bandits with knapsacks [ 42 , 43 ] .
The key distinction is that our “reward” is a complex black-box outcome of deep generative inference, motivating offline oracle construction from pre-recorded evaluations rather than online exploration.

 Appendix D Practical Notes on Utility Estimation
 When budget b b corresponds to best-of- K K sampling, Acc ⁡ ( x , b ) \mathrm{Acc}(x,b) is defined as the probability that the best of K K samples is correct.
This is estimated by running R R independent trials of K K -sample generation and recording the fraction of correct outcomes.
Averaging over R = 8 R=8 – 16 16 repetitions is typically sufficient for stable oracle labels.
With limited resources, one may use R = 1 R=1 with binary correctness indicators, relying on the law of large numbers across inputs for reliable aggregate performance estimates.

Since C ¯ ​ ( λ ) \bar{C}(\lambda) is a staircase function, we use stochastic mixing to achieve exact budget targets: we find two adjacent λ \lambda values giving C ¯ \bar{C} above and below B B , then randomly mix the corresponding label sets so that the expected cost equals B B .

 Appendix G Theoretical Property Validation
 G.1 Empirical Cost Monotonicity — Extended Analysis
 The cost monotonicity property (Theorem 1 ) is validated empirically in Figure 2 (main text).
Here we provide additional observations.
All four model–dataset combinations exhibit the predicted non-increasing staircase behaviour, but the curves differ in shape.
For the three MATH settings, C ¯ ​ ( λ ) \bar{C}(\lambda) spans the full range from ∼ \sim 3.5 (at λ ≈ 0 \lambda\approx 0 , where every question receives b = 16 b=16 ) down to 1.0 (at λ ≳ 0.10 \lambda\gtrsim 0.10 , where every question receives b = 1 b=1 ).
The transition is concentrated in the interval λ ∈ [ 0.01 , 0.10 ] \lambda\in[0.01,0.10] , reflecting the range of marginal accuracy gains across questions.
 For DeepSeek-V3 × \times GSM8K, the curve is markedly compressed: C ¯ ​ ( λ ) \bar{C}(\lambda) starts at only ∼ \sim 1.8 even at λ = 0 \lambda=0 , indicating that the unconstrained oracle assigns low budgets to most questions.
This occurs because GSM8K is easy—the base model already achieves 94.6% accuracy—so the marginal value of additional samples is small for most questions, and the oracle finds little reason to allocate high budgets even when compute is free.
 The staircase width varies across models: Qwen2.5-7B exhibits slightly wider plateaus than DeepSeek-V3 or GPT-4o-mini, suggesting a more discrete distribution of marginal accuracy gains.
This has practical implications for budget targeting: wider plateaus mean that exact budget matching via a single λ \lambda is harder (larger residual gap), motivating the stochastic mixing procedure described in Appendix E .

This heterogeneity is precisely what uniform allocation leaves on the table and what our oracle is designed to exploit.

The GBM crosses the Fixed- b b baseline with only 20–25% of the training data on every setting and climbs monotonically toward the oracle upper bound, with diminishing returns beyond 60%. 
 The pattern is strikingly consistent across backbones and datasets.

Two implications follow.
First, the oracle labels carry enough signal that a few dozen labelled questions are already valuable — the entire Solve-then-Learn pipeline (including the expensive API data collection) can be bootstrapped from as few as 50–100 questions per model.
Second, the remaining 1–2 pp gap to the oracle at 100% data usage is model-independent , suggesting that richer features — not more data — are the primary bottleneck for further improvement.
