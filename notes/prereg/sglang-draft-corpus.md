## 主假设

> **H1（可证伪的一句话）**：在**同一个 prompt 集、同一顺序、串行、无前缀缓存**的条件下，
> 全新启动的 SGLang NGRAM 实例的**第一遍**（首通）平均接受长度显著低于其饱和值（**冷启动罚金**），
> 且该罚金主要来自**草案语料为空**而非进程预热。

> **H2（干预假设，可证伪）**：在全新实例上**于第一个请求之前经 `POST /add_external_corpus` 装入预置语料**，
> 能把首通接受长度**恢复到稳态的 ≥80%**（记作 `recovery ≥ 80%`）。

**为什么 H2 不是"引擎自带的东西"**（硬约束 #5 的自查）：
引擎自带的是**会话内累积**（H1 的稳态就是它），**跨会话/跨重启的语料恢复需要外部动作** ——
`ExternalCorpusManager` 只有 add/remove/list，**没有任何持久化**（`srt/speculative/external_corpus_manager.py:23-111`，读正文）。
本实验里"预置语料"由**客户端**在 serve 之外构造并推送，**不是**引擎默认行为。

## 观测量与判据

### 主观测量（主判据）

`accept` = 每请求 `meta_info.spec_accept_length` = `completion_tokens / spec_verify_ct`（含 bonus token）。
出处：`sglang/srt/managers/tokenizer_manager.py:2811-2814`（SGLang 0.5.19）。

```
accept_control_first  = A 臂三进程首通 accept 的均值
accept_treat_first    = B 臂三进程首通 accept 的均值
accept_steady         = C 臂第 4 遍 accept（第 3/4 遍作为饱和证据）
cold_penalty          = (accept_steady − accept_control_first) / accept_steady
recovery              = (accept_treat_first − accept_control_first) / (accept_steady − accept_control_first)
```

### 判据（数字写死，采数前）

| # | 判据 | 通过条件 | 备注 |
|---|---|---|---|
| **C0** | **现象可复现（前置）** | `accept_control_first ≤ 0.5 × accept_steady`（即 `cold_penalty ≥ 50%`），且三个对照进程**同向** | 不成立 ⇒ 本次运行作废，不用于判定（可采纳前置条件 #3） |
| **C1** | **语法/口径自洽** | 每请求 `spec_accept_length ≤ speculative_num_draft_tokens (=8)`，且 `spec_accept_rate ∈ [0,1]`；**违例数 = 0**；且所有臂 `cached_tokens == 0` | 已知答案对照 |
| **C2** | **可回收性（主判据）** | **`recovery ≥ 80%`** | 这是"真优化"的判定 |
| **C3** | **可分辨性** | 效应量 `accept_treat_first − accept_control_first ≥ 3 × σ`，其中 `σ` = A 臂三进程首通 accept 的**样本标准差**（**k = 3**，写死） | 决策级噪声预算 |
| **C4** | **wall 佐证（辅助，不作为 Go/Kill 的唯一依据）** | 32 请求总 wall：`wall_treat_first ≤ wall_control_first`，且差值方向与 C2 一致 | C 臂给出稳态 wall 供对照 |

**Go 判定**：C0 ∧ C1 ∧ C2 ∧ C3 全部成立 ⇒ **Go**（并报 C4）。
**C2 成立但 C3 不成立** ⇒ 不是 Go，按"补测后再判"（见杀判据）。

## 网格

| 臂 | serve 进程数 | 语料 | 每进程遍数 | 覆盖的极值 |
|---|---|---|---|---|
| **A_control** | **3**（独立全新进程） | 空 | **1** | 时间轴极小值（首通）+ 进程间重复（估 σ） |
| **B_treat** | **3**（独立全新进程） | **启动后立刻预置**（32 条 documents） | **1** | 干预臂的进程间重复 |
| **C_steady** | 1 | 空 | **4** | 时间轴饱和极值（第 3/4 遍） |

**固定量（全网格一致）**：prompt 集 = `prompts_4096.jsonl` **前 32 条、固定顺序**；`temperature=0`；`ignore_eos=true`；`max_new_tokens=128`；`--disable-radix-cache`；`--max-running-requests 32`；**串行**（同时只有 1 个在飞请求）；引擎 `SGLang 0.5.19`；模型 `Qwen3-4B`；γ=7（`--speculative-num-steps 7 --speculative-num-draft-tokens 8`）；`--context-length 8192`。

### 逐轴"翻转会不会发生在极值处"论证（写死，不靠直觉）

| 轴 | 范围 | 极值处会翻转吗？ | 论证 |
|---|---|---|---|
| **语料状态** | 空（A）↔ 预置（B）↔ 饱和（C） | **翻转只可能发生在"空 vs 非空"这一跳** | 冒烟显示第 2 遍就到 6.97（饱和 7.78 的 90%），第 3–4 遍只再涨 2.5%；**没有中间态可供翻转** ⇒ A/B/C 三点覆盖该轴。 |
| **时间（遍数）** | 1 遍 ↔ 4 遍 | 不会 | 冒烟 rep2→rep3 = +2.2%、rep3→rep4 = **+0.17%**（已收敛）⇒ 4 遍足够代表饱和。 |
| **进程（重复）** | 3 个独立全新进程 | 不会（但要**量出** σ） | σ 未知正是 C3 要估的量；3 个是最小可估样本，若 C3 不成立则按 E1 补到 5 个。 |
| **prompt 难度** | 同 32 条固定顺序 | **不会**（轴被固定） | A/B 用**同一批 prompt、同一顺序** ⇒ 难度在臂间**抵消**（decision #53 的教训：范围过窄的上界不可外推）。 |
| **并发** | 串行（=1） | **未知，本轮不测**（适用范围外） | 高并发下批内多样本会改变 NGRAM 命中率；**明写为未测区间**。 |
| **上下文长度** | 4096 | 未测其他长度 | 仅 ctx=4096；**明写为未测区间**。 |
| **前缀缓存** | 全关 | 不会（轴被固定） | 若开，`cached_tokens>0` 会引入第二种机制、污染归因 ⇒ 全网格关闭并在 C1 里检查 `cached_tokens==0`。 |

## 杀判据

| 结果 | 处置 |
|---|---|
| **C0 不成立**（对照首通没变慢） | **杀 H1**：冷启动罚金不存在 ⇒ 动机不成立 ⇒ 停止（不许"再跑一次看看"） |
| **C2 < 80% 且 `recovery ≤ 0`** | **杀 H2**：预置语料闭合不了冷窗口 ⇒ 按预登记降级（现象记录），换线索 |
| **C2 落在 `0 < recovery < 80%`** | **补测后再判**：按 E1/E2 补测；**不得**直接判 Go |
| **C3 不成立**（效应 <3σ） | **补测后再判**：按 E1 把 A/B 各补到 5 进程；仍不成立 ⇒ 判"效应不可分辨" |
| **C1 违例 / `cached_tokens>0` / 语料装载被截断** | **本次运行作废**（仪器或前提失效），修好重跑，不计入判定 |
| **任何臂 serve 未就绪或探针有 err 行** | 该臂作废；若 A 或 B 只剩 <2 个有效进程 ⇒ 整轮作废重跑 |

## 噪声与可分辨性

| 来源 | 估计（采数前，来自冒烟） | 采数后的处理 |
|---|---|---|
| 接受长度：同进程内、语料饱和后 | **0.17%**（rep3 vs rep4）～2.2%（rep2 vs rep3） | 作为"稳态"稳定性证据 |
| 接受长度：空语料、同进程内 | 首 8 vs 后 8 均值差 **0.06%** | 支撑"变量是语料不是进程" |
| **接受长度：进程间（A 臂 3 次）** | **未知 —— 由本实验测出（这就是 σ）** | C3 用它；σ 过大则按 E1 补测 |
| wall：单请求跨 prompt | 0.264–1.056 s（**跨 prompt 差异，不是噪声**） | 只用 32 请求**总 wall** 做辅助判据 |
| wall：进程间 | 待测 | C4 只用方向一致性，不设百分比阈值 |

**可分辨性要求（写死）**：主判据 C2 的阈值 `recovery ≥ 80%`，在冒烟数字下对应
`0.8 × (7.7827 − 1.8365) = 4.76 token`；同进程噪声 ≈0.013 token ⇒ **≈360× 噪声**。
进程间 σ 由本实验给出；**C3 要求效应 ≥ 3σ（k = 3）**。

## 扩展条款（先登记，后触发）

- **E1**：若 C3 不成立（效应 <3σ）⇒ 在**同一预登记**下把 A、B 两臂各补到 **5 个独立进程**（≤0.1 GPU·h），用 5 进程的 σ 重判 C3。
- **E2**：若 C2 落在 `0 < recovery < 80%` ⇒ 在**同一预登记**下追加 **B2 臂**：预置语料改为**外部分布**（`corpus.txt`，与测试 prompt 不同分布），判定"部分恢复"是语料相关还是机制上限。
- **E3**：若 C2 成立但 C4 方向相反（接受长度涨而 wall 不降）⇒ 在同一预登记下追加**每步代价**分解（用 `spec_verify_ct` 与 `e2e_latency` 反算），**不得**直接报"吞吐提升"。
- **E4（明写不做）**：**不**做多引擎/多副本对照表（命中伪问题形态⑥，且是 NVIDIA Dynamo 已做过的形态）；**不**做并发扫描（适用范围外）。
- **E5**：若 B 臂 `recovery ≥ 80%` ⇒ 才允许进入**下一阶段**（跨会话/跨副本的语料持久化与共享），且该阶段必须**新开独立预登记**，不得把本实验数据重新解读成"持久化可行"。
