# S5 预登记（Pre-registration） — 前缀复用的生效时延（重复前缀第 2 次仍零命中）

**候选**：`prefix-reuse-lag` ｜ **成本上限**：0 GPU·h
**目标**：判据、网格、杀条件、噪声阈值全部写在采数之前，并且**覆盖每个轴的极值**。

## 主假设

> **H：同一 serve 会话中，完全相同的重复前缀**在第 2 次出现时不会立即被复用**，且该滞后可被消除或显著提前。**
**反向（判死）**：若受控实验显示第 2 次**本来就会命中**（A3 的零命中是我们 harness 的假象），或滞后是结构性不可避免且无法提前 ⇒ **判死**。


## 观测量与判据

| 编号 | 判据 | 可分辨性 |
|---|---|---|
| **C1 复现** | 与 A3 同条件（util 0.95、bs32、同 prompt、3+ reps）下，**第 2 次命中增量 = 0** 且第 3 次 > 0 | 命中是计数器的整数增量，**无噪声**；吞吐差 2.1–2.6× vs 噪声 ≤2% |
| **C2 交叉验证** | 命中出现的那个 rep，`mean_ttft_ms` **相对前一 rep 下降 ≥30%** | TTFT 变异性较大，故用 30% 阈值 |
| **C3 依赖关系** | onset 随**并发**（1/8/32）与**池大小**（0.30/0.55/0.95）如何变化；至少给出 2×2 的 onset 表 | 每格 3 reps |
| **C4 可回收性（Go 判据）** | 存在一种**不改变负载**的干预（如预热/保留/参数），使 onset **从 3 提前到 2**，且该 rep 吞吐提升 **≥8%** | 对照同格 3 reps |


## 网格

| 轴 | 取值 | 极值论证 |
|---|---|---|
| 显存预算 util | **0.30 / 0.55 / 0.95** | 0.30 = 池小于工作集（A3 实测永不命中）；0.95 = 池远大于工作集（出现滞后）⇒ 覆盖两端 |
| 并发 | **1 / 8 / 32** | 单请求（无批竞争）到满批（全部同时到达）⇒ 覆盖两端 |
| 重复次数 | **5** | 需要看到 onset 出现在第几次；A3 只有 3 次，不足以判断是"第 3 次"还是"更晚" |
| 投机 | off（γ 无关） | 本现象与投机无关（A3 的 accept 稳定），去掉该因子以降低噪声 |
| 固定 | 模型/ctx(4096)/prompt 文件/OUTLEN(128)/`max-num-seqs 32`/`--disable-shuffle`/`--enforce-eager`/KV=bf16 | 同实验内必须一致 |

规模：3 util × 3 并发 × 5 reps = **45 个 bench**，9 个 serve ⇒ **≤1 GPU·h**。


## 杀判据

| 条件 | 动作 |
|---|---|
| C1 复现失败（第 2 次就命中） | **判死**：A3 的零命中是假象 |
| C1 成立但 C4 找不到任何把 onset 提前的干预 | **降级**为"复用生效时序的刻画"（可预测模型），不作优化主张 |
| onset 随并发/池大小无规律且无法解释 | 判为不可控现象 ⇒ 判死 |


## 噪声与可分辨性

命中计数为**整数增量**（无噪声）；吞吐噪声 ≤2%（`A3_tight`），现象 ≥110% ⇒ 可分辨。
TTFT 用 30% 阈值（其格间变异较大，需逐格对照）。**所有计数器一律用增量**（decision #76）。


## 扩展条款

1. **允许**：若 onset 在 5 次内未出现，自动把 reps 扩到 10（同一预登记）。
2. **允许**：若发现 onset 依赖并发，自动补一轮**串行提交**（并发 1 逐条发同一 prompt）以隔离"批"与"时间"两个因素。
3. **不自动扩**：不改引擎代码做正式主张（补丁只用于**验证机制**；若要主张"修复"，须另开预登记并跑对照）。
4. **降级形态**：见杀判据第二行。
