## 0. 与 v1 的关系：问题不变，**判据与仪器全部重写**

v1 问的是对的问题（"前缀缓存是否按 drafter 类别造成差异损害"），但它的主判据 P3 在原理上**不可辨识**：
`off/on` 这个比值被"48 个请求是否复用同一个 1024-token system prefix"支配（共同效应 **4.87–5.53×**），
而待检验的类别差异只有 **2%**（0.1810 vs 0.1847）。用一个 5× 的共同效应做分母去分辨 2%，无论采多少数据都无解。

**v2 把同一个问题拆成三个可独立证伪的子问题**，并为每一个配一件能直读的仪器。

| | v1 | v2 |
|---|---|---|
| 机制判据 | P1「dflash 的 `cached_tokens ≈ 0`」——与 §0 自述机制**无因果关系**（审计 §1.3） | **P1' 正确性不变量**：PC on/off 在贪心解码下必须逐 token 相同；分歧即缺陷 |
| 记账判据 | P2「靠第 2/3 遍变快推断」——已被同批数据证伪（`ngram\|PC off` 首遍也慢 1.39×，审计 §2.2） | **P2' 直读** `cached_tokens` / `prefix_cache_hits_total` |
| 工程判据 | P3 = 整段墙钟 tok/s（**预填充占绝对主导**） | **P3' 解码期 tok/s**，预填充单独报为 TTFT |
| K | 与 drafter 绑定（7/5/3，审计 §2.4） | **固定 K=3**；K 敏感性单独做 |
| 噪声 | 无（阈值 1.15× 拍定，实测波动达 3.00×，审计 §2.1） | **pilot 先估 σ**，阈值由 σ 决定 |
| 对照 | 每格独立起停引擎、on→off 顺序固定（审计 §4.3） | **同一引擎实例内完成全部臂**，顺序随机化 |

## 1. 可证伪预测（三条，逐条独立）

### P1' —— 正确性不变量（机制）

> 对每一个 `(target, drafter, K)` 组合：**PC on 与 PC off 在贪心解码、相同 prompt、相同 `max_tokens`、
> `ignore_eos` 下，必须产出逐位完全相同的 token id 序列。**

**为什么这是正确的机制仪器**：前缀缓存在语义上必须是**透明**的——它只是复用已算过的 KV，不改变任何计算结果。
v1 的 §0 自述机制（"dflash 需要 target 辅助隐藏状态建 context KV，而缓存恢复的 token 从不经过 target ⇒ 读到未初始化 KV"）
若为真，其**直接可观测后果就是 PC-on 与 PC-off 的输出分歧**（或接受率塌陷），而**不是** `cached_tokens` 归零。

- **对照（缺一不可）**：`none` 臂必须一致。若 `none` 也分歧 ⇒ 是装置/浮点问题，不是 drafter 缺陷 ⇒ 本次运行作废。
- **报什么**：每个组合的首个分歧位置、分歧率、以及分歧是否**按 drafter 类别聚集**。
- **杀判据**：若全组合一致 ⇒ 该版本 vLLM 上不存在缓存相关的正确性缺陷（机制不成立）。

### P2' —— 命中记账（阳性对照，同时是有效性闸门）

> **暖臂**（同一 prompt 集第二次发送）上，每个开启 PC 的臂必须 `cached_tokens > 0` 且 ≈ 共享前缀长度；
> **冷臂**（引擎从未见过的 prompt 集）必须 ≈ 0；**PC off 的全部臂必须 = 0。**

- **若暖臂 `cached_tokens ≈ 0` ⇒ 缓存根本没工作 ⇒ 该次运行作废并重跑**（v1 在这里把结论反了：它把"没测到"当成"机制成立"）。
- 这条同时是 P3' 的**有效性闸门**：缓存没命中时，PC on/off 的吞吐对比没有意义。

### P3' —— 解码期代价（工程后果，主判据）

> 定义 **decode tok/s = 输出 token 数 ÷ 解码段墙钟**（排除预填充）。
> 在**暖臂**上比较 PC on vs off，**按 drafter 分层**；差异必须同时满足：
> (a) 超过噪声底 θ，(b) 方向在 5 个 seed 上一致。

- **为什么必须分预填充**：v1 的整段墙钟里，预填充是绝对主导（48 请求 × ~1024–1400 token prompt vs 32 token 输出）。
  PC 的预填充收益对所有臂同号同量级，会把任何解码期效应淹没。v2 把预填充单独报成 **TTFT p50/p95**。
- **必须同时报"预填充占比"**，以证明主判据不再被预填充支配。

## 4. 噪声模型与判据（**采数前定死**）

**噪声底由"同一格内的重复臂"给出，不另设丢弃式 pilot。**
每个 `(seed, concurrency)` 在**同一个引擎实例内**跑 1 次冷臂 + **R=3 次完全相同的暖臂**（`warm1/warm2/warm3`）。
因为 `warm1..warm3` 发送的是**逐 token 相同的 prompt**、缓存状态也相同，它们之间的离散度就是该格的纯噪声。

```
σ_cell   = stdev(decode_tps(warm1), decode_tps(warm2), decode_tps(warm3))     # 臂内重复性
σ        = median over all cells of σ_cell
μ        = median over all cells of mean(decode_tps(warm1..3))
```

**阈值**：`θ = max(1.05, 1 + 3σ/μ)`

> 之所以不用单格一次性的 pilot：本平台是共享云 GPU，噪声在**时间上**不均匀；用每一格自带的重复臂，
> 噪声估计与它所约束的那个判据来自同一时刻、同一批形。（§4 的这处修订发生在**任何数据采集之前**。）

**主判据**：存在某个 drafter 使 `|decode_tps(PC=on, warm) / decode_tps(PC=off, warm) − 1| > θ`，且方向在 5 个 seed 上一致 ⇒ **存在 drafter 特异性代价**。
否则 ⇒ **无工程后果**。

> v1 的 1.15× 之所以无效，是因为它落在单格自身的跨遍波动（1.14–3.00×）之内。v2 的阈值由实测 σ 生成。

## 5. 杀判据（写死在采数前）

| # | 条件 | 处置 |
|---|---|---|
| S1 | P2' 暖臂阴性（`cached_tokens ≈ 0`） | 该次运行**作废重跑**（不许解释成"机制成立"） |
| S2 | `none` 臂 P1' 出现输出分歧 | 装置故障 ⇒ **全部作废** |
| S3 | 噪声底 `σ/μ > 15%` | 该装置噪声过大、不足以支撑判定 ⇒ **报告并停止**，不得降低阈值凑结论 |
| S4 | P3' 未过 θ，或方向在 seed 间不一致 | **归档**，理由写"无工程后果" |
| S5 | 任一臂引擎启动失败 | 记为**装置失败**，与"效应为零"严格区分（v1 把二者混为一谈） |

## 6. 已知边界（采数前先承认）

1. **单卡、单节点**，A800 与 v1 的 4080 SUPER 架构不同；v1 的绝对 tok/s 一律不可与本轮跨机器比较（v1 链内同一名义格就已跨 6.3×）。
2. `enforce_eager=True` 会关闭 CUDA graph；这会改变每步成本的**水平**，故本轮所有结论限于该配置，并**在 JSON 中记录**。
3. `Falcon-H1-3B + 投机` 在 vLLM 0.29 上可能撞上 `page_size_padded >= page_size` 断言（v1 曾遇到）。若触发：**记为装置失败（S5）并保留原始报错**，不使用本地 monkey-patch 出数（v1 的 Falcon 列用了未归档的 patch，不可复现）。
4. 5 个 seed 只能给出弱不确定性刻画；不足以保证小效应的统计显著性。
5. 本轮**不**尝试回答"上游 #47930 是否为真"——只能回答"在 A800 + vLLM 0.29.0 + 本配置下是否可复现"。
