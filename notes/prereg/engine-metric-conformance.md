# S5 预登记（Pre-registration） — 跨引擎指标定义一致性（投机解码/服务度量）

**候选**：`engine-metric-conformance` ｜ **成本上限**：0 GPU·h（登记本身）
**登记时点**：**数据采集前** —— 本节全部判据写在 `run_conformance.sh` 第一次运行之前。
**仓库级冻结副本**：`notes/prereg/engine-metric-conformance.md`

## 主假设

> **H：两家引擎在同模型、同负载、同硬件下，对"对应的指标"给出**语义不等价**的数值，
> 且不等价幅度足以让跨引擎比较超过 8% 的误差。**

**反向（判死）条件**：若实测 C1/C3/C4 三项差异**全部 <8%**，且 C2 的"每步 vs 每 token"错位在 SGLang 侧不出现
⇒ **语义实际等价、Dynamo 的文档只是不完整** ⇒ 本方向**当场判死**，结论写成一条负面结果。

## 观测量与判据（可执行断言 C1–C4）

| 断言 | 判据（含**可分辨性**要求） | 参照系 |
|---|---|---|
| **C1 名称映射的语义** | 同负载下，Dynamo 表中**无歧义的计数类**指标对必须一致：`prompt_tokens_total`、`generation_tokens_total`、请求完成数（vLLM `request_success_total{length}` vs SGLang `num_requests_total`）。**要求差 <1%**（计数类是精确量，1% 已很宽松） | 同一客户端 ⇒ 客户端差异被消除 |
| **C2 延迟单位（每步 vs 每 token）** | 投机解码下 vLLM 的 `mean_itl_ms / mean_tpot_ms` **应 ≈ `accept_len`**（≥2×）；若 SGLang 的 ITL 在同负载下**不随 accept_len 缩放**（比值 ≈1）⇒ 两家 ITL 单位不同 ⇒ **不可直接并列** | 我们已有 vLLM 侧 24 格实测（比值 2.45–2.88×）作为上界参照 |
| **C3 接受长度定义** | `accept_vllm`（= `1 + accepted/drafts`，取自**增量**计数器）vs SGLang 的 `spec_accept_length`：**相对差 ≥8% ⇒ 定义不同（判据成立）**；<8% ⇒ 视为可比 | 我们已验证 vLLM 内部两条路径一致（24/24，≤5%） |
| **C4 吞吐计入口径** | vLLM 同时给 `output_throughput` 与 `total_token_throughput`；检验 SGLang 的 `gen_throughput` 与哪一条同量级（比值落在 output/total 二者之一的 ±5% 内）⇒ 判定其口径；**若两引擎口径不同而报告里未声明 ⇒ 判据成立** | 同负载、同客户端 |

**主判据**：**C2 或 C3 至少一项 ≥8%** ⇒ H 成立（上界通过）；**C1 与 C4 用于给出"哪些指标可以跨引擎比、哪些不能"的结论表**。

## 网格（采数前固定；覆盖每个轴的极值）

| 轴 | 取值 | 极值论证 |
|---|---|---|
| 引擎 | **vLLM 0.29.0** ／ **SGLang（版本以装完自检为准，记入 §修订记录）** | 两家都在 Dynamo 的对照表里（TRT-LLM 因安装体积/许可**主动排除**，已在 S4 声明为"已知不可做"） |
| 投机 | **off** ／ **NGRAM（γ=7）** | off 是基线（检验"普通解码下 ITL 是否已是同一个量"）；NGRAM 两家都支持且**不需要额外 drafter 权重** ⇒ 消除"drafter 不同"这一混淆。γ=7 取可实现的最大值（vLLM 侧训练操作点） |
| 并发 | **1** ／ **32** | 延迟受限与吞吐受限两端（`#6` 的经验：差异最可能出现在两端） |
| 重复 | 3 | 噪声预算见下 |
| 固定 | 模型 `Qwen3-4B`、KV=bf16、`max-model-len=40960`、`OUTLEN=128`、32 条真实文本 prompt、同一客户端 `vllm bench serve`、`--ignore-eos --seed 0` | 对照条件在同一实验内必须一致 |

**规模**：2 引擎 × 2 投机档 × 2 并发 × 3 reps = **24 个 bench**，约 8 个 serve ⇒ **≤2 GPU·h**。

## 噪声与可分辨性

| 量 | 噪声（采数前估计） | 依据 |
|---|---|---|
| 接受长度 | 逐次极差 **<1%** | A1 的 120 格实测（它是模型属性，不受调度噪声影响） |
| 计数类（prompt/generation tokens、完成数） | **精确**（同负载应逐位相同） | 计数器语义 |
| 吞吐 | bs=1 极差 3–9.5%，bs≥8 为 1.5–4% | A1 实测 ⇒ C4 用 ±5% 容差、C1 用 1% |
| 延迟（ITL/TPOT） | 只用**比值**（`itl/tpot`），比值对绝对噪声不敏感 | 自洽 |

⇒ **C2/C3 的 8% 阈值远超噪声，可分辨**；C1 的 1% 阈值对计数类是合理的。

## 杀判据

| 条件 | 动作 |
|---|---|
| C1/C3/C4 **全部 <8%** 且 C2 的错位在 SGLang 侧不存在 | **判死**：语义实际等价，写负面结果 |
| 只有 C1（计数类）不一致 | 判为**引擎行为差异**（例如计入了被撤销的请求），**不足以支撑"不可比"结论** ⇒ 降级为现象记录 |
| SGLang 侧无法在运行中取到 `spec_accept_length`（gauge 归零） | 判**仪器不可用** ⇒ 改用其 bench 工具自带统计；若仍取不到 ⇒ C3 **不可判定**，只能靠 C2 ⇒ 主张降级 |
| 服务起不来 / OOM | 作废，不算数据 |

## 可采纳前置条件

1. 两引擎**同模型路径、同 dtype、同 `max-model-len`、同 `OUTLEN`、同 prompt 顺序**；
2. 引擎侧指标**只取计数器**，或**运行中**抓取的 gauge（跑完后 gauge 归零，decision #66）；
3. 跨 rep **一律用增量**，分组键覆盖**整个 serve 会话**（decision #76 的两个仪器教训）；
4. `preemption == 0`（vLLM）/ `num_retracted_reqs == 0`（SGLang）；
5. 客户端**必须是同一个**（`vllm bench serve` 打两家的 OpenAI 兼容端点）。

## 证伪性预测（先写下，便于事后判我对错）

- **Pa**：**C3 会成立** —— 两家的"接受长度"定义不同（例如是否含 bonus token / 按 step 还是按 token），相对差 **≥8%**。
- **Pb**：**C1 会通过（<1%）** —— token 计数类是精确语义，两家应当一致。
- **Pc**：**C2 成立且只是 vLLM 侧已知事实** —— 若 SGLang 的 ITL 也是"每步"，则**两家其实一致**（那就只剩命名不同）⇒ 此时本方向的"不可比"主张**必须缩到 C3**，否则退化为 known issue。
- **Pd**：**C4 会成立** —— 两家的吞吐口径不同（输出 vs 总 token），且 SGLang 可能只给一个。

## 扩展条款（预登记；改动即事后调整）

1. **允许的扩展**：若 C3 成立，**自动允许**追加 γ∈{1,3} 以确认"定义差异是否随 γ 系统性变化"（同一预登记、同一模型）。
2. **允许的扩展**：若 SGLang 的 gauge 取不到，**自动允许**改用其 `bench_serving` 自带统计作为 C3 的第二来源。
3. **不自动扩**：① 不装 TRT-LLM（体积/许可）；② 不换模型家族；③ 不做多卡；④ **不写"三引擎对照表"**（那是 Dynamo 做过的，形态⑥ 会命中）。
