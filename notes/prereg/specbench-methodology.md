# S5 预登记（Pre-registration） — 投机解码/MTP 服务评测的方法学

**候选**：`specbench-methodology` ｜ **成本上限**：0 GPU·h（登记本身）
**登记时点**：**数据采集前** —— 本节全部判据写在 `run_groundtruth.sh` 第一次运行之前。
**仓库级冻结副本**：`notes/prereg/specbench-methodology.md`

## 主假设

> **H：由度量恒等式构成的自检器，能区分"协议有效"与"协议无效"的投机解码测量。**
> 具体地：在真实文本 + 非零温度下自检器**通过**；在随机数据集下自检器**报警**（且报警原因是可解释的：接受长度触到理论上界）。

若 H 不成立（随机数据集与真实文本在接受长度上无显著差异），则 `#P2` 不成立 ⇒ 本方向重伤；
若恒等式 I1 在真实数据上不成立，则**我们的恒等式本身错了** ⇒ 本方向死。

## 观测量与判据（五条恒等式，逐条可判定）

| 编号 | 恒等式 | 容差 | 含义 |
|---|---|---|---|
| **I1** | `mean_tpot_ms ≈ mean_itl_ms / accept_len` | ±3% | ITL 是**每步**延迟（不是每 token） |
| **I2** | `accept_len ≤ γ + 1` | 硬约束 | 接受长度的理论上界 |
| **I3** | `accept_len`（`bench.json`）≈ `1 + accepted_total / drafts_total`（`.metrics` **计数器**） | ±5% | **两条独立路径**必须一致 |
| **I4** | 逐位置接受率 `max_k p_k < 1.0` | 报警阈 ≥ 0.999 | 真实文本下不可能每个位置都必然接受 |
| **I5** | `tok/s ≤ 1.05 × batch × 1000 / tpot_ms` | **单边上界** | 稳态理想吞吐是**上界**：实测**低于**它属正常（prefill/爬升/尾巴），**高于**它才不可能 |

**判据 ①（自检器有判别力）**：
`random` 格 `accept_len ≥ γ + 1 − 0.05` **且** `max_k p_k ≥ 0.999`；
`custom`（真实文本）格 `accept_len ≤ γ` **且** `max_k p_k ≤ 0.95`。两者同时成立 ⇒ 判别力成立。

**判据 ②（身份一致性）**：I1 在**所有**格成立；I3 在 `custom` 格成立（`random` 格若 I3 不成立，说明随机输入下引擎自身的两条路径也不一致 ⇒ 那是**更强的发现**，须如实记录）。

**判据 ③（温度是接受率的混淆变量）**：`temperature=0` 相对 `0.7` 使 `accept_len` 提升 ≥8%。
> 这一条与 **2605.24217 §4.3 不同**：他们测的是温度对**吞吐**的影响（21%），**没测温度对接受率的影响**（投机解码特有）。

## 网格（数据采集前固定；**覆盖每个轴的极值**）

| 轴 | 取值 | 极值论证（为什么必须覆盖） |
|---|---|---|
| 数据集 | `custom`（真实文本 `prompts_4096.jsonl`）／`random`（`--random-input-len 4096`） | 这是 H 的**自变量**；两端即"协议有效/无效" |
| 温度 | **0** ／ **0.7** | 极值：贪心（草稿最易被接受）与采样（常规）⇒ 接受率混淆变量的两个极端 |
| 并发 `bs` | **1** ／ **32** | 极值：延迟受限与吞吐受限两端；`#6` 的经验是差异最可能出现在两端 |
| 重复 | 3 次 | 噪声预算：接受长度逐次极差 **<1%**（S4 已估），3 次足够判 ≥8% |
| 固定 | γ=7、`OUTLEN=128`、`max-model-len=40960`、KV=bf16、`--enforce-eager`、`--disable-shuffle` | 对照条件在同一实验内必须一致 |

**服务数**：数据集 × 温度 = **4 个 serve**；每个 serve 跑 `bs{1,32}` × 3 reps = 6 benches ⇒ **24 个 bench**。成本预估 **≤1.5 GPU·h**。

## 噪声与可分辨性

- **接受长度**：逐次极差 **<1%**（S4 估算，来自 A1 数据）⇒ 判据①③ 的 8% 阈值远超噪声，**可分辨**。
- **吞吐**：`bs=1` 极差 3–9.5%、`bs≥8` 1.5–4% ⇒ I5 用 ±10% 容差。
- **必须核 `preemption == 0`**（计数器），否则吞吐读数受显存挤占污染（decision #66/#68 的同源纪律）。

## 杀判据

| 条件 | 动作 |
|---|---|
| `random` 与 `custom` 的 `accept_len` 无显著差异（<8% 且落在噪声内） | **P2 不成立 ⇒ 方向重伤**，回到测绘第 2 轮 |
| I1 在 `custom` 格不成立（>3%） | **恒等式错 ⇒ 方向死**（我们的理论根基不成立） |
| `random` 与 `custom` 都触到 `γ+1` | 数据集不是自变量 ⇒ 判据①无效，方向死 |
| 服务起不来（OOM/加载失败） | 判作废，不算数据 |

## 可采纳前置条件

1. `num_preemptions_total == 0`；
2. 四个 serve 的 KV dtype、`max-model-len`、`max-num-seqs`、`OUTLEN`、γ **完全一致**；
3. `bench.json` 与 `.metrics` **成对留存**（I3 需要两条路径）；
4. `.metrics` 只采**计数器**（gauge 跑完归零，不可用，decision #66）。

## 证伪性预测（先写下，便于事后判我对错）

- **Pa**：`random` ⇒ `accept_len ≈ 8`（= γ+1）；`custom` ⇒ ≈ 2.8。**若 `random` 下也只有 ~3，则我此前的记录（run_t1.sh 第 11 行注释）是错的，必须更正。**
- **Pb**：I1 在两种数据集下**都**成立（它是引擎内部恒等式，与负载无关）。
- **Pc**：`temperature=0` 会提高 `accept_len`（贪心 ⇒ 草稿更易被接受），幅度 ≥8% ⇒ 说明**采样参数是接受率的混淆变量**，而这一点 2605 未测。


## 基线（引擎已 ship 的可观测性 = 本方向的最强基线）

本方向不是"比谁快"，但**判据的比较基准必须是引擎已 ship 的东西**，否则 8% 无意义：

| 已 ship 的基线 | 它给了什么 | 它**没给**什么（= 我们的空隙） |
|---|---|---|
| `bench.json` 的 `spec_decode_acceptance_length` / `per_position_acceptance_rates` / `mean_itl_ms` / `mean_tpot_ms` | 全部原料 | **不做任何一致性判定**；字段语义随配置改变而不提示 |
| `/metrics` 的 `spec_decode_num_{drafts,accepted}_tokens_total`（**计数器**） | 第二条独立路径 | 不与 `bench.json` 交叉核对 |
| ITL/TPOT 文档（vLLM PR **#55283** 才澄清） | 文字说明 | **文档修不了已发表的分析** |
| `--dataset-name random` / 温度参数 | 可配置 | 不提示"这个协议会让接受率失效" |

⇒ **判据的对照物是"引擎原始输出"**：跑出来的每条恒等式要么被引擎的字段满足、要么不满足，
**不引入任何我们自己的新指标**（避免"自定义指标自证"的循环）。

## 扩展条款（预登记；**改动即事后调整**）

1. **允许的扩展**：若判据①在 `bs{1,32}` 两端都成立，**自动允许**把并发扩到 `{8,16}` 以确认中间点
   （同一预登记、同一模型、同一 γ；不新增判据）。
2. **允许的扩展**：若 I3（两条独立路径）在 `custom` 格**不一致**，**自动允许**追查该不一致
   （它是比"协议无效"更强的发现），但必须在结论里与"协议无效"分开陈述。
3. **不自动扩**：① 不换模型家族（避免变成"跨模型可比性"课题）；② 不引入多卡/集群；
   ③ 不改成"审计公开报告"—— 那需要先证明字段可得性（见 §杀判据之后的备注）。
4. **降级形态**（若判据①不成立）：把交付物缩为"五条恒等式的可行域 + 自检器"，**删去**"能区分协议"的主张。
