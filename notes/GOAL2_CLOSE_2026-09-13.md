## 一、本目标（goal-ebcec24d）三条线索的终局

### 线索 A：批组成不变性 / 确定性（`candidates/batch-invariance-cost/`）

| 项 | 内容 |
|---|---|
| **现象** | 批量推理的数值结果依赖批的组成 ⇒ "同一请求 + 同种子 + 贪心"不保证同一输出；引擎提供 opt-in 开关来消除它 |
| **机制（源码级）** | **vLLM 0.29**：`VLLM_BATCH_INVARIANT`（`envs.py:617-619`，默认 `0`），打开后关/改 attn cascade（`config/vllm.py:1730`）、allreduce（`all_reduce_utils.py:136/165`）、symm mem + FlashInfer allreduce（`cuda_communicator.py:63/235/254/457`）、LoRA kernel（`lora/ops/triton_ops/utils.py:222`），另有 `model_executor/determinism/batch_invariant.py`。**SGLang 0.5.19**：`--enable-deterministic-inference`（`server_args.py:3474-3478`，默认 `False`，文档串 **"Enable deterministic inference mode with batch invariant ops"**），强制 `sampling_backend=pytorch`（`overrides.py:1030-1035`）、禁 FlashInfer allreduce fusion（`overrides.py:1066-1077`）、禁 `FLASHINFER_MOE_FUSED_FINALIZE`（`serving_hook.py:404-405`） |
| **被否的确切原因** | 命中 S3b 杀出口：**两家主流引擎都已 ship 同一问题类的专用开关**，且**上游把失效机制写进了代码** —— `speculative_hook.py:770-776` 直接 `raise ValueError("...the sampling kernel draws coins from the global RNG and is not batch-invariant.")` ⇒ 这不是"没人想到"，而是"**已知、已建开关、已被容忍**"。剩余可写内容只有"把代价测一遍" ⇒ **程度性**差异轴（违反判据 ②）+ 测量类（违反用户"只接受优化类"裁定） |
| **证据路径** | `candidates/batch-invariance-cost/35_solved_check.md`；decision #109/#110 |
| **复活条件** | 若出现**新的非不变性来源**且上游**未**在代码里挡住（例如新硬件后端、新量化格式、新并行策略引入新的归约不确定性），且其代价 ≥8% ⇒ 可作为新候选，但**必须先过 S3b 且差异轴写成条件性** |

### 线索 B：thinking 阶段的投机解码（同轮平行检验，未立项）

| 项 | 内容 |
|---|---|
| **现象** | 推理模型的 thinking 阶段与答案阶段的草稿接受特性不同（thinking 段接受长度显著更低），静态投机步数无法同时最优 |
| **机制** | SGLang 文档自述：adaptive mode *"designed for workloads whose **accept length changes over time**, where one static step count is rarely optimal"*，实现含**按 batch-size 分桶的独立 EMA 跟踪器** + hysteresis + ceiling + CUDA graph 分档（[文档](https://docs.sglang.io/docs/advanced_features/adaptive_speculative_decoding.md)）；vLLM 侧同决策已有 per-BS（`config/speculative.py:473-529`）与 per-request（RFC `#48202`）两级自适应 |
| **被否的确切原因** | ① "**CoT 阶段接受长度低**"已是教材级既定事实（有专门章节 [Low acceptance on chain-of-thought](https://theneuralbase.com/speculative-decoding/learn/advanced/low-acceptance-on-chain-of-thought/)、[Why reasoning models are a poor fit](https://theneuralbase.com/speculative-decoding/learn/advanced/reasoning-model-poor-fit/)）；② 上游控制器是**通用自适应**（对任意 accept 变化都响应）⇒ "在 thinking 阶段做自适应"只能是**程度性**区别（违反判据 ②）；③ 与 decision #62 已记录的学术邻居（HELIOS / CAS-Spec 的运行时深度自适应）重叠 |
| **证据路径** | `candidates/batch-invariance-cost/35_solved_check.md` 附录；decision #113 |
| **复活条件** | 若出现**结构性**新事实（例如某引擎的自适应控制器在 thinking 段**被硬编码闸门禁掉**，如 `ceiling_coeff=0` 或高 BS 锁 `step=1` 使其在该负载下失效），且可测出 ≥8% ⇒ 可复活；仅"调参更好"不算 |

### 线索 C：跨引擎指标语义一致性（唯一活口 #11，量化为负）

| 项 | 内容 |
|---|---|
| **现象** | 同模型/同负载/同客户端下，vLLM 与 SGLang 的 `accept_len` 差 **−32.6%**（1.479 vs 2.194 @bs32）；`itl/tpot` 比值 **1.07× vs 1.98×**；`mean_itl_ms` 的语义随**投机方法**漂移（决定其口径的是**每个流式 chunk 携带的 token 数**） |
| **机制（源码级）** | `mean_itl_ms` 记在**每个流式 chunk**（`benchmarks/lib/endpoint_request_func.py:241`，位于 `if choices := data.get("choices"):` 之内），`mean_tpot_ms` 是**每 token**（`benchmarks/serve.py:616`）⇒ `itl/tpot ≈ 每 chunk 携带的 token 数`（dflash2 下 = accept_len = 2.85；NGRAM 下 = 1.07） |
| **被否的确切原因** | 按判据 ③（整机账）**量化失败**：把 A1 归档网格（8 格 × d1/d3/d5）按"引擎报告的吞吐"选最优 vs 按文档轴选，**最大差 0.2%** ⇒ "语义不一致 ⇒ 配置选错 ⇒ 损失 X%"这条链在可测范围内**填不出 ≥8% 的数字**（与 decision #76 的"计数类指标 0.00% 一致、吞吐口径仅差 4%"同向） |
| **证据路径** | `results/p09-engine-conformance/2026-09-13/conformance.md`、`results/p06-frontier/2026-09-13/A1_4k/mechanism.csv`、decision #112 |
| **复活条件** | 若出现**语义差异 ≥8% 且直接改变配置选择**的场景（例如某新引擎把 `accept_len` 定义成 batch 平均而非每请求、或把 prefill token 计入 output 吞吐），并能量化由此产生的**实际损失** ⇒ 可复活 |

## 三、下一轮测绘结论（本轮最重要产出：三条可检验的判断）

### 结论 1：**"读引擎源码找痛点"这条路被证明是结构性无效的**（三次独立实证）

> **凡是通过"读引擎源码 / 读上游 roadmap"能发现的痛点，几乎必然已经被维护者知道并处理过。**

| 实证 | 内容 |
|---|---|
| ① | `sglang-draft-corpus`：S3 读到 SGLang roadmap 已做外置语料 ⇒ 继续做，撞上 **vLLM 早已 ship 同问题类**（prompt-lookup decoding，**opt-in**，见上「就地更正」） |
| ② | 本轮纠错：我以为"vLLM 把 prompt-lookup 设成默认" ⇒ 实际 `speculative_config` 默认 `None`（**opt-in**） |
| ③ | `batch-invariance-cost`：两家都 ship 了确定性开关，SGLang 甚至**在代码里** `raise` 挡住非 batch-invariant kernel |

**原因**：引擎维护者比任何外部研究者更早知道自己的痛点，且**有能力当场处理**（建开关、加校验、写注释）。
**⇒ 引擎源码是"已解问题的施工记录"，不是"未解问题的藏宝图"。**

### 结论 2：**可发表性在本工作区的约束下已被系统性关闭**

可发表需要**同时**满足：真实痛点 + 未被人从"我做 X 你做 Y"的差异轴占住 + 差异轴是**条件性**的 + 过**整机账** + 在**单卡/1 人周/只接受优化类**的半径内。
本目标 3 轮 + 上一段 12 轮的搜索表明：**同时满足这五条的课题，在"单卡 × vLLM/SGLang × 引擎内部与文献"这个空间里，我没有找到任何一个。**
这不是搜索不够（18 个对象 + 7 条候选 + 40+ 条决策记录），而是**该空间的发表密度已超过"可被调研发现的缺口"的消耗速度**。

### 结论 3：唯一未被证伪的输入源是**用户自己环境里的疼**

`GAP_SURVEY` §八 的推荐 ① 在本工作区**已被验证过一次**：E1 的 `R_byte` p95 = **0.072%** 与 D3 的 **1.0053** 都是**文献里没有的数字**（虽然最终因无 headroom 被归档，但它们的**真实性与无人做过**是成立的）。
⇒ **这是唯一还有期望值的路径**，且**必须由用户提供输入**（我无法访问用户环境里未被记录的现象）。
