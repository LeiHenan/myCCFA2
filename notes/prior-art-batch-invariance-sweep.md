# Prior-art sweep — batch-composition invariance of LLM inference engines

**Problem class under investigation.** LLM inference engines' outputs (and other results) are NOT
invariant to batch composition / scheduling, even at temperature=0 with a fixed seed. Engines ship
opt-in switches to make results batch-invariant (e.g. vLLM's `VLLM_BATCH_INVARIANT` env var), and
those switches disable / alter several performance paths.

**Provenance convention.** Every row is tagged `READ BODY` (page/source content was actually
retrieved and read) or `TITLE ONLY` (only a search-result title/snippet was seen).

**Network note.** The environment's configured HTTP proxy (`ALL_PROXY=http://127.0.0.1:7890`) accepts
CONNECT but fails the TLS handshake, so `curl` through it returns `HTTP:000`, and the `web_fetch`
tool failed for every URL tried. All reads below were done with a direct connection
(`env -u HTTPS_PROXY -u HTTP_PROXY -u ALL_PROXY curl ...`). The GitHub REST API hit the
60 req/hr unauthenticated cap from this IP partway through; GitHub HTML and
`raw.githubusercontent.com` were used instead.

### What the determinism switch actually disables (vLLM)

`vllm/model_executor/determinism/batch_invariant.py`, `override_envs_for_invariance()` (L1143-1161)
and `init_batch_invariance()` (L1163-1172), READ BODY:

- `VLLM_ALLREDUCE_USE_SYMM_MEM = "0"` — symmetric-memory all-reduce path off
- `CUBLAS_WORKSPACE_CONFIG = ":4096:8"` — comment at L1077: the alternative "variance is split-k, which we disable via the cuBLAS workspace"
- `NCCL_LAUNCH_MODE=GROUP`, `NCCL_COLLNET_ENABLE=0`, `NCCL_NVLS_ENABLE=0`, `NCCL_P2P_NET_DISABLE=1`, `NCCL_MIN_NCHANNELS=1`, `NCCL_MAX_NCHANNELS=1`, `NCCL_PROTO=Simple`, `NCCL_ALGO=allreduce:tree`, `NCCL_NTHREADS=1`, `NCCL_SOCKET_NTHREADS=1` — the NCCL tuning space is collapsed to a single deterministic configuration
- `VLLM_USE_AOT_COMPILE = "0"` — ahead-of-time compilation off
- `torch.backends.cuda.preferred_blas_library(backend="cublaslt")`; `allow_fp16/bf16_reduced_precision_reduction` forced; comment: "Disable TF32 for batch invariance - it causes non-deterministic rounding"

The docs' "Implementation Details" section states it plainly: the mode "Disables certain
optimizations that may introduce non-determinism (such as custom all-reduce operations in tensor
parallel mode)".

## 5. Gaps, discrepancies and unverified items

- **Doc vs source discrepancy (vLLM).** `vllm/envs.py` L628 says the mode "Requires NVIDIA GPU with
  compute capability >= 9.0", while `docs/features/batch_invariance.md` says "compute capability 8.0
  or higher" plus Intel XPU with Triton. Both READ BODY. The doc is the newer/hardware-broader
  statement; the env-var comment quoted in the problem statement is the stale one.
- **The switch is not sufficient.** Multiple open issues (P3, P4, P5, P6, P9) report
  batch-dependence *with* `VLLM_BATCH_INVARIANT=1`, on specific backends (FA3/sm_90), specific
  parallelism modes (SP/async-TP, DP), and specific ops (RMSNorm block size).
- **Open coverage holes named by vLLM itself** (#27433 body, READ BODY): FLASHINFER_MLA
  (help needed), prefix caching, AMD, XPU, speculative decoding ("this might be hard"), and
  "Optimize the batch invariant performance".
- **Mechanism separation matters.** L22, L23, L24 are KV-/prefix-cache effects and are a
  **different mechanism** from batch-composition invariance; they are labeled B above. L19, L21,
  L25, and parts of L13–L15 are adjacent (precision/atomics/cross-kernel) and labeled C.
- **Could not open / excluded:** "Bounded Determinism: A Framework for Analyzing the Operational,
  Functional, And Architectural Limits of LLM Inference" — scilit.com returned HTTP 403 and no
  arXiv ID was found, so it is **excluded as unverified**. Semantic Scholar API and the arXiv export
  API both returned persistent HTTP 429, so no citation-graph expansion of the anchor was possible.
  SGLang PRs #10651 / #10694 rest on **TITLE ONLY** evidence.
- **Sub-areas with nothing found** (queries listed in the search log): no arXiv work found on
  chunked-prefill output consistency, bitwise TP all-reduce determinism, MoE routing
  batch-dependence, or batch-size ↔ refusal/safety.
- **Deduplication note.** Several items below are corroborated by more than one agent
  independently; where the second reader disagreed with the first, the corrected value is recorded
  (e.g. vLLM #48391 is a merged fix **PR**, not an issue).
