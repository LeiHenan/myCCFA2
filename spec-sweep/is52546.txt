 Purpose
 Fixes #52258 . speculative_config.max_model_len is accepted and validated, then
never read.
 V0 used it to skip speculation for sequences past a threshold. V1 has no
consumer:
 $ grep -rn "draft_model_config" vllm/ --include=*.py | grep max_model_len \
 | grep -v ^vllm/config/
(no matches)
$ grep -rn "speculative_config\.max_model_len" vllm/ --include=*.py \
 | grep -v ^vllm/config/
(no matches)
 For ngram and custom_class , draft_model_config aliases
 target_model_config ( config/speculative.py:834 , :848 ), so the override at
 :1127 never runs. For draft-model methods the override does run, but nothing
reads the result.
 Modifications
 Warn at the end of SpeculativeConfig.__post_init__ when the field is set, and
replace this PR's original test with one asserting the warning.
 Warn rather than reject so existing configs keep starting, and rather than
implementing the V0 skip, which is a feature rather than a bug fix and needs a
scope decision. I asked about scope on #52258 and have not heard back, so this
PR covers only the silent-ignore part; I'm happy to follow up with the skip if
maintainers want it.
 Note on the change of approach: this PR previously added a failing test
asserting the value reached the draft config. That test was wrong. For ngram 
the draft and target configs are the same object, so it asserted
 draft == 80 and target == 200 simultaneously, which cannot hold. Even
un-aliased it would have passed while the option stayed unread, which is worse
than no test.
 Test Plan
 pytest tests/v1/spec_decode/test_max_len.py -k warns_that_it_has_no_effect
 Test Result
 1 passed . Reverting only the speculative.py change makes it fail, so it is
not passing vacuously.
 Whole file on an RTX 4090, 6 failed, 6 passed , against 6 failed, 5 passed 
for the same file on 017e9f4448 without this change: the same six
 test_eagle_max_len cases fail either way (pre-existing on this hardware) and
the extra pass is the new test.
 Note the file imports get_attn_backend_list_based_on_platform() at module
scope, so it does not collect without a supported accelerator.
 Notes
 Not a duplicate: no other open PR references #52258 .
 No model output changes, so no evals: the only runtime change is an added
warning.
 AI assistance was used for this change. I have reviewed every changed line.
