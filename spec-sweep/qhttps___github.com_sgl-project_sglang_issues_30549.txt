 Describe the bug
 Enabling --speculative-adaptive (default candidate config) crashes the server during startup on all TP ranks:
 File ".../sglang/srt/model_executor/graph_shared_output.py", line 56, in get_logits_buffer
 assert rows <= self.max_rows, (
AssertionError: shared logits buffer holds 128 rows but caller needs 256 (vocab_size=154880)
 followed by Received sigquit from a child process and full engine shutdown. Reproduced twice (2/2 boots) on the 2026-07-08 nightly ( nightly-dev-cu13-20260708-b3632494 , base commit b363249 ).
 Analysis
 The numbers line up exactly with the adaptive candidate geometry:
 128 = cuda_graph_max_bs (32) × initial speculative_num_draft_tokens (4) 
 256 = 32 × 8 , where 8 = steps 7 + 1 — the draft-token count of the largest default adaptive candidate ( candidate_steps [1, 3, 7] ).
 The shared logits buffer introduced in #29779 ("Share one logits output buffer across prefill/decode/draft cuda-graph") appears to be sized from the active speculative_num_draft_tokens , but --speculative-adaptive pre-builds runtime states for every candidate step ( AdaptiveController.init_states ), and capturing the steps=7 state requests bs × 8 rows → assert.
 ServerArgs.max_speculative_num_draft_tokens already exists and returns max(candidate_steps) + 1 when adaptive is enabled — sizing the shared buffer with it (instead of speculative_num_draft_tokens ) should cover all adaptive states.
 Timing-wise this is a regression from the interaction of two features: adaptive spec ( #21599 / #24055 , 04-20/06-05) and the shared logits buffer ( #29779 , 07-02) — the combination appears untested.
 Reproduction
 python -m sglang.launch_server \
 --model-path zai-org/GLM-5.2 \ # any EAGLE topk=1 target reproduces
 --tp 8 --speculative-algorithm EAGLE \
 --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 \
 --speculative-adaptive \
 --cuda-graph-max-bs 32
 Crash occurs while building/capturing the adaptive runtime states at startup (before Ready). vocab_size=154880 above is GLM-5.2; the assert is model-agnostic.
 Environment
 Image: lmsysorg/sglang:nightly-dev-cu13-20260708-b3632494 (main @ b363249 )
 Model: GLM-5.2 (glm_moe_dsa), w4afp8, 8×H100, TP8 (no dp-attention)
 Spec: EAGLE (NEXTN), steps 3 / topk 1 / draft 4, --speculative-adaptive with default candidates
 Happy to submit a PR sizing the buffer via max_speculative_num_draft_tokens if that's the preferred direction.
