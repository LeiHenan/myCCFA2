 Release Notes
 New Features 
 Added support for dynamic draft length scheduling in speculative decoding, allowing draft lengths to vary based on batch size for improved performance and resource utilization.
 Improvements 
 Enhanced per-draft-length caching and resource management for more efficient memory allocation and CUDA graph compatibility across varying batch sizes.
 Description
 This PR adds support for dynamic draft length (based on batch size) and max concurrency control (disable speculation when batch size is above threshold) in the one-model speculative decoding path.
 LLM API: Users can define a batch size → runtime draft length mapping via speculative_config.draft_len_schedule.
For example, draft_len_schedule = {4: 4, 8: 2, 32: 1} means:
 Batch sizes 1–4: use runtime_draft_len=4
 Batch sizes 5–8: use runtime_draft_len=2
 Batch sizes 9–32: use runtime_draft_len=1
 Batch sizes 33+: use runtime_draft_len=0 (implicit max concurrency control; speculation disabled)
 The runtime draft length is determined at the beginning of each iteration. For CUDA graph compatibility, when the runtime draft length changes between iterations, draft tokens are padded or truncated to match the current iteration's draft length. We allow speculation off and turn on later if the batch size gets smaller.
 For future works (will be in future PRs):
 Algorithm coverage: This PR currently supports only Eagle3. Will add support for all other one-model spec decode algorithm like MTP.
 Feature compatibility: Currently compatible with CUDA graphs and the overlap scheduler. Will test compatibility with other features.
 Speculation-off for low acceptance rate: Will port from the two-model path.
 Test Coverage
 Added accuracy tests on GSM8K in tests/integration/defs/accuracy/test_llm_api_pytorch.py for both dynamic draft length and max concurrency control. For dynamic draft length, as requests are submitted and completed, the batch size changes naturally, causing the draft length to change like 4→3→2→0→2→3→4.
 Added a unit test in tests/unittest/_torch/speculative/test_dynamic_spec_decode.py. A mock function forces the runtime draft length to cycle through 0, 2, and 4 (e.g., 4→4→2→2→0→0→2→2→…), which cover the tests of draft length increases, decreases, and disable/re-enable transitions.

 Introduces dynamic draft length support for speculative decoding, enabling variable draft lengths per batch iteration based on a configurable schedule.
