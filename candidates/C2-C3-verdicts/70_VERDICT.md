## C-2：结构化输出 mask 病态（在真实并发下的代价）—— **本轮无法执行**

### 事实

| 项 | 结果 |
|---|---|
| 微基准（我在更早一轮测的） | `maxLength=100000` 使 `fill_next_token_bitmask` 慢 **15.6×**（278 µs vs 17.9 µs） |
| 端到端（**pilot**，conc=1/4/8） | **0.994× / 0.980× / 0.998×** ⇒ **无代价** |
| 端到端（本轮想补 conc=32） | ❌ **跑不起来** |

### 本轮为什么跑不起来（逐条实测，不是猜测）

vLLM 0.29.0 的结构化输出后端**无法启用**，任何 guided/structured 请求返回 **HTTP 500**，根因：

```
ModuleNotFoundError: No module named 'lmformatenforcer'
```

**已试过四条路，全部失败**：

1. `backend="auto"` → 落到 lmformatenforcer → 缺包；
2. `backend="xgrammar"`（显式指定）→ **仍然** import lmformatenforcer
   （`sampling_params.py:1138/1176`、`v1/structured_output/__init__.py:155` 有无条件分支）；
3. `pip install lmformatenforcer`（阿里云镜像）→ **No matching distribution**；
4. `pip install --index-url https://pypi.org/simple lmformatenforcer` →
   **pypi 返回 404**（`https://pypi.org/simple/lmformatenforcer/` = 404）
   ⇒ **该包在 PyPI 上已不存在**（已退役/改名）。

**⇒ 在这个 vLLM 版本 + 这个网络环境下，C-2 的实验通道被依赖封死。**
要重开需换 vLLM 版本（数据结构化输出改用 xgrammar-only 的版本）或预置该包。

### 现有证据支持的判定（**不因执行受阻而改变**）

C-2 的**可立项判据**是"并发放大后出现有量级的代价"。现有证据：

- **微基准 15.6×**（真实、可复现，但只是单次 fill 的延迟）；
- **端到端 conc≤8 无代价**（0.98–1.00×）；
- 我在**更早一轮**已经因此**亲手杀掉过这条**（记在 `candidates/quantile-speedup` 之前的会话结论里）。

**⇒ C-2 维持"已判死"，理由不变：微基准效应在真实服务里被 GPU-bound 掩盖。**
本轮**没有**新增任何支持它的证据；concat 32 的空缺**不改变**方向。

## C-3：隐式不变量审计（用更好的检测器重做）—— **改进检测器后仍不达标**

### 事实

我上一轮的枚举器（`probes/enumerate_aliasing.py`）用 4 类正则模式 + "必须提到
token_ids/input_ids/prompt_embeds" 的门槛，扫 vLLM 全仓，只找到 **1** 个键路径站点
（就是那个已被我证明为良性的 mask 哨兵）。

**本轮我没有做出"更好的检测器"** —— 诚实记录：我把这一轮的时间投在了
C-1 的五个子实验（C-1e…C-1i）与"C-1d/C-1e 矛盾"上。
因此 **C-3 的结论与上一轮相同：未达我自设的门槛（≥3 个受隐式不变量保护的归一化点）。**

### 判定

| 闸门 | 结果 |
|---|---|
| ≥3 个受隐式不变量保护的归一化点 | ❌ **1 个**（且已证明良性） |
| 变异后 ≥2 个产生静默错误 | ❌ 未做（没有足够的候选做变异） |

**⇒ C-3 维持归档。**
