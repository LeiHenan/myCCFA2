# S4 可测量性与上界（Measurability & ceiling） — 投机解码/MTP 服务评测的方法学

**候选**：`specbench-methodology` ｜ **成本上限**：≤2 GPU·h（仪器冒烟）
**目标**：在花 GPU 之前算出**最好情况能赚多少**。上界不过 8% 就不要开跑。
**结论**：🟡 **闸门部分通过** —— 三条伪影里 **P3 通过（放大 2.85–4.23×）**、**P2 待 GPU 复核（预期 ~2.8×）**、
**P1 未通过（≤2.31 pp，且符号不一致）⇒ P1 降级**。方向据此**收窄**（见 §收窄后的判定）。

## 观测量与其恒等式

本方向的观测量不是"吞吐"，而是**报告量的内部一致性**。核心恒等式（在 A1 的 18 个格上实测核对过）：

```
每步延迟      step_ms   = mean_itl_ms                     （ITL 是「每步」不是「每 token」）
每 token 延迟 tpot_ms   ≈ mean_itl_ms / accept_len
单序列吞吐    tok/s/seq ≈ 1000 × accept_len / step_ms = 1000 / tpot_ms
聚合吞吐      tok/s     ≈ batch × 1000 / tpot_ms       （理想并发下）
接受长度上界  accept_len ≤ γ + 1
```

⇒ 任何报告里 `accept_len × (1000/step_ms)` 与 `tok/s/seq` 不一致、或 `accept_len` 触到 `γ+1`、
或 `itl/tpot ≠ accept_len` 的，都**内部不自洽**。这就是可自动检测的抓手。

### 三条伪影的幅度 vs 8% 闸门

| 伪影 | 幅度（实测） | 闸门 | 判定 |
|---|---|---|---|
| **P1 暖机/重复次数口径** | `argmax_depth` 在 8/8 格**都没变**；差距偏差最大 **2.31 pp**，且**符号不一致**（bs=1/32 为负、bs=8/16 的 γ=7 为正） | ≥8% | ❌ **未通过 ⇒ 降级** |
| **P2 数据集（random ⇒ 接受率 1.00）** | 接受长度从真实 **2.45–2.88** 变成 **γ+1 = 8** ⇒ 隐含 **2.8–3.3×** | ≥8% | 🟡 **待 GPU 复核**（预期通过） |
| **P3 ITL/TPOT 口径** | 当成"每 token"用 ⇒ 放大 **2.45–2.88×**；报 `p99 ITL` ⇒ **2.85–4.23×** | ≥8% | ✅ **通过** |

> **P1 的诚实结论**：冷启动爬升**确实存在且随配置变化**（bs=1 时 d5 爬 11–13%、d1/d3 只爬 6–7%），
> 但它**在本数据上只造成 ≤2.31 pp 的差距偏差，且不改变任何一格的 argmax** ⇒
> 我此前"均值口径会系统性偏置赢家"的说法**被自己的复算证伪（在幅度上）**。
> **P1 从"三大伪影之一"降级为"次要注意事项"**，不得写成论文主张。

## 收窄后的判定（方向仍然成立，但主张必须换）

**能站住的是 P2 + P3 的合体**：它们都是**因子级（2.8–4.2×）**的不自洽，而不是几个百分点。
⇒ 主张从"暖机口径会偏置结论"改为：

> **投机解码/MTP 的服务报告存在可**自动检测**的内部不自洽；用一组恒等式审计公开与自产的报告，
> 可以量化"有多少报告的数字在数学上不可能同时成立"。**

这条主张的好处：
1. **可自动检测** ⇒ 不是 best-practice 清单，而是**判据 + 工具**（对冲伪问题形态⑥）；
2. **零 GPU 就能做主体**（拿公开报告 + 我们的 120 格数据当语料）；
3. **可量化**（审计 N 份报告，报不自洽率与不自洽幅度）；
4. GPU 只用来**建立 ground truth**（random vs 真实文本的接受率对照）—— ≤2 GPU·h。

## 仪器冒烟与口径核对

- `mean_itl_ms` 的语义**必须对着引擎源码/文档核**：vLLM 需专门发 PR **#55283** 澄清 ITL vs TPOT
  ⇒ 连官方都认为易混；本工作区已在 18/18 格上核对 `tpot ≈ itl/accept_len`（误差 <1%）。
- `.metrics` 的 **gauge 跑完归零、只有 `*_total` 计数器可用**（decision #66）。
- `/metrics` 的 `vllm:spec_decode_num_accepted_tokens_total` + `num_draft_tokens_total` 可用于**交叉核对**
  `bench.json` 里的 `spec_decode_acceptance_length`（两条独立路径给出同一个量 ⇒ 可做自检）。

## 噪声预算

采数前的估计（来自 A1 的逐次数据，同配置重复）：

- **吞吐**：`bs=1` 重复极差 **3–9.5%**；`bs=8/16/32` **1.5–4%**。⇒ 判定阈值取 **效应 > 3× 极差**（bs=1 时约 10–28%）。
- **接受长度**：逐次极差 **<1%**（它是模型属性，不受调度噪声影响）⇒ 这是本方向**最稳的观测量**，
  因此"内部不自洽"的判定应优先建立在接受长度与它的恒等式上，而不是吞吐。
- **⚠️ 冷/热双峰**：极端显存配置下同格可差 **2–2.6×**（decision #65）⇒ 复现实验必须固定显存预算并核 `preemption == 0`。

## 可采纳前置条件

1. 任何"接受率"结论必须声明**数据集类型**（random / 真实文本）与 **γ**；
2. 任何"每步代价"结论必须声明用的是 ITL 还是 TPOT，并给出 `accept_len`；
3. 交叉核对必须来自**两条独立路径**（bench.json 与 /metrics 计数器），单一来源不算；
4. 复现实验必须 `preemption == 0`（否则吞吐读数受显存挤占污染）。
