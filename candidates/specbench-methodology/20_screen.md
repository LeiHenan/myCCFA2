# S2 伪问题筛查（Pseudo-problem screen） — 投机解码/MTP 服务评测的方法学

**候选**：`specbench-methodology` ｜ **成本上限**：0 GPU·h
**目标**：把『没人做过』『听起来优雅』『指标能动』这类立项理由剔除掉。
**结论**：🟡 **未被直接杀掉，但被限定形态** —— 唯一能立住的形态是「**spec-decode 度量恒等式的可行域刻画 + 自检器 + 对公开报告的审计**」；若退化成"建议清单"，则按形态⑥ 杀。

## 七形态逐条判定

| 形态 | 命中？ | 说明 |
|---|---|---|
| ① 「没人做过」当立项理由 | ❌ 不适用 | 我们的立项理由是**量级**（2.8–4.2× 因子级不自洽）与**别人在问**（论坛两帖），不是"空白" |
| ② 方法找问题 | ⚠️ **需警惕** | 恒等式是我在 `#6` 分析里顺手推出来的 ⇒ 必须证明**别人真的在这些量上出错**，而不是"我能算出漂亮恒等式"。**对冲**：S3 的审计语料 + 服务器 ground truth |
| ③ 指标能动但没人疼 | ❌ 不成立（已排除） | 疼的证据：vLLM 论坛两帖问"标准测法/真实吞吐"；vLLM 需专门发 doc PR #55283 澄清 ITL/TPOT；**且邻接论文自己实测出 21%（温度）与 50%（输入 token）的度量伪影** ⇒ 社区承认这类疼 |
| ④ 度量口径伪影 | ✅ **正是本方向的研究对象** | 本方向就是研究"口径本身"，所以这一形态**不构成杀**，但要求我们**自己先过恒等式检验**（S4 已做：18/18 格核过 `tpot ≈ itl/accept_len`） |
| ⑤ 上界不足 8% | ✅ **已算（S4）** | P3 = **2.45–4.23×**；P2 隐含 **2.8–3.3×**（待 GPU 复核）；**P1 已因不足闸门被降级** ⇒ 上界通过 |
| ⑥ 只是工程配置 / best-practice 清单 | ⚠️ **最大风险** | 若结论只是"用真实文本、别把 ITL 当 TPOT"，那是**建议清单，不是论文**。**唯一的对冲**：给出**可行域刻画（哪些指标组合在数学上不可能同时成立）+ 可自动运行的自检器 + 对 N 份公开报告的审计结果**。⇒ 这是本方向**必须交付**的三件套，缺一即退化为 plumbing |
| ⑦ 收益只在极端角落 | ❌ 不成立（已排除） | 不自洽出现在**主流区间**：`bs∈{1,8,16,32}`、`ctx=4096`、`accept_len 2.45–2.88`、真实文本 ⇒ 不是极端角落 |

**判定**：**不被七形态直接杀掉**，但**形态⑥ 是生死线**：必须交付"可行域 + 自检器 + 审计"三件套。这与上一个候选（被 S3 直接判死）不同，本候选的形态是可判定的。

## 自检十问

1. **有人在疼吗？** 是 —— 论坛两帖、doc PR #55283、邻接论文自测出 21%/50% 伪影 ⇒ 不是我觉得。
2. **有数字吗？** 有 —— P3 **2.45–4.23×**（自测 18 格）、P2 隐含 **2.8–3.3×**（待复核）、邻接 **21%/50%**。
3. **现在没人治吗？** **部分有人治**：2605.24217 治**客户端**（GIL/M-G/1）、§4.3 治**温度**、§4.4 治**前缀缓存/截断**，且其 §7.2 把"受控缓存命中率的数据集"列为 **future work**；**没有任何工作治 spec-decode 自身的度量恒等式**（accept_len / 每步代价 / ITL 语义）⇒ 缝隙存在但**窄**。
4. **能在这台机器上验证吗？** 能 —— 单卡 96 GB；主体（恒等式 + 审计语料）**零 GPU**，GPU 只用于 ground truth（random vs 真实文本 / 温度对照）。
5. **3–4 周能拿到可信数字吗？** 能到决策级；论文级取决于**语料规模**（审计多少份公开报告）。
6. **相对最佳"固定配置"有 ≥8% 空间吗？** 重新表述：**伪影幅度 / 真实效应** 的比值 = 2.8–4.2× ⇒ 远超 8%（S4 已算）。
7. **我把"没人做过"当理由了吗？** 没有；相反，最近邻已经很近（2605 同类体裁、且是 Google 团队 + 5000 QPS 基础设施）⇒ **我们必须避开规模竞争，走"恒等式 + 可自检"这条他们没走的路**。
8. **我的度量口径经得起恒等式检验吗？** 经得起 —— 18/18 格实测 `tpot ≈ itl/accept_len`（<1%），且**初版写错被自测抓到**（decision #67）⇒ 我们自己也踩过这个坑，不是旁观者。
9. **结论会不会只在极端角落成立？** 不会 —— 见形态⑦。
10. **如果失败了，能不能留下可迁移的结论？** 能 —— 「服务报告的可行域自检」这套方法可迁移到任何多指标系统报告（不限于投机解码）。

> 十问全部作答；第 3 问的答案是"部分有人治"，**因此存活清单里把它写成"窄缝"而不是"空白"**（不得夸大为"没人做过"）。

## 存活清单

| 编号 | 一句话 | 进入条件（不满足即淘汰） | 为什么它不是伪问题 |
|---|---|---|---|
| **P3** | 投机解码下 ITL 是**每步**延迟 ⇒ 当成每 token 用时，每步代价与尾延迟被放大 `accept_len` 倍（实测 **2.45–4.23×**） | 必须证明**别人真的这么用错**（审计语料），否则只是"我们知道" | 官方需发 doc PR **#55283** 澄清 ITL/TPOT ⇒ 混淆被官方承认；本工作区 18/18 格实测恒等式 |
| **P2** | `--dataset-name random` ⇒ 接受长度被推到上界（隐含 **2.8–3.3×** 偏差）；温度/数据集选择直接改变接受率 | **必须先在服务器上复现并给出机制**（不能只引用旧笔记）；且需与 2605 §4.3（温度 21%）、§7.2（缓存命中数据集）划清边界 | 有本工作区实测记录 + 邻接论文自证同类伪影存在（21%） |
| **新·检测法** | **可行域刻画 + 自检器 + 审计**：给定报告的 (γ, accept_len, ITL, TPOT, tok/s, batch)，判定其是否数学上自洽 | 必须能在**公开报告**上跑出**非平凡**的不自洽率（若几乎没人违反 ⇒ 无病呻吟，杀） | 这是形态⑥ 的唯一对冲：把"建议"变成"判据 + 工具 + 人群证据" |
