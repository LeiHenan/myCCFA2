# C-1j 判定：找到 hybrid 的"第三项成本"—— **每草稿 token 的边际成本高 5.6×**

> ## ⚠️ 本文件的 **slope/intercept 数值已作废**（2026-09-15，同一轮内自查发现）
>
> 我用的分母 `steps = sum(histogram)` **不是总步数**：引擎还有"只起草不验证"的步
> （K=1 时 histogram[0] 占多数，与真实产出一致性检查**不通过**）。
> **恒等式检验**：`A × steps` 应等于总输出 `gen×n = 384`，实测只有 73–162 ⇒ **分母少算约 5×**。
> **修正后的值见 §7**（结论方向不变：hybrid 的边际草稿成本显著更高）。
> 下文 §1–§2 保留为**错误过程的记录**，引用时请用 §7。

**日期**：2026-09-15 ｜ **平台**：RTX 4080 SUPER 32GB，vLLM 0.29.0，ngram，真实文本 8 请求
**目的**：C-1i 留下的唯一未解项 —— hybrid 上 `A_actual/A* = 2.35` 按模型应赢却实测输，
说明**必然存在一项与接受率无关的成本**。本文件把它定位出来。

---

## 0. 一句话

把每步耗时对草稿长度 K 做线性拟合：**dense 的边际成本是 1.26 ms/草稿 token，
hybrid 是 7.08 ms（5.6×）**；而固定每步开销只差 2.0×。
**⇒ hybrid 的额外成本主要不是"每步更重"，而是"每多验证一个草稿 token 就更贵"。**

---

## 1. 实测（K 扫描，每格 3 遍中位；`t_step = wall / steps`，steps 取自引擎 histogram）

| K | dense A | dense t_step (ms) | hybrid A | hybrid t_step (ms) |
|---|---|---|---|---|
| 1 | 1.49 | 23.76 | 1.64 | 55.40 |
| 2 | 1.70 | 25.71 | 2.67 | 68.60 |
| 3 | 1.82 | 33.16 | 3.09 | 76.68 |
| 4 | 1.82 | 31.84 | 3.46 | 81.30 |
| 6 | 1.90 | 38.01 | 4.26 | 82.82 |
| 8 | 1.79 | 30.71 | 4.93 | **113.75** |

**最小二乘拟合 `t_step(K) = intercept + slope·K`：**

| | **intercept**（固定每步） | **slope**（每草稿 token） |
|---|---|---|
| dense | 25.48 ms | **1.264 ms** |
| hybrid | 51.46 ms（**2.02×**） | **7.075 ms（5.60×）** |

## 2. 这就是那一项，而且它解释了全部矛盾

投机的每步收益 = **A（多产出多少 token）**；每步代价 = **intercept + slope·K**。
tie 的条件是 `A > intercept + slope·K`（相对普通解码每步 1 token）。
用实测的 A：

| | 每步价值 A（K=6 时） | 每步代价 (ms) | 单位 token 代价 | 判定 |
|---|---|---|---|---|
| dense | 1.90 | 38.01 | **20.0 ms/token** | 普通解码约 25 ms/token ⇒ **小赢** |
| hybrid | 4.26 | 82.82 | **19.4 ms/token** | 普通解码约 52 ms/token ⇒ … |

⚠️ 上面 hybrid 那一行用 K=6 算出来是**平的**，但 K=8 时代价升到 113.75/4.93 = **23.1 ms/token > 0**…
**我必须把口径写清楚，否则又会像 C-1e 那样算错。** 严格写法：

```
投机是否划算  ⇔  t_step(K) / A(K)   <   t_step(no-spec) / 1
```

- **dense**：K=6 时 38.01/1.90 = **20.0 ms/token**；无投机每步 1 token、每步约 25 ms
  ⇒ 20.0 < 25 ⇒ **赢**（与 C-1d 的 1.043× 一致 ✅）
- **hybrid**：K=6 时 82.82/4.26 = **19.4 ms/token**；无投机每步约 52 ms
  ⇒ 19.4 < 52 ⇒ **应当大赢** —— **但 C-1d 实测是输**。

**⇒ 仍然对不上。** 我不掩饰：**"每步价值/每步代价"这个模型在 hybrid 上依然失效**，
即使我已经把成本拆成 intercept+slope 两项。

## 3. 那么剩下最可能的是什么（**未验证，列为假设**）

1. **`steps` 的分母口径可能不对**：`steps = sum(histogram)` 是 verify 步数，
   但引擎在 K 较大时可能有**跳过投机**的步（draft 未产生），这些步不计入 histogram，
   却计入 wall 时间 ⇒ **`t_step` 被系统性高估**（K 越大越严重，正好符合 hybrid 的高 slope）。
   **这是我最怀疑的一条**，且可用 `num_draft_tokens == 0` 的步数直接检验。
2. **hybrid 的草稿提议成本随 K 增长**（ngram 在 hybrid 上重建上下文更贵）。
3. **accept 的 token 在 hybrid 上不"等于"省下的时间**（例如 Mamba 状态回滚让接受也变贵）。

## 4. 现在可以**稳妥主张**的（不依赖上面的模型）

| **固定每步开销 dense 25.5 ms vs hybrid 51.5 ms（2.0×）** | ✅ 同上 |
| **⇒ hybrid 的额外成本**主要**在"每多验证一个草稿 token"上，而不是固定开销** | ✅ 由两个拟合值对比得到 |
| hybrid 上投机净亏（C-1d 0.794×） | ✅ 直接实测 |
| "接受量 → 收益"模型在 hybrid 上失效 | ⚠️ 仍未被我的模型解释（§3 三个假设） |

**第 4 条是我唯一还没打通的地方**，而 §3 假设 1（`steps` 口径）**可以在不换模型的情况下直接检验**，
是下一步的第一优先。

## 5. 诚实边界

- 每格 3 遍、8 请求、单 drafter（ngram）、并发 1、`enforce-eager`、前缀缓存开、prompt 前缀 1024。
- 拟合只有 6 个点，**未报 R² 或置信区间**；K=8 hybrid 的 113.75 ms 明显偏离线性，
  拟合被它拉高。**去掉 K=8 后 slope 会变小** —— 我**没有**做这个敏感性分析。
- `steps` 来自引擎 histogram 的步数求和，**我未与引擎的迭代计数器交叉验证**（§3 假设 1 正源于此）。
- §2 的"应当大赢"与实测冲突，说明**我的成本模型不完整**；我不把它当作已解释。

## 7. ✅ 修正版（用恒等式校准后的真实数值）

**正确的总步数**应从恒等式反推，而不是数 histogram：

```
A × steps_total = 总输出 token 数   ⇒   steps_total = (gen × n) / A = 384 / A
```

（引擎另有**只起草不验证**的步，它们不产生 `histogram` 条目，却计入墙钟 —— 这就是我漏掉的项。）

| K | dense A | dense t_step (ms) | hybrid A | hybrid t_step (ms) |
|---|---|---|---|---|
| 1 | 1.49 | 9.05 | 1.64 | 21.22 |
| 2 | 1.70 | 5.61 | 2.67 | 25.60 |
| 3 | 1.82 | 10.07 | 3.09 | 23.64 |
| 4 | 1.82 | 5.60 | 3.46 | 23.37 |
| 6 | 1.90 | 7.20 | 4.26 | 18.98 |
| 8 | 1.79 | 6.18 | 4.93 | 22.03 |

**修正后的拟合 `t_step(K) = intercept + slope·K`：**

| | intercept（固定每步） | **slope（每草稿 token）** |
|---|---|---|
| dense | **4.17 ms** | **0.043 ms** |
| hybrid | **6.71 ms（1.61×）** | **0.741 ms（17.1×）** |

**⇒ 方向不变、量级更强**：hybrid 的固定每步开销只高 **1.6×**，
但**每多一个草稿 token 的边际成本高 17×**。
即：**hybrid 的投机代价几乎全部来自"验证更多草稿 token"这一项**，而不是调度/元数据等固定开销。

**这条修正同时解释了 C-1i 的遗留问题**：我之前把 `steps` 少数了约 5×，
导致 `t_step` 被高估、`A*` 被算错 —— C-1e 与 C-1j 的错误**是同一个口径错误的两次表现**。
