# S4 可测量性与上界（Measurability & ceiling） — 跨引擎指标定义一致性（投机解码/服务度量）

**候选**：`engine-metric-conformance` ｜ **成本上限**：≤2 GPU·h（仪器冒烟 + 首个对照）
**目标**：在花 GPU 之前算出**最好情况能赚多少**。上界不过 8% 就不要开跑。
**结论**：🟡 **闸门条件性通过** —— **已知分量是因子级（2.45–2.88×，远超 8%）**；
**未知分量（两引擎同负载下的实际差异）必须实测** ⇒ 本节把它写成**可执行的一致性断言**（C1–C4），
实测不达标即判死。

## 观测量与其恒等式

本方向的观测量不是吞吐，而是**"两个指标是不是同一个量"**。判据写成**可执行断言**（这是 S2 形态⑥ 要求的对冲）：

| 断言 | 内容 | 判定方式 | 失败意味着 |
|---|---|---|---|
| **C1** | Dynamo 表中被判为"对应"的指标对，在同一负载下**数值应当一致** | 同负载取两引擎同名/异名指标的数值，算相对差 | **表中映射在语义上错误** ⇒ 跨引擎比较不可比 |
| **C2** | 每个延迟指标属于**每 token** 还是**每步**，可由它与 `accept_len` 的比值判定 | 若 `A/B ≈ accept_len`（而非 ≈1）⇒ 两者**单位不同** | 把 SGLang 的 ITL 与 vLLM 的 TPOT 并列时，**差 `accept_len` 倍** |
| **C3** | 两引擎的"接受长度"必须是同一个定义（是否含 bonus token、是否按 step 计） | `spec_accept_length`（SGLang）vs `1 + accepted/drafts`（vLLM 计数器）在同负载同 γ 下比较 | 接受长度跨引擎不可比 ⇒ 所有接受率驱动的结论不可移植 |
| **C4** | 吞吐的计入口径必须声明（仅输出 token vs 输入+输出） | 同负载下比对 `output_throughput` 与 `total_token_throughput` 类指标 | 吞吐差异被**口径**而非性能解释（经典跨引擎误比） |

## oracle 上界

本方向没有"完美决策能多赚 X%"的形态，其等价上界是：**不可比性造成的最大误差幅度**。

| 分量 | 数值 | 来源 | 是否 ≥8% |
|---|---|---|---|
| **已知分量：ITL ↔ TPOT 单位差** | **2.45–2.88×**（= `accept_len`） | vLLM 上 24 格实测（decision #76）；Dynamo 表对 SGLang(vLLM) 的 ITL/TPOT 非对称**零提示** | ✅ 远超 |
| **已知分量：TPOT 命名（vLLM 自身）** | 投机解码下 Prometheus 的 TPOT **数值等于 ITL** | vLLM issue **#19776** + doc PR **#55283** | ✅ 因子级 |
| **未知分量：两引擎同负载的实际差异（C1/C3/C4）** | **待实测** | 本轮新增（SGLang 已装入独立 venv） | ⚠️ **未定 ⇒ 本方向生死于此** |

**⇒ 闸门规则（先写下）**：若实测 C1/C3/C4 的差异 **全部 <8%** ⇒ 说明"跨引擎语义实际等价、文档只是不完整"
⇒ **判死**（负结论写成"名称映射虽不完整但语义一致"）。若**任一项 ≥8%** ⇒ 上界成立，进入 S5/S6。

## 仪器冒烟与口径核对

- **必须用同一个客户端打两个引擎**（否则客户端差异与被测量的引擎差异混淆）：用 `vllm bench serve`
  对**两家**的 OpenAI 兼容端点发同一份 prompt、同一 `max-concurrency`、同一 `OUTLEN`；引擎侧数值**只从各自的 `/metrics` 取**。
- **`.metrics` 只采计数器**；且**同一 serve 会话内跨 rep 必须用增量**（我们已在此踩过坑：decision #76，
  直接比累计值会造出 8–16% 的**假**不自洽）。
- **vLLM 侧的接受长度有两条路径**：`bench.json` 的 `spec_decode_acceptance_length` 与
  `/metrics` 的 `1 + accepted/drafts` ⇒ **两条路径本身就是 C3 的参照系**（已验证 24/24 一致，误差 ≤5%）。
- **SGLang 侧**（Dynamo 表所列）：`sglang:spec_accept_length`（gauge）、`sglang:spec_accept_rate`（gauge）。
  ⚠️ **gauge 在跑完后会归零**（我们在 vLLM 上验证过这个陷阱）⇒ **必须在 bench 运行中抓取**，
  或改用 SGLang 的 bench 工具（`sglang.bench_serving`）自带的统计输出。**这一条是仪器能否成立的关键。**

## 噪声预算

采数前的估计（来自 A1 的 120 格逐次数据与 p08 的 24 格 ground truth）：

| 量 | 噪声 | 对判据的含义 |
|---|---|---|
| **接受长度** | 逐次极差 **<1%**（模型属性，不受调度噪声影响） | C3 的 8% 阈值**远超噪声** ⇒ 可分辨 |
| **计数类**（prompt/generation tokens、完成请求数） | **精确量**（同负载应逐位相同） | C1 用 **1%** 容差已很宽松 |
| **吞吐** | `bs=1` 极差 **3–9.5%**，`bs≥8` **1.5–4%** | C4 用 **±5%** 容差 |
| **延迟** | 绝对噪声较大，但判据只用**比值**（`itl/tpot`） | C2 的 ≥2× 阈值对噪声不敏感 |
| **⚠️ 冷/热双峰** | 极端显存配置下同格可差 **2–2.6×**（decision #65） | 必须固定显存预算并核 `preemption==0` |
| **⚠️ 累计计数器陷阱** | 直接比累计值会造出 **8–16% 假差异**（decision #76） | 一律用**增量** + 分组键覆盖 serve 会话 |

## 环境前提

| 项 | 值 |
|---|---|
| 引擎 A | vLLM **0.29.0**（`/root/ccfa_venv`，已验证） |
| 引擎 B | SGLang（独立 venv `/root/autodl-tmp/venvs/sglang`，**不得与 vLLM 混装**），版本以装完后自检为准 |
| 模型 | `Qwen3-4B`（同一份本地权重，KV=bf16） |

| 负载 | `prompts_4096.jsonl`（32 条真实文本），`OUTLEN=128`，`bs ∈ {1,32}`，3 reps |
| 对照 | 同一 load 下 **spec off** 各跑一遍（作为"普通解码下 ITL 是否已是同一个量"的基线） |
| 客户端 | `vllm bench serve`（同一个客户端打两家） |

## 可采纳前置条件

1. 两引擎**同模型、同 dtype、同 max-model-len、同 OUТLEN、同 prompt 顺序**；
2. 引擎侧指标**只取计数器或运行中抓取的 gauge**，禁止取跑完后的 gauge；
3. 跨 rep 一律用**增量**，分组键覆盖**整个 serve 会话**；
4. `preemption == 0`（vLLM 侧）或 `num_retracted_reqs == 0`（SGLang 侧）—— 否则吞吐读数受显存挤占污染。
