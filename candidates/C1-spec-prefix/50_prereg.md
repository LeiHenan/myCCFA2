## 0. 先写清楚这条可能**根本不是新课题**

上游已有材料（来自本工作区侦察，**我会在读正文前不采信其结论**）：

本预登记要验证的是**更窄的主张**（见 §1），并**在采数前**承认：若窄主张也不成立，本候选归档。

## 1. 主假设（可falsify）

> **前缀缓存对投机解码的破坏是 `drafter 类别特异`的，且其端到端吞吐代价的量级
> 远大于"接受率下降"本身所暗示的**——因为失效路径不只是接受率，
> 还包含**该请求的 prompt 被反复重算**。

**可证伪的预测**（三档，逐条独立）：

| # | 预测 | 若为假则 |
|---|---|---|
| P1 | `dflash2` 在第 2 遍（前缀缓存已热）时 **cached_tokens ≈ 0**（prompt 全量重算） | 假设的核心机制不成立 |
| P2 | `eagle3` 与 `ngram` 在第 2 遍时 **cached_tokens ≈ prompt 长度**（正常命中） | "类别特异"不成立 |
| P3 | 端到端吞吐：**(P/C 开 vs 关) 的差值在 dflash2 上显著大于在 eagle3/ngram 上**，且差异 > seed 间波动 | 无工程后果 ⇒ **归档** |

**关键口径**：P3 是**唯一的立项判据**。P1/P2 只是机制证据，**单独不足以立项**
（上一轮我已经因为"机制真实但无后果"归档过键基础方向）。

## 2. 网格（覆盖极值）

| 轴 | 取值 | 为什么覆盖极值 |
|---|---|---|
| drafter | `dflash2` / `eagle3` / `ngram` / **无投机（对照）** | 三种机制类别齐全；无投机是零点 |
| 前缀缓存 | 开 / 关 | 唯一自变量 |
| 复用形态 | 第 1 遍（冷）/ 第 2 遍（热）/ 第 3 遍（再热） | **极值**：第 1 遍必然全 miss，第 3 遍检验"滞后一拍" |
| 并发 | 1 / 8 | 极值：单请求看机制，并发看代价是否放大 |
| seed | 5 个独立 prompt 集 | 抗"单次运行"错误 |

**必报量**：`cached_tokens` / `prefix_cache_hits_total` / 吞吐（tok/s）/ TTFT p50。
**每个配置重复 5 次**（workspace §4.1），报中位与极差。

## 3. 对照（缺一不可）

1. **无投机 + 前缀缓存开/关**：证明缓存本身工作（若这里也不命中，整个实验无效）；
2. **同 drafter 换 seed**：给出"类别内"波动，P3 的差异必须大于它；
3. **冷/热/再热三遍**：区分"完全不命中"与"滞后一拍命中"；
4. **输出长度钉死**（`ignore_eos` + `max_tokens`）：消除输出长度混淆。

## 4. 杀判据（写死在采数前）

- **杀 P1/P2 失败**：若 dflash2 也正常命中 ⇒ 机制不存在 ⇒ 归档；
- **杀 P3 不成立**：若 dflash2 的 (PC开 vs 关) 吞吐差 **≤ 1.15×**，或该差 **不大于** eagle3/ngram 的同类差
  ⇒ **无工程后果 ⇒ 归档**（这是主判据）；
- **杀 不一致**：若 5 个 seed 中 P3 的方向不一致（有正有负）⇒ 不可复现 ⇒ 归档。
