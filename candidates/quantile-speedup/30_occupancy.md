# 第 5–6 轮结论：方向 B 的**新颖性核查通过**，但严格复现被环境问题阻塞

**日期**：2026-09-14 ｜ **平台**：<SSH_HOST>（RTX 4080 SUPER，vLLM 0.29.0）｜ **成本**：≈0.3 GPU·h

---

## 1. 本轮最重要产出：**新颖性核查做完了，方向 B 站得住**

我读了最近邻 [*Speculative Decoding: Performance or Illusion?*](https://arxiv.org/abs/2601.11580)
（arXiv 2601.11580v2，MLSys'26，UC Berkeley / Stoica / Cheung 组）的**全文 HTML**，
并对关键词做了机械扫描：

| 关键词 | 命中 | 上下文 |
|---|---|---|
| `percentile` | 3 | **全部**在"per-request mean **generation length** 的箱线图（25–75 分位，须 5–95）"这一处 |
| `p95` / `p99` | **0** | — |
| `tail latency` | **0** | — |
| `jitter` / `straggler` / `worst-case` | **0** | — |
| `SLO` | 0（1 处匹配是 `translate` 的子串） | — |

**该文实际做什么**（据其自述贡献）：
1. vLLM 上的生产级 SD 评测；2. 加速比分解（验证阶段主导）；3. **接受行为**在
   *token 位置 / 请求 / 数据集* 三个层面的变异；4. 理论上界 + 自适应组合（4.9×）。

**⇒ 差异轴成立（这是本轮的关键结论）**：

> 该文报的是**接受长度/生成长度**在请求间的变异，落点是**均值加速比与理论上界的差距**；
> **全文没有任何一处给出延迟或加速比的分位数、尾部或抖动**。
> 本文报的是**端到端逐请求加速比分布**，落点是**按分位数签订的 SLO 是否被加速技术破坏**。
> **当 SLO 以 p95/p99 表述、且加速比在请求间高度异质时**，二者结论不同。

**这不是"换格子"，是"换问题"**：同一批数字，一个问"平均快多少"，一个问"合同里的那个数有没有变好"。

## 2. 但严格复现**没有跑成**（必须如实说）

### 2.1 试过的设计与其失败原因（全部是我自己的工程问题，非科学问题）

| 设计 | 失败原因 |
|---|---|
| 3 引擎 @ `gpu_util=0.28` | 第 3 个引擎拿不到 KV block（单引擎配额太小） |
| 3 引擎 @ `gpu_util=0.42` | 总量超卡 |
| 2 引擎建好后 `del` 再建第 3 个 | **`empty_cache()` 与引擎自身关闭竞态** ⇒ 显存不释放 |
| 2 引擎 @ `max_len=2048` | 两个引擎的 KV 需求合计 > 卡 |
| **2 引擎 @ `max_len=1024`** | ✅ **引擎能起来**（已验证 `ENGINE1 OK` / `ENGINE2 OK`），但**完整 200-prompt × 3 遍测量超过我的单次命令窗口（10 分钟）** |
| 用 `setsid nohup` 后台跑 | 该主机上**反复无法持久化**（多次尝试后 `pgrep` 只剩查询自身，且不产生日志文件） |

**最后一次有效状态**：2 引擎（baseline + ngram-spec）@ `gpu_util=0.42, max_len=1024`
在同一进程内**可以并存**（已用最小脚本验证）。

### 2.2 因此当前证据等级

| 项 | 等级 |
|---|---|
| 新颖性（无同靶子工作） | ✅ **已核实**（全文关键词扫描 + 自述贡献比对） |
| 现象存在（均值 vs 尾部背离） | ⚠️ **仅 pilot（n=24×1）**：`mean 1.197× / p99 0.997× / CV 0.078→0.320 / 逐请求 0.81–2.59×` |
| 现象稳健 | ❌ **未验证**（缺 n≥200、缺噪声底、pilot 有实例间混淆） |

**⇒ 方向 B 现在是"新颖性已确认、量级未确认"的状态。**

## 3. 下一轮的执行方案（已把环境坑全部标注）

**在能跑满的窗口内一次执行**（预计 15–25 分钟）：

```bash
# 单进程、两引擎、交错、含同引擎二次通过作噪声底
cd /root/autodl-tmp
VLLM_USE_FLASHINFER_SAMPLER=0 VLLM_ATTENTION_BACKEND=FLASH_ATTN \
  nohup /root/miniconda3/bin/python e4_final.py \
    --n-prompts 200 --gpu-util 0.42 --max-len 1024 --tag main \
    > /root/autodl-tmp/e4out.log 2>&1 &
```

**已知必须设的参数**（踩过的坑）：
- `--max-len 1024`（2048 会让两引擎 KV 合计超卡）
- `--gpu-util 0.42`（两引擎；三引擎不可行）
- `VLLM_USE_FLASHINFER_SAMPLER=0`（缺 flashinfer 包）
- 单进程**最多建两个** `LLM` 实例

**判据（先写后做）**：
- 立项：`p95_ratio / mean_ratio > 1.15`（尾部明显跟不上均值）**且**该比值超过同引擎二次通过的噪声底；
- 杀：比值落在噪声底内 ⇒ 归档，回 `第4轮结论` 的四选项。

**一条必须补的对照**：`--control-only`（两个**相同**的 baseline 引擎）给出跨引擎噪声底。
