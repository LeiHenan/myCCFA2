### σ = 0.0000 的诚实说明（不许当成"效应无穷大"）

`temperature=0` + 引擎固定随机种子 + 完全相同的 prompt 集 ⇒ 该配置**完全确定性**：
4 次对照与 3 次处理**逐位相同**。因此：

- **σ = 0 是测量设置的性质，不是"效应无穷大"**；C3 应读作"**效应远大于本设置下的可分辨下限（0）**"，
  而不是"效应是噪声的无穷倍"。
- **正面证据是另外两条**：① 效应 **+4.84 token** 远大于 S4 估计的同进程噪声（0.013 token，≈**360×**）；
  ② 两臂**逐请求区间完全不重叠**（[2.29, 8.00] vs [1.23, 3.05]），且存在**单调剂量-反应**（1.8360 → 3.7576 → 6.6787）。
- **适用范围限制**：σ = 0 只在**该确定性配置**下成立；换 temperature > 0、换采样或换 prompt 集，σ 必须重测。

## 判定

**决策级 Go（条件性）**，条件必须与结论一起报：

1. **语料语义是一等自变量**：`output-as-corpus`（4127 token）⇒ `recovery = 86.2%`；
   **prompt 原文**（131103 token）⇒ **负收益（−16.5%）**。**失败模式是"语料不对"，不是"机制不成立"**。
2. **配额必须显式打开**：`sam_budget = 0`（默认）时上述一切**都不发生**，且 HTTP 装载路径**不报错**。
3. **未测区间（不得外推）**：并发 > 1、其他上下文长度、其他模型/drafter、**真正的跨进程/跨副本状态恢复**
   （本实验的"预置"是**在同一台机器上重新生成**语料，**不是**从持久化状态恢复 —— 后者属下一阶段）。

## R 阶段（续，2026-09-13）：语料恢复的成本与等价性 —— **通过**

**背景**：母阶段的"预置语料"是**在同一台机器上重新生成**的（25.04 s GPU）。语料本身是**文本**而非引擎状态，
所以持久化的真实对手是**重新生成那一遍**。本阶段按**独立预登记** `notes/prereg/sglang-draft-corpus-r.md`
（采数前冻结，commit `3c590b4`）执行 6 臂实验，**≈0.15 GPU·h**。

| 臂（每臂 = 全新 serve 进程） | 首通 accept | 说明 |
|---|---|---|
| `R_gen`（无语料，用于生成语料） | 1.836007 | cost_gen = **25.058 s**（32 请求 GPU 忙时之和） |
| `R_cold`（冷启动对照） | 1.836007 | 与母实验**逐位一致** ⇒ 前提复现 |
| `R_regen`（重新生成语料） | 6.678743 | 与母实验 D_treat **逐位一致** |
| `R_restore_docs`（**落盘 documents 恢复**） | **6.678743** | cost_restore = **0.0539 s** |
| `R_restore_combo`（prompt 原文 + 续写，135231 tok） | **6.946652** | cost_restore = **0.4067 s** |
| `R_restore_xproc`（**另一全新进程**恢复同一文件） | **6.678743** | cost_restore = **0.0625 s** |

**判据结果**：

| 判据 | 阈值 | 实测 | 结果 |
|---|---|---|---|
| **R1 恢复 < 15% 生成成本** | `cost_restore < 0.15 × cost_gen` | **1.62%**（0.4067 / 25.058，取最差一次） | ✅ |
| **R2 恢复 vs 生成 等价** | 相对差 < 1% | **0.000%**（三臂逐位相同） | ✅ |
| **R3 合并语料 ≥ 仅续写 −1%** | — | **+4.0%**（6.9467 vs 6.6787） | ✅ |
| **跨进程可移植** | 相对差 < 1% | **0.000%** | ✅ |

**⇒ R 阶段判定：**恢复路径成立** —— 更便宜（**1.62%** 的生成成本）、**效果逐位等价**、且**跨进程可移植**。
**顺带修正母阶段的一处未测**：`prompt 原文 + 续写`（135231 tok）比仅续写**更好（+4.0%）** ⇒
母实验 T1-b 的"prompt 语料有害（−16.5%）"**只在没有同分布打底时成立**；这正是累积后 SAM 的真实状态
（`ngram_worker.py:420-425` 把 `origin_input_ids` 与 `output_ids` 拼接后 `batch_put`，同一份内容也被喂给 SAM）。
**恢复后达到稳态的**93.0%**（6.9467 / 7.7696，母阶段 `recovery` 为 86.2%）。

**同时确认一条硬约束（源码）**：`NgramCorpus` 的**全部 14 个方法**里**没有任何导出/序列化接口**
（`srt/speculative/cpp_ngram/ngram_corpus.py:15-153`：`batch_put`/`synchronize`/`remaining_token_budget`/
`load_external_corpus_named`/`commit_corpus_external_load`/`remove_external_corpus`/`list_external_corpora`/
`reset`/`batch_get`/`erase_match_state`/`leaf_paths_from_mask`/`debug_result`/`_get_state_id`/`__init__`），
全仓唯一使用 `MultiprocessingSerializer` 的是 `eagle_worker_v2.py`（EAGLE **权重复制**，与语料无关）。
⇒ **"会话中学到的 trie"在结构上导不出来**；能跨副本共享的只有**外部语料文本**这一半。

**未测（诚实登记）**：本轮"跨副本"是**同机第二个进程**，**未测**跨机/网络传输、并发 >1、
真实流量形态下的整机收益（即"新副本从 0 学" vs "从 warm 副本继承"在完整工作负载上的总时间对比）。
