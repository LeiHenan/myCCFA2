# S7 归因与机制（Attribution） — 草案语料生命周期：跨会话/跨副本的冷启动罚金

**候选**：`sglang-draft-corpus` ｜ **成本上限**：≤0.5 天（多数可复用 S6 已采的数据）
**目标**：把效应拆成可命名的因子，并排除显存/排队/顺序/冷启动的替代解释。

## 效应分解

用 S4 的恒等式 `Δln(吞吐) = Δln(接受长度) − Δln(每步代价)`，全部**对着实测**代入：

| 因子 | 实测 | 占比 / 贡献 |
|---|---|---|
| **Δln(接受长度)** | 1.8360 → 6.6787 = **3.6376×** ⇒ **+129.2%** | **主导因子** |
| **Δln(每步代价)** | 每 128 token 的解码步数：`spec_verify_ct` 由 ≈70 降到 ≈19.2（= 128 / 6.6787）；单请求 wall 0.7807 → 0.3192 s | 步数降 **3.64×**，与接受长度**同步** ⇒ **每步代价基本不变**（±10% 内） |
| **端到端 wall（冷窗口内）** | 24.98 s → 10.22 s | **2.45×**（= 接受长度比的 67%，因为 prefill 与固定开销不随语料变化） |
| **剩余差距（瓶颈转移）** | 恢复后单请求 wall **0.3192 s** vs 同进程稳态 **0.2715 s** | 尚差 **17.6%** ⇒ **恢复不是 100%**，`recovery = 86.2%` 的余量就在这 |
| **全链路（生成语料 1 遍 + 之后每会话首通都恢复）** | **35.20 s → 8.69 s = 4.05×** | 诚实账：**生成语料那一遍占 25.04 s，是全链路最大单项** ⇒ 下一阶段（持久化）的收益点正是**省掉这一遍** |

**可命名因子的三分法**（回答"增益从哪来"）：

1. **语料存在性**（从无到有）：1.8360 → 6.6787 ⇒ **主因子**。
2. **语料语义**（同样的存在性、不同内容）：prompt 原文使 accept **降到 1.5337（−16.5%）**，
   模型续写使其**升到 6.6787（+263.8%）** ⇒ **符号由语义决定**。
3. **配额大小**（同样好的语料）：budget 0 → 3 → 7 给出 1.8360 → 3.7576 → 6.6787，
   边际收益 **+0.640/单位 → +1.210/单位**（**超线性**） ⇒ 配额不是线性旋钮。

## 替代解释与排除证据

**逐条排除**（排除证据一律用**逐请求字段/计数器**或源码，**不用跑完归零的 gauge**）：

| # | 替代解释 | 排除证据 | 结论 |
|---|---|---|---|
| A1 | **前缀缓存 / radix cache 造成的假象** | 全臂 `--disable-radix-cache`，且 **704 行逐请求 `cached_tokens` 全为 0** | **排除** |
| A2 | **显存挤占 / preemption** | 全部运行**串行**（同时 1 个在飞请求）、`--max-running-requests 32`、`--mem-fraction-static 0.7`；每臂之间显存回到 **0 MiB**；无 OOM / retraction 记录 | **排除** |
| A3 | **排队 / 并发污染** | 同一张卡**同一时间只跑一个 serve**；每臂独立进程，启动/结束时间在日志与 console 里 | **排除** |
| A4 | **顺序效应（prompt 顺序或缓存残留）** | 所有臂使用**同一 32 条 prompt、同一顺序**；每臂**全新进程**；语料装载发生在**第一个请求之前** | **排除** |
| A5 | **进程冷启动（JIT / warmup）而非语料** | ① 冒烟 rep0 的**前 8 条 1.713 vs 后 8 条 1.712**（全程平坦）；② **4 个独立对照进程全部 1.8360**；③ D_gen（budget=7、无语料）同样 1.8360 | **排除**（本候选最关键的一次排除） |
| A6 | **收益只是"语料越大越好"** | T1-b：**131103 token 的 prompt 语料**（是 output 语料的 **31.8 倍**）却给出**负收益** ⇒ 规模不是决定因素，**语义才是** | **排除** |
| A7 | **预算参数根本没生效（于是"一切都是噪声"）** | budget = 0 / 3 / 7 给出**三个可分辨读数**（1.8360 / 3.7576 / 6.6787），且 budget=0 时装载前后**逐位相同** | **排除**（并反向确认 budget 的作用通道） |
| A8 | **输出被 EOS 提前截断（长度不等导致不可比）** | `ignore_eos=true`，且全部 704 行 `completion_tokens == 128.0000`（min = max = 128） | **排除** |
| A9 | **prompt 难度差异** | 臂间使用**同一批 prompt**，难度在臂间抵消；逐请求区间完全不重叠（[2.29, 8.00] vs [1.23, 3.05]） | **排除** |
| A10 | **跨机器 / 跨版本差异** | 全部实验在**同一台机器、同一次会话、同一引擎版本（SGLang 0.5.19）、同一模型（Qwen3-4B）**内完成 | **不适用**（本轮未跨机器，**未取证**） |
| A11 | **仪器算错** | `verdict.py` 含 `--selftest`（合成数据验证 control/treat/steady 统计、recovery、C0–C4、越界检测）；`probe.py`、`analyze.py`、`corpus_client.py`、`build_corpus.py` 亦各有 `--selftest` | **排除** |

## 机制（可辩护的因果链）

**因果链（每一环都有实测或源码支撑）**：

```
请求到达（全新进程、trie 空）
  → NGRAM 的 drafter 无候选可提（accept_len = 1.8360；verify_ct ≈ 70 / 128 token）
  → 【会话内累积】解码过程中 trie 被填充（引擎自带）
  → 第 2 遍起 accept_len ≈ 6.97～7.78（verify_ct ≈ 16 步 / 128 token）
  ─────── 以上是 H1：冷启动罚金 = accept_len 上 76.4% 的落差 ───────
  干预：在第一个请求之前装载「模型自身续写」的语料
  → 外置 SAM 在 `sam_budget` 个 draft 槽内提供**同分布**候选
    （`ngram.cpp:173` = num_sams>0 ? min(external_sam_budget, total_draft_token_num) : 0）
  → 首通 accept_len 立刻到 6.6787（recovery = 86.2%）
  → 匹配深度被 `max_trie_depth = 18` 掐住（`ngram_worker.py:257-299` 的注释与切片）
    ⇒ 恢复永远差最后 13.8%
```

**两条结构性发现（比性能数字更有迁移价值）**：

1. **配额是必需条件，且其默认值是静默关闭**：
   `ngram.cpp:173` 取 `min(external_sam_budget, total_draft_token_num)`；
   而 `speculative_hook.py:867-880` 的三条校验**只在设了 `--…-corpus-path` 时触发** ⇒
   **HTTP 装载路径可以"装载成功但完全不生效"，且无任何警告**（9 次装载全部 `success:true`，其中 6 次实际无效）。
   **这条同时解释了本工作区上一轮的观测**（decision #94 记录"预置语料看不出效果"）——
   不是预置无效，而是**当时也没有打开配额**（当时甚至没意识到有这个参数的存在）。**已就地标注**。

2. **语料语义决定收益的符号（不只是大小）**：
   同为"外置语料 + budget=7"，**prompt 原文 −16.5%** vs **模型续写 +263.8%**。
   机制解释（与上游 design 一致）：SAM 的匹配是**后缀 → 续写**的检索，
   只有被检索序列**落在目标模型自己的续写分布里**时，检索候选才与目标模型下一步一致；
   **prompt 原文的续写属于"别人的续写"**，在 BFS(recency) 下会给出**冲突候选**，
   占掉 `sam_budget` 个槽而**不被接受** ⇒ 负收益。
   **可检验推论（未测）**：换**另一个模型**生成的续写做语料，收益应显著低于同模型续写。

## 上界复核

S4 登记的 oracle 上界是 **Δln(接受长度) = +144.4%**（1.8365 → 7.7827，即"从第 1 个请求起就有饱和语料"）。
**实测有没有超过上界？没有，且方向一致**：

| 量 | S4 上界 | S6 实测（干预首通） | 是否越界 |
|---|---|---|---|
| 接受长度 | 7.7827（饱和值） | **6.6787** | ❌ 未越界（达到上界的 **85.8%**） |
| 相对吞吐（冷窗口） | ≈ **2.87×**（25.22 → 8.79 s 外推） | **2.45×** | ❌ 未越界（达到上界的 **85.4%**） |

**⇒ 上界算对了**（不存在"实测超过上界 ⇒ 上界算错"的情况）。
**上界的解释力**：干预**能接近但到不了**饱和值，差的 13.8% 与两个候选机制一致 ——
① SAM 匹配被 `max_trie_depth = 18` 掐住；② trie 仍需自积累。
本轮**未做**能区分这两者的实验，故**只作为候选解释登记**，**不作机制主张**。
