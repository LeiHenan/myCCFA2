# S0 立项准备（Intake） — 草案语料生命周期：跨会话/跨副本的冷启动罚金

**候选**：`sglang-draft-corpus` ｜ **成本上限**：0 GPU·h
**目标**：把『想做什么』换成『在什么约束下做什么』；约束不量化就不许往下走。

## 目标与决策人

**决策人**：用户（本人）。Agent 只做取证、预登记、判定与归档；**Go/Kill 由闸门数字触发，不由 Agent 态度触发**。

**本轮目标（按用户 2026-09-13 的三项授权）**：

| 项 | 用户裁定 | 对选题的直接约束 |
|---|---|---|
| 解半径 | **授权中半径**：改动可落在**引擎源码内**，但要求 **≤1 人周**、补丁**可回滚**（备份 + `revert` + `status`）、**单轮可验** | 调度器/内核级的**大手术被排除**；上轮 `prefix-reuse-lag` 的"3–4 周按组独立 computed 长度"**不在本轮半径内**（除非能砍到 ≤1 人周） |
| GPU 预算 | **上限提到 ≤8 GPU·h**（决策级单项仍 ≤1 GPU·h、T1/T2 合计 ≤3 GPU·h） | 超出 8 GPU·h 必须**先停下问用户** |
| 课题类型 | **只接受优化类**：必须是"干预前 vs 干预后"的对照数字，效应 > 3× 同格重复噪声；**测量/刻画类只能作为副产品**，不得作为本轮的收口形态 | 上轮已全过 S0–S8 的 `engine-metric-conformance`（测量类）**本轮不得直接拿来收口** |
| 痛点来源 | 用户**暂不提供**"自己环境里的疼"，要求先按**已有资产/已知线索**推进，遇岔路再问 | S1 必须从"本工作区已实测的数字"+"引擎源码/issue 的可复现事实"取证，**不得**引用未核实的外部二手数字当 L2 |

**本轮明确不换机、不重装、不删资产**（用户 §7 固定）。服务器只有在机器真的不可用时才按 `docs/MACHINE_REQUIREMENTS.md` 换机。

## 已知不可做

**半径与体裁（用户裁定的硬边界）**

1. **不做**需要 >1 人周的引擎改造（含调度器级"按组独立 computed 长度"）—— 超出中半径授权。
2. **不做**以测量/刻画为**收口形态**的课题（上轮 `engine-metric-conformance` 不得直接收口）。
3. **不主张**"引擎默认就会产生的增益"作为创新点（decision #95 教训：会话内累积是自带行为）；创新必须落在**引擎不覆盖的维度**（跨会话 / 跨副本 / 跨重启 / 跨租户）。
4. **不碰**已被 2026 年占位者占满的靶子：LLM 服务引擎内部机制（RFC #55697 等）、集群/多租户 KV（Lyapunov/SAGA）、RL rollout 交界、agent 会话调度、客户端评测方法学（2605.24217）。

**环境与资产（避免重蹈覆辙）**

5. **不删 `/root/miniconda3`**（删了整个 vLLM 环境废掉）；**不把两个引擎装进同一个 venv**。
6. **不在服务器上 `git pull`**；同步只用 `git archive --format=tar HEAD | ssh ... 'rm -rf /root/myCCFA && mkdir -p /root/myCCFA && tar -x -C /root/myCCFA'`；**结果不放 `/root/myCCFA`**。
7. **不用** `pkill -f "<字面量>"`（会杀掉自己的 SSH 会话）⇒ 一律写不自匹配形式 `pkill -f "vllm[.]entrypoints"`。
8. **不用** `--dataset-name random` 做任何涉及接受率的结论（实测接受长度 2.12 vs 真实文本 2.93，decision #76）。
9. **不用**引擎侧"跑完再抓"的 gauge 做判定（跑完归零）；**只用 `*_total` 计数器，且必须做差**。
10. **不在无预登记的情况下采数**；**不绕过** `pipeline/check.py`；**不手改骨架文本**。

**外部依赖**

11. **不重装**已就绪资产（重装一次 >1 小时）；**不换机**（机器可用）。
12. **不依赖**未取证的二手数字作为量级（L0 不入 S1 存活清单）；**不把**"已定位配方"当成"已跑通"（`corpus_tokens.jsonl` 与 `sam-budget` 的四个约束只到"读源码 + 冒烟报错"级别，尚未有一次成功启动）。

**用户裁定：只接受优化类 ⇒ 明确拒绝"纯测量/理论"作为最终交付。**

| 触发条件 | 降级形态 | 约束 |

| S4 oracle 上界 <8% 或 S6 T2 <8% | 把已采数据整理为**该候选的现象记录**（含机制边界与排除链），入库 + 推 GitHub | **不作为本轮成功交付**；只作为"为何被否"的证据 |
| 10 轮内全部候选被否 | 按目标 §1B：交付"为何全部被否 + 下一轮测绘结论"（每条含现象数字/复现命令、机制到源码行、被否的确切原因、证据路径、复活条件） | 用户已允许此形态作为**次优成功** |

**不接受**的降级：把 `engine-metric-conformance`（测量类）重新包装成"理论贡献"来充当优化类交付。
