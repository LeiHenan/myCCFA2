 [Bug] [DFlash2] Greedy output diverges from target-only Qwen3.8-27B when thinking is enabled #38009 
 Copy link 
 Description
 forlayo 
 opened on Sep 4, 2026 
 Issue body actions 
 Checklist
 I searched related issues but found no solution.
 The bug persists in the latest version.
 Issues without environment info and a minimal reproducible demo are hard to resolve and may receive no feedback.
 If this is not a bug report but a general question, please start a discussion at https://github.com/sgl-project/sglang/discussions . Otherwise, it will be closed.
 Please use English. Otherwise, it will be closed.
 Describe the bug
 Summary
 Using SGLang's dedicated Qwen3.8/DFlash2 development image, greedy decoding
with DFlash2 does not produce the same token sequence as the target-only model
when Qwen3.8 thinking is enabled. The first divergence is deterministic at
completion token 30 for the reproduction below.
 The target-only baseline is deterministic across two identical requests, and
the DFlash2 result is exactly equal to the target-only result with thinking
disabled. This makes the issue appear specific to the DFlash/hybrid
state/thinking path rather than prompt formatting, sampling, or general model
loading.
 Expected behavior
 For greedy decoding ( temperature=0 ), DFlash2 speculative decoding should
produce exactly the same generated token sequence as target-only decoding for
the same model, prompt, chat-template settings, and seed.
 Observed behavior
 With thinking enabled, the sequences diverge at generated token index 30:

 }

 For the control, replace chat_template_kwargs with:

The first 30 tokens match in the thinking run; the next token differs exactly
as shown above. With thinking disabled, all 64 returned tokens match.

model's reasoning/thinking path is active? If a different DFlash setting,
draft checkpoint revision, attention backend, or Mamba/GDN cache configuration
is required for greedy equivalence, please point to the supported configuration.
