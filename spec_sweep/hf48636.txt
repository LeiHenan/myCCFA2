 [Feature Request] Approximate Speculative Decoding (ASD): training-free, budget-bounded acceptance for greedy assisted decoding #48636 
 Copy link 
 Description
 Kissmetothemoon 
 opened on Sep 9, 2026 
 Issue body actions 
 Feature request
 Is your feature request related to a problem? Please describe. 
 Greedy assisted decoding in Transformers uses strict argmax verification: the entire draft
suffix is discarded at the first position where the draft token differs from the target
argmax. This is lossless, but it rejects near-optimal draft tokens whose logit gap to the
argmax is negligible, capping the practical speedup of speculative decoding for greedy users.
 PR #45979 ( assistant_ensemble_weight ) added a lossy verification option for the
sampling path by mixing the target and draft distributions. Greedy decoding, however, still
lacks a deterministic, explicitly-bounded relaxation mechanism.
 Describe the solution you'd like 
 Add Approximate Speculative Decoding (ASD) 鈥?a training-free, verifier-side acceptance
policy for greedy assisted decoding. For a draft token x_i and target logits z_i , define
the local regret r_i = max_v z_i(v) - z_i(x_i) ( r_i = 0 iff x_i is the target argmax).
A draft prefix is accepted only while ALL of the following hold:
 Request-level cumulative regret stays within a budget B ;
 Local regret satisfies r_i / (K - i) <= g , where K is the candidate length
(suffix-value weighting: later draft positions get less slack);
 The number of relaxed mismatches in the current block does not exceed m .
 Verification stops at the first infeasible position and commits the target argmax bonus
token as usual. The policy is fully deterministic (no RNG) and exactly reduces to strict
greedy verification when B = 0 or m = 0 (all r_i must be 0, i.e. strict argmax
prefix matching) 鈥?our gold-standard correctness check.
 Proposed API (three scalar parameters, mirroring the assistant_ensemble_weight style;
naming open to maintainer feedback):
 outputs = model . generate (
 ** inputs ,

 assistant_asd_budget = 2.0 , # float >= 0, request-level cumulative regret budget; None = disabled (lossless) 
 assistant_asd_local_ratio = 0.25 , # float >= 0, per-token regret / suffix-value cap 
 assistant_asd_max_mismatches = 2 , # int >= 0, max relaxed mismatches per block 
)
 How is this different from assistant_ensemble_weight ( #45979 )?

 Implementation scope (~150 lines of library code, no external dependency):
 Three scalar parameters in GenerationConfig + checks in validate() ;
 A small acceptance helper next to _speculative_sampling in
 src/transformers/generation/utils.py , called from the greedy branch (Case 2) of
 GenerationMixin._assisted_decoding() ; a request-level budget accumulator in the decode
loop; a ValueError guard for prompt lookup decoding (no candidate logits) in
 _get_candidate_generator ;
 Unit tests added to the existing tests/generation/test_utils.py and
 tests/generation/test_configuration_utils.py (no new test files), plus a short section
in docs/source/en/assisted_decoding.md .
