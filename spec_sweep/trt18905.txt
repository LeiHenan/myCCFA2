 Description
 Expand model-level coverage for speculative decoding and make the PyTorch model-feature support matrix reflect the exercised decoding mode for each architecture.
 This change:
 consolidates MTP, EAGLE-3, DFlash, and DSpark into a descriptive speculative-decoding matrix column;
 adds GSM8K and acceptance-length coverage for Qwen3 MoE and Llama 4 EAGLE-3 (linear and dynamic), Step 3.7 MTP, GLM-4 MoE MTP, and Kimi K3 DSpark;
 adds acceptance-length regression checks to existing DeepSeek V3.2, DeepSeek V4 Flash, GLM 5.2, Qwen3.5, Qwen3 Next, GPT-OSS, and Gemma 4 speculative-decoding tests; and
 wires the added cases into the relevant B200 and QA test lists.
 Known Acceptance-Length Baseline Limitations
 The acceptance-length measurements added by this PR expose two baselines that are lower than expected and should be treated as known issues pending a healthy rerun:
 Llama 4 Maverick EAGLE-3: With max_draft_len=4 , the measured reference acceptance lengths are 1.0097 for linear and 1.0186 for dynamic decoding. This corresponds to draft-token acceptance on only roughly one in 100 decoding iterations. The current min_al: 1.001 therefore detects little short of a completely dead drafter and does not establish a healthy EAGLE-3 baseline. The cause has not yet been isolated; areas to verify include draft/target checkpoint compatibility, tokenizer/vocabulary alignment, one-model versus two-model integration, and rejection sampling. Until a healthy run is recorded, the Llama 4 EAGLE-3 acceptance-length references and support-matrix entry should be considered provisional. https://nvbugspro.nvidia.com/bug/6743982 
 Qwen3-30B-A3B EAGLE-3: The same run measured 1.35 for linear decoding versus 1.67 for dynamic decoding with max_draft_len=4 . The linear result is lower than expected relative to the dynamic result and other Qwen3 EAGLE-3 configurations. A minimum derived from this potentially degraded result could preserve the degradation instead of catching it, so the run needs a health check and rerun before the value is treated as a stable reference. https://nvbugspro.nvidia.com/bug/6743990
