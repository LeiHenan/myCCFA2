 [Bug] [NPU] Hybrid-GDN MTP speculative decoding is not lossless on Ascend NPU #25587

 Describe the bug
 Bug Description
 When running Qwen3.5 (or any hybrid-GDN model) with MTP speculative decoding on Ascend NPU, the generated output diverges from non-speculative decoding at temperature=0.0 . This violates the lossless guarantee that is fundamental to any correct speculative decoding implementation.
 Observed: 
 With MTP enabled, output tokens begin to diverge from non-spec after ~100 tokens
 The divergence accumulates with generation length
 Expected: 
At temperature=0.0 , MTP speculative decoding output must be bitwise-identical to non-speculative decoding. This is guaranteed on NVIDIA and is the standard correctness criterion for speculative decoding.
 Reproduction
 # Launch with MTP 
ASCEND_RT_VISIBLE_DEVICES=0 python -m sglang.launch_server \
 --attention-backend ascend \
 --model-path /path/to/Qwen3.5-4B \
 --tp-size 1 --disable-radix-cache \
 --host 0.0.0.0 --port 30000 \
 --dtype bfloat16 --mamba-ssm-dtype bfloat16 \
 --speculative-num-steps 3 \
 --speculative-eagle-topk 1 \
 --speculative-num-draft-tokens 4 \
 --speculative-algorithm EAGLE \
 --cuda-graph-max-bs 4
 Compare output at temperature=0.0 between non-spec (no --speculative-* flags) and spec (above). On NVIDIA the two are identical. On NPU they diverge.
 Root Cause
 The issue is in conv state restoration after partial acceptance during MTP verify.
 What the verify forward does
 The target model runs verify forward with all N draft tokens. causal_conv1d_update_v2 updates conv_states with num_accepted_tokens=N , assuming all N tokens are accepted. After verification, only k ≤ N tokens are actually accepted.
 Why conv_state_rollback cannot fix this
 The current code calls conv_state_rollback to right-shift conv_states by (N - k) positions, intending to undo the effect of rejected tokens. This is mathematically incorrect :
 Conv1d with SiLU activation at each step is:
 out[t] = silu( sum_{i=0}^{K-1} weight[i] * x[t-i] )
col_window = [x[t], x[t-1], ..., x[t-K+2]] # updated each step
 After processing all N draft tokens, the K-1 history window has been updated N times with the rejected tokens folded in. A pure position-shift cannot undo these updates because:
 SiLU is non-linear and non-invertible
 The correct K-1 history after accepting k tokens is the window state that existed after step k and before step k+1 — this intermediate state is not preserved anywhere in the current NPU implementation
 Right-shifting only moves existing (already-corrupted) values around; it does not restore what the window would have contained had only k tokens been processed. The result is a conv state that drifts further from ground truth on every verify call.
 The correct approach (NVIDIA reference)
 On NVIDIA, this is solved with per-step snapshots ( sgl-project/sglang#10335 ):
 During verify forward, causal_conv1d_update saves the K-1 window state after consuming each draft token into intermediate_conv_window[batch, step, dim, K-1] 
 After acceptance of k tokens, the snapshot at step = k-1 is scattered back into conv_states via fused_mamba_state_scatter_with_mask 
 This restores exactly the K-1 history after processing k tokens sequentially — bitwise identical to non-spec
 The NPU gap
 causal_conv1d_update_v2 (introduced in PR #445 ) does not implement the snapshot path. The SAVE_INTERMEDIATE logic and intermediate_conv_window parameter exist in the older causal_conv1d_update_npu (v1) but were never ported to v2 during the performance-oriented rewrite. Consequently:
 NPU cannot record per-step conv snapshots during verify
 conv_state_rollback is used as a workaround but introduces conv state drift on every partial acceptance
 This drift accumulates across decoding steps, producing outputs that diverge from non-spec
 This is also the underlying cause of the acceptance length gap reported in #408 (NPU acceptance rate 15–20% lower than H100): a corrupted conv state leads the draft model to generate tokens that are less consistent with what the target model expects, reducing the acceptance rate.
 Proposed Fix
 Two coordinated changes are needed:
 1. Add SAVE_INTERMEDIATE to causal_conv1d_update_v2 
 Add intermediate_conv_window pointer, four stride parameters, and SAVE_INTERMEDIATE: tl.constexpr to _causal_conv1d_update_kernel_npu_tiled . After writing output in the STEP 5 loop body, store col0..col_{K-2} to intermediate_conv_window[mamba_slot, idx_token, dim, win] .
 Note: v2 uses tl.range(seqlen_run) (a runtime loop ), so the K-1 additional stores per iteration do not trigger static unrolling. This avoids the UB overflow that would occur in v1 (which uses tl.static_range(seqlen) , statically unrolling the stores seqlen times). When SAVE_INTERMEDIATE=True , cap BLOCK_N to 256 (from default 512) to keep UB usage within the 192 KB limit with --enable-auto-multi-buffer=True .
 2. Replace conv_state_rollback with snapshot scatter 
 Add a Triton kernel move_intermediate_conv_cache that after verification writes:
 intermediate_conv_window[L, mamba_slot, accept_len-1, :, 0..K-2]
 → conv_states[L, mamba_slot, state_len-K+1 : state_len, :]
 Pass num_accepted_tokens = N_max (the physical buffer size, not the runtime draft count) during verify so the kernel always reads from the fixed offset state_len - K + 1 , which is also where the scatter writes. This keeps reads and writes aligned regardless of batch composition.
