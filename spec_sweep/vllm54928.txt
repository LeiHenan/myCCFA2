 🐛 Describe the bug
 Summary
 Qwen3.8-27B with the Qwen3.8-27B-DFlash2 draft is not greedy-equivalent
to the same BF16 target when Qwen thinking is enabled. This is reproducible
with temperature=0 , so it is a correctness issue rather than a normal
sampling difference.
 The baseline target is deterministic across repeated runs. DFlash2 diverges
at generated token 30. The first 30 generated tokens match exactly.
 Environment
 vLLM: 0.26.1rc1.dev942+g5a4c8d992 , with the DFlash2 implementation from
PR [Spec Decode] DFlash2: local convolution + candidate selector #52816 applied to a nightly image
 Target: Qwen3.8-27B , BF16, TP=4
 Draft: Qwen3.8-27B-DFlash2 , BF16, architecture DFlash2DraftModel 
 Hardware: 4x RTX 3090 (SM86)
 Target KV: BF16; Mamba/SSM cache: FP32
 Prefix caching: tested both enabled and disabled
 Qwen thinking: {"reasoning_effort":"medium","preserve_thinking":true} 
 Reproduction
 Use the same model, prompt and decoding parameters for target-only and
DFlash2. The request is:
 {
 "model" : " qwen3.8-27b " ,
 "messages" : [{ "role" : " user " , "content" : " hazme un tetris de gatos en una pagina web, debe de ser muy impactante y visualmente atractivo con efecto gráficos y sonoros " }],
 "temperature" : 0 ,
 "top_p" : 1 ,
 "top_k" : -1 ,
 "seed" : 20260902 ,
 "max_tokens" : 64 ,
 "logprobs" : true ,
 "top_logprobs" : 5 ,
 "chat_template_kwargs" : { "reasoning_effort" : " medium " , "preserve_thinking" : true }
}
 Expected behavior
 With greedy decoding, speculative decoding should emit the same token sequence
as target-only decoding.
 Actual behavior
 The target-only baseline is repeatable. Every DFlash2 variant below diverges
at completion token 30:

 The enable_thinking:false control matches target-only for all 64 generated
tokens. This makes the problem conditional on the generated reasoning path,
not a generic tokenizer or prompt mismatch.
 Interpretation / suggested trace points
 The failure persists at K=1, with no prefix cache and with graph capture /
torch.compile disabled. It appears in the speculative decode path, likely in
verification or target hybrid GDN/DeltaNet/Mamba state update. Suggested
instrumentation around token 29/30:
 target argmax/logits at every verified position;
 proposed token IDs and accepted/rejected count;
 target KV and recurrent-state write/rollback boundaries.

compose files and a standalone reproduction script on request.
