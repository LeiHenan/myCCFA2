 Description
 This PR does two related things: it removes the two-model speculative decoding path , which had already been made unreachable and was marked for removal, and it clears out the dead code left on the C++ speculative-decoding side . Both are speculative-decoding cleanup, which is why they travel together.
 Part 1 — Removing the two-model path (the breaking part)
 Three separate one-model forcings had already made every two-model mode unreachable:
 Config 
 How it was forced 
 EagleDecodingConfig 
 An after-validator overwrote eagle3_one_model back to True , warning that 2-model "will be removed in a future release" 
 MTPDecodingConfig 
 Same pattern for mtp_eagle_one_model 
 DraftTargetDecodingConfig 
 Backed by _draft_target_one_model: bool = PrivateAttr(True) , never assigned anywhere 
 Because all three modes were unreachable, SpeculativeDecodingMode.has_draft_model() was a constant False — and that predicate is the guard on the entire separate-draft-engine build. So the whole two-model machinery behind it was dead.
 Removed: the EAGLE3 / MTP_EAGLE / DRAFT_TARGET enum members and their predicates ( has_draft_model() , needs_kv_cache_recompute() , the three is_*() ); model_drafter.py in full (905 lines — ModelDrafter , get_draft_model_prompt ); the two-model branches in speculative/utils.py ; the draft-engine construction block and forced overlap-scheduler disable in py_executor_creator.py ; _two_model_spec_dec_decoding_type() in llm_utils.py and both KV-cache-V2 guards it fed; the needs_kv_cache_recompute branch in cuda_graph_runner.py (whose enclosing helper became a pure passthrough and is inlined); the eagle3_two_model telemetry flag; and the MTP_EAGLE register_draft_model entry plus its _arch_index row.
 Also removed as plain dead code: EagleDecodingConfig.greedy_sampling and .posterior_threshold (no reader anywhere — the one --eagle_posterior_threshold grep hit is a CLI-flow test arg for the removed TRT build path, not this pydantic field), and MTPEagleWorker.is_thop , which was written but never read (every is_thop reader is on MTPWorker , a different class).
 Compatibility
 eagle3_one_model and mtp_eagle_one_model are kept as fields , so existing configs that pass True — including the examples and docs in this repo — keep working unchanged. Passing False now raises an explicit ValueError instead of being silently ignored, which is the actual behavior change users will see. quickstart_advanced.py loses its --use_one_model flag accordingly.
 Part 2 — Dead C++ speculative-decoding code
 The root here is the TRT-engine config parsing in gptJsonConfig , which is unreachable end to end: the engine builder is gone from the repo ( tensorrt_llm/builder.py and commands/build.py no longer exist, no trtllm-build entry point), trtllm-bench rejects --backend tensorrt at parse time because ALL_SUPPORTED_BACKENDS = ["pytorch", "_autodeploy"] is passed to click.Choice , and SpeculativeDecodingMode.from_arguments() has no callers. GptJsonConfig itself is kept — it still parses name/version/precision/parallelism and loraManagerTest.cpp uses it; only the speculative-decoding branches are dropped.
 Removing those branches leaves gptJsonConfig as the sole writer of ModelConfig::mSpeculativeDecodingMode and mSpeculativeDecodingModule , pinning the mode to None() — the only constructor hardcodes it, the setters have no remaining callers, and nanobind exposes the field read-only ( def_prop_ro ). That made the dependent branches dead too.

SpeculativeDecodingModule does shrink, but it lives in runtime/ and is not reachable from executor.h (which does not include modelConfig.h ); it was only ever constructed by the TRT-engine parsing path this PR removes, so no object of the old size can be produced by the new library.
 Migration 
 There is no replacement for any of these. toTensor() served the fast-logits path of the TRT-engine flow, which no longer exists; the predicates and accessors described state that is now permanently unset. Callers should delete the call sites. If an external consumer turns out to depend on toTensor() , please say so on this PR — it is the one symbol here worth reconsidering.

 This corrected one claim made earlier in this PR. I had described SpeculativeDecodingModule as merely shrinking from 24 to 16 bytes. In the built library it does not shrink — it disappears from the dynamic symbol table entirely, vtable and RTTI included. The class is still declared in the header, but after this PR removes the gptJsonConfig parsing path nothing constructs it, so the compiler emits no vtable/typeinfo for it and the linker drops it. Practically this makes the layout question moot: the new library cannot produce an object of either size. But it is a larger ABI delta than "one member function", and downstream code that constructs a SpeculativeDecodingModule directly would fail to link.
 No unexpected symbols were removed — nothing outside the speculative-decoding surface changed, which is the property the closure build could not establish on its own.
 Notes for reviewers
 speculativeDecodingModule.h no longer needs cudaUtils.h . Dropping that heavy header exposed two pre-existing include-what-you-use gaps that had been relying on it transitively, both fixed here: modelConfig.h uses TLLM_CHECK_WITH_INFO / TLLM_LOG_DEBUG without including assert.h or logger.h , and runtimeUtils.cpp uses TLLM_CUDA_CHECK / std::ifstream without including cudaUtils.h or <fstream> .
 kernels/CMakeLists.txt uses file(GLOB_RECURSE ... *.cu) , so deleting the kernel file pair needs no CMake change.
 Same-named-but-unrelated symbols deliberately not touched: executor::DecodingMode::isMedusa/isEagle/isExplicitDraftTokens (a different class from runtime::SpeculativeDecodingMode ) and the pure-Python SpeculativeDecodingMode in models/modeling_utils.py .
 The three main kernel families under kernels/speculativeDecoding/ ( dynamicTree , kvCacheUpdate , mtp ) were scanned and are clean — nothing removed from them. Two things there look dead but are not: updateLinearKVCacheDraftTokenLocation is never reached from production code ( kv_cache_manager_v2.py hardcodes use_paged_kv_cache=True ) but test_linear_kvcache_update passes False and checks it against a ground-truth reimplementation; and the three parameters the 2D variant always receives as nullptr are shared with the 1D variant, which passes real pointers.
 In suffixAutomaton/ , only whole-entity dead code was removed. The individually-unused members of SADynamicBuffer / SAOptional / SAFlatHashMap / NamedType are left alone — those files are adapted from Baseten's sa_spec and the members mirror the upstream std::optional / STL contract.
 ModelConfig 's speculative-decoding members and their accessors are now written by nobody and are dead, but are left in place to keep this PR's blast radius bounded; they are a natural follow-up.

 [None][fix] Reject post-construction assignment of the retired one-mo… 
 …
 faa2c96 
 …del flags
The field validators added earlier only run at construction time. Because
`validate_assignment` is off, `config.eagle3_one_model = False` after
construction still succeeded, leaving a value that telemetry reports by value
while the runtime unconditionally takes the one-model path.
`validate_assignment` cannot be turned on here: the model validators on these
classes assign to `self` (9 such assignments in EagleDecodingConfig alone), so
re-validating on every assignment recurses without bound. Guard the two retired
fields in `__setattr__` instead, which is narrow enough to avoid that.
Construction and deserialization are unaffected: pydantic's `validate_python`,
`model_construct` and `model_copy` write `__dict__` directly rather than going
through Python `__setattr__`, so the guard only fires on genuine
post-construction assignment. The one in-tree self-assignment
(`validate_eagle_config` setting the flag to True) is passed through, and no
in-tree caller writes either field after construction.
