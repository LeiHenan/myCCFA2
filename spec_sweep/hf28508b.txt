 I've been trying to verify the correctness of the Speculative Decoding (SD) implementation. To do so, I'm planning to add a test which verifies that the token distributions we get using SD are indeed similar (or very close) to the token distributions when using standard sample based decoding. If I understand correctly, this is what the SD paper guarantees.
 So far, I found that when comparing the token scores of the above methods on a sample input, they are very similar but not identical, perhaps only due to hardware numerics errors.
Since tokens with very low probability do not affect the sampling outcome, I think the test should verify that the top k token scores of both methods are close enough to each other (for some chose k like 5-10). Do you think there's a better way?
 When I benchmark Assisted Generation vs SD, I get very similar latencies, even though SD should theoretically be faster, due to a more relaxed acceptance criteria. In consequence, I think it's important to verify the correctness of the SD implementation e.g. by comparing outputs like above.

I wrote this code to check our assumptions about the distributions:
 import torch 
 from transformers import AutoTokenizer , AutoModelForCausalLM , set_seed 
 def top_k ( a , k ):
 sorted , indices = a . sort ( descending = True )
 return sorted [: k ], indices [: k ]
 def get_dist ( outputs , num_samples = 10 ** 6 , norm_factor = 1e7 ):
 probs = outputs . scores [ 0 ][ 0 ]. softmax ( dim = - 1 )
 print ( "probs:" , top_k ( probs , k = 5 ))
 next_std_token = torch . multinomial ( probs , num_samples = num_samples , replacement = True )
 counts = torch . bincount ( next_std_token , minlength = probs . shape [ 0 ]). float ()
 print ( "counts:" , top_k ( counts , k = 5 ))
 norm_counts = counts . float () / norm_factor 
 print ( "softmaxed_counts:" , top_k ( counts . softmax ( dim = - 1 ), k = 5 )[ 0 ])
 print ( "norm_counts:" , top_k ( norm_counts , k = 5 ))
 softmaxed_norm_counts = top_k ( norm_counts . softmax ( dim = - 1 ), k = 5 )[ 0 ]
 print ( "softmaxed_norm_counts:" , softmaxed_norm_counts )
 return softmaxed_norm_counts 
 checkpoint = "EleutherAI/pythia-1.4b-deduped" 
 tokenizer = AutoTokenizer . from_pretrained ( checkpoint )
 model = AutoModelForCausalLM . from_pretrained ( checkpoint )
 assistant_model = AutoModelForCausalLM . from_pretrained ( "EleutherAI/pythia-160m-deduped" )
 gen_kwargs = dict ( ** tokenizer ( "In other words, we" , return_tensors = "pt" ),
 pad_token_id = tokenizer . eos_token_id ,
 max_new_tokens = 1 ,
 do_sample = True ,
 temperature = 0.1 ,
 return_dict_in_generate = True ,
 output_scores = True )
 print ( "Standard sampling:" )
 set_seed ( 0 )
 std_dist = get_dist ( model . generate ( ** gen_kwargs ))
 print ( " \n Speculative decoding:" )
 set_seed ( 0 )
 sd_dist = get_dist ( model . generate ( ** gen_kwargs , assistant_model = assistant_model ))
 print ( std_dist == sd_dist )
 In short, I get the token probs for some input for both decoding methods, then I sample 1M times from this prob, and get the token counts (I always look at top 5 scores in all the following computations). As you can see below, the counts are very close to each other but not equal of course. If we apply softmax to the counts, they produce an insignificant result of [1., 0., 0., 0., 0.] (tested other inputs too). So I normalize the counts and then apply softmax , and then the output distributions look similar, however, they are still not equal to each other (final output).
 WDYT? Is this the way to go?
