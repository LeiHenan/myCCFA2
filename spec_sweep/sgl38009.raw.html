Describe the bug

Summary

Using SGLang's dedicated Qwen3.8/DFlash2 development image, greedy decoding
with DFlash2 does not produce the same token sequence as the target-only model
when Qwen3.8 thinking is enabled. The first divergence is deterministic at
completion token 30 for the reproduction below.

The target-only baseline is deterministic across two identical requests, and
the DFlash2 result is exactly equal to the target-only result with thinking
disabled. This makes the issue appear specific to the DFlash/hybrid
state/thinking path rather than prompt formatting, sampling, or general model
loading.

Expected behavior

For greedy decoding (temperature=0), DFlash2 speculative decoding should
produce exactly the same generated token sequence as target-only decoding for
the same model, prompt, chat-template settings, and seed.

Observed behavior

With thinking enabled, the sequences diverge at generated token index 30:

Profile Tokens around the first difference
target-only with canvas, particles, cat-themed pieces (cat
DFlash2 with canvas, particles, Web Audio API sounds,

The corresponding reasoning_content continues differently after that point.

Environment

  • Host: native Linux, 4 × NVIDIA RTX 3090 (24 GiB each), tensor parallelism 4.
  • SGLang image: lmsysorg/sglang:dev-cu13-qwen38-27b-dflash2
  • Image digest: sha256:616a3e97f45191af975896cfa644279096cb31bd408a071c2e99ca7209c3cafe
  • SGLang commit from image label: 5f55db35e926d50676f75b812640ea2410b0fe0e
  • SGLang version: 0.0.0.dev1+g5f55db35e
  • Container CUDA: 13.0.3; NCCL reported by SGLang: 2.30.7.
  • Target: local copy of Qwen/Qwen3.8-27B, BF16.
  • Draft: local copy of incoai/Qwen3.8-27B-DFlash2, BF16.
  • Tensor parallel: --tp-size=4.
  • DFlash block size: 8.
  • KV dtype: SGLang default (auto, BF16 in this BF16 run); no KV quantization.

The validation intentionally used a single request, 32k context and a reduced
static memory fraction only to fit the target and draft on 24-GiB cards:

--context-length=32768
--mem-fraction-static=0.75
--max-running-requests=1
--disable-radix-cache
--disable-overlap-schedule
--disable-cuda-graph

Those flags are identical in baseline and DFlash profiles. They remove cache,
scheduling and graph-capture variables; they do not alter sampling or logits.

Server commands

Baseline profile:

python3 -m sglang.launch_server \
  --model-path /root/.cache/huggingface/models/Qwen3.8-27B \
  --served-model-name qwen3.8-27b \
  --tp-size 4 --host 0.0.0.0 --port 30000 \
  --context-length 32768 --mem-fraction-static 0.75 \
  --max-running-requests 1 \
  --reasoning-parser qwen3 --tool-call-parser qwen3_coder \
  --disable-radix-cache --disable-overlap-schedule --disable-cuda-graph

DFlash profile differs only by adding:

--speculative-algorithm DFLASH \
--speculative-draft-model-path /root/.cache/huggingface/models/Qwen3.8-27B-DFlash2 \
--speculative-dflash-block-size 8

Reproduction request

Send this request to each profile (target-only twice, then DFlash once):

{
  "model": "qwen3.8-27b",
  "messages": [{
    "role": "user",
    "content": "hazme un tetris de gatos en una pagina web, debe de ser muy impactante y visualmente atractivo con efecto gráficos y sonoros"
  }],
  "temperature": 0,
  "top_p": 1,
  "top_k": -1,
  "seed": 20260902,
  "max_tokens": 64,
  "logprobs": true,
  "top_logprobs": 5,
  "chat_template_kwargs": {
    "reasoning_effort": "medium",
    "preserve_thinking": true
  }
}

For the control, replace chat_template_kwargs with:

{"enable_thinking": false}

Compare choices[0].logprobs.content[*].token, rather than rendered text.
The first 30 tokens match in the thinking run; the next token differs exactly
as shown above. With thinking disabled, all 64 returned tokens match.

Attached evidence

Attach the six files from
resultados/20260904T105622Z-qwen38-sglang-dflash2-ab/:

  • baseline_thinking_a.json

  • baseline_no_thinking.json

The requests are local/direct to SGLang; LiteLLM was not in the request path.

Question

Is this a known limitation or bug in the Qwen3.8 DFlash2 integration when the
model's reasoning/thinking path is active? If a different DFlash setting,
draft checkpoint revision, attention backend, or Mamba/GDN cache configuration
is required for greedy equivalence, please point to the supported configuration.
