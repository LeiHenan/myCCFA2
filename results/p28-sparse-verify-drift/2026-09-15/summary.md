# p28 —— verify 侧 KV 稀疏：**「丢弃质量」不能预测输出漂移**（运行期证书被证伪）

**日期**：2026-09-15 ｜ **目标**：`goal-e5030ca8` ｜ **成本**：≈0.1 GPU·h（空闲卡 2，纯 HF 前向）
**平台**：HF transformers 4.57.6 + torch 2.11.0+cu128 + Qwen3-4B bf16，**`attn_implementation="eager"`**
（vLLM 在本机不可用——见 `notes/SCHOOLSERVER_ENV_2026-09-15.md` §6）
**仪器**：`probes/p28-sparse-verify-drift/drift_probe.py`

## 1. 被检验的命题

🥈 方向（verification-aware attention）经检索后**唯一存活**的窄缝是：
*"没人把**注意力输出误差界**复合进那条精确漂移公式 —— SPRINTER 定理 3.1：`d_TV(p, p_SPRINTER) = η_FP · d_TV(p,q)`"*，
而 vAttention 明说 *"directly controlling the resulting errors in per-layer outputs or overall model behavior is
**mathematically challenging**"*。**该窄缝的可操作形式**是：能否用**一个运行期可校验的廉价量**（最自然的就是**丢弃的 softmax 质量** `1 − Σ_kept w`）
来预测/上界最终 token 分布的漂移？若能，就能给近似 verifier 做**运行期证书**；若不能，这条路当场死。

## 2. 实验设计

在 `transformers.models.qwen3.modeling_qwen3.eager_attention_forward` 注入两种保留策略（**同一个 n**）：

- **oracle `topn`**：每 query 保留**注意力权重最大的 n 个**位置（丢弃的质量最小）；
- **`randn`**：在**允许的位置**（权重>0）里**随机**保留 n 个（丢弃的质量大得多）。

两者都**重新归一化**后被 `V` 聚合；记录每层的**平均丢弃质量**，并比较**最后一个位置的 next-token 分布**与精确值的 `TV = ½Σ|p−p̃|`。
1041-token 上下文；`n ∈ {1024,512,256,128,64,32,16}`。

**对照（关键）**：`mode=off`（完全不做稀疏、重跑一遍前向）⇒ **TV = 0.000000**。
⇒ 本平台的前向是**逐位确定**的，下面所有非零 TV 都是真实扰动，不是运行间噪声。

## 4. 判定：**证书被证伪**（三条独立证据）

1. **同一 n、同样的"保留位置数"，TV 差 3–31 倍**（n=1024 时 12.6×，n=256 时 31.2×）
   ⇒ **漂移取决于"丢了哪些质量"，而不只是"丢了多少"**。
2. **两个模式下 TV 都非单调**：oracle 在 n=32→16 时丢弃质量 0.152→0.230（升）而 TV 0.1013→0.0887（**降**）；
   randn 在 n=256→128 时丢弃质量 0.410→0.620（升）而 TV 0.806→0.193（**降 76%**）。
   ⇒ **没有任何单调的 `TV = f(丢弃质量)` 可作上界**。
3. **`TV/丢弃质量` 跨 2–3 个数量级**（440× / 1323×）⇒ 用它当廉价上界会**既漏报又误报**。

## 5. 三条副产品（比否定本身更有信息量）

1. **深度放大被量化了**：oracle 在 **n=1024**（每层只丢 **3.4e-5** 的注意力质量、1041 个位置里保留 1024 个）
   就已经让最终分布移动 **TV = 0.0058**（随机保留时 **0.073**）。
   ⇒ **逐层 ~1e-5 量级的质量扰动会在 36 层后放大到 ~1e-2 的分布漂移**。这正是 vAttention 所说"难以控制"的定量形态。
2. **贪心对 oracle 稀疏稳健、对随机稀疏不稳健**：oracle 下 7 个 n **全部** top-1 不变；
   随机保留在 n ≤ 256 时 **top-1 改变**。⇒ 与 VeriCache 的"仅贪心下同一"观察一致，但**只在 oracle 选择下成立**。
3. **"丢弃质量"这个量本身在本设定里可以精确计算**（不需要近似）——所以被证伪的不是"能否观测"，而是**"观测到它是否有用"**。

## 6. 诚实边界

- 我对**所有 query**都做了稀疏（不是只对 verification queries）。这放大了绝对漂移；但被检验的是**函数形式**
  （TV 是否由丢弃质量决定），这个结论**不依赖**稀疏作用在哪些 query 上。
- 只测了 **1 个模型（Qwen3-4B）、1 段 1041-token 上下文、1 个 n 网格**，且每种模式**每个 n 只跑一次**——
  但 `mode=off` 的逐位一致说明**重复不会带来差异**，所以"每格一次"在此平台上是充分的。
- **未测**：verification-only 稀疏（只对最后 k 个 query）；不同上下文长度/领域；非 oracle/非随机的**真实选择器**
  （如 SnapKV/H2O 的打分）。真实选择器落在 oracle 与随机之间，**其位置未被刻画**——若要复活此方向，这是唯一入口。

## 7. 对目标的意义

🥈 方向的"存活窄缝"在**其可操作形式**上被本轮的廉价实验否掉 ⇒ 记录为**杀**。
若要在该方向继续，唯一剩下的入口是 §6 最后一条：**真实打分选择器（而非 oracle/随机两极端）的漂移-质量关系**——
但本轮已证明"质量"不是充分统计量，所以那条路要成立，必须找到**另一个**廉价充分统计量（例如**被丢弃权重的分布形状**），
而目前没有任何证据表明这样的量存在。
