**成本**：≈0.6 GPU·h ｜ **脚本**：`probes/p35-fixed-axis/`（`fixed_axis_probe.py` + `analyze.py`）

## 0. 结论先行

**候选「丢弃质量不是货币，支撑结构才是」——按事前冻结的判据，在修正后的匹配轴上不成立，杀掉。**
这是本目标内我**第二次否证自己的头条数字**（第一次是 p30）。

## 1. 我发现的自身缺陷（这一节比结论更重要）

p28–p33 的匹配量 `dropped_mass` 是**对全部 query 取平均**：

```python
STATE["dropped"].append(float((1.0 - keep_v.sum(-1)).mean()))   # mean over (B, H, Lq)
```

但被测量的输出**只有最后一个 query 的 logits**。因果掩码下三种结构在**早期 query** 上行为不对称：

| 结构 | 早期 query（allowed 位置 < n）的行为 | 该 query 记的 dropped |
|---|---|---|
| `window` | 窗口 = 行的最后 n 个**索引**，与 allowed **交集为空** ⇒ `keep_v.sum()=0` | **1.0（高估）** |
| `topn` | top-k 取到权重为 0 的已掩码位置 ⇒ `keep_v.sum()=1` | **0（低估）** |
| `randn` | `.topk` 在 `masked_fill(-1)` 上取，补到 -1.0 项、权重 0 | **0（低估）** |

**实测缺陷幅度**（同一 `drop_last` 下，全局均值相对末-query 质量的倍数；`analyze.py` §A）：

| 结构 | synth | natural | random |
|---|---|---|---|
| `topn` | 0.59× | 0.63× | 0.58× |
| **`randn`** | **0.23×** | **0.23×** | **0.24×** |
| **`window`** | **1.16×** | **1.27×** | **1.19×** |

⇒ **按全局均值匹配时，window 的"真实"质量低于目标、randn 的"真实"质量高于目标
⇒ 三种结构从未在相同真实质量下比较过。** 而 window 被低估的那一侧恰好是"漂移更小"的方向
⇒ **p33 的 18–23× 与"random 100% 翻转 vs window 7%"是这一缺陷的产物。**
（同样地，p33 里"synth 上下文不敏感"也是轴缺陷的产物——修正后 synth 在 mass 0.60 处的 TV 比是 12194×，
但**两者翻转率都是 0**，所以那只是软指标差异，不构成决策层证据。）

## 2. 修正轴（末 query 丢弃质量）上的重测

L=512，30 上下文（synth/natural/random 各 10）× 3 结构 × 4 目标质量，二分 13 次，合格格 **226/360 = 62.8%**。

| 冻结判据 | 实测 | 裁决 |
|---|---|---|
| 合并 mass 0.40 的 `randn/window` TV 比（CI 下界须 >3×） | **4.3×，CI [0.9, 10.3]（含 1）** | **未过 ⇒ 杀** |
| natural mass 0.40 | 5.6× **[1.3**, 22.5] | **未过**（下界 1.3） |
| natural mass 0.60 | 3.3× **[1.9**, 15.4] | **未过**（下界 1.9） |
| **oracle(topn) vs random**（p28 原始主张的核心） | **0.8–2.7×**（mass 0.10–0.60，CI 普遍含 1） | **低于 3× ⇒ 该区分消失** |
| 翻转率 CI 是否可分（natural mass 0.40） | randn 4/10=0.40 [0.17,0.69] vs window 1/5=0.20 [0.04,0.62] | **重叠 ⇒ 不能主张** |

|---|---|---|---|

| random mass 0.60 | 12.4× | [10.3, 17.8] | 单上下文；window 只 7 格合格 |
| synth mass 0.60 | 12194× | [4886, 24916] | **两结构翻转率都是 0** ⇒ 仅软指标差异 |

## 3. 一个确有价值、但**已知**的附带事实

**近因窗口无法丢弃"中等"注意力质量。** 合格格分布显示 `window` 只在 mass **0.60** 上凑够 10/30 格，
在 0.1/0.2/0.4 上几乎全部失配（random: 2/1/3 格）：
因为注意力沉洞（attention sink）集中在**最前面几个位置**，
窗口要么保留它们（丢弃 ≈0），要么把它们移出窗口（丢弃立刻 ≈0.6）——中间没有可调档位。
⇒ 这是 **StreamingLLM（2309.17453，"4 个初始 token 足够"）** 已经建立的同一机制，**不构成新贡献**。

## 4. 复活条件（写清楚，避免下一轮重新发现）

**本候选不再复活**，除非同时满足：
1. 匹配轴是**决定被测输出的那个 query** 的质量（或整套 query 的 logits 都被测），而不是全局均值；
2. 在**该轴**上，oracle-vs-random 或 window-vs-random 的 TV 比 **CI 下界 >3×**（3× = 2604.13206 的稠密方向天花板）；
3. **翻转率的 Wilson CI 不重叠**，且结构排序在 **≥2 类上下文**上一致（本轮 random 上下文上排序反向 ⇒ 已违反）。
4. 必须在**真实部署的稀疏/驱逐实现**上复现，而不是 monkey-patch 的 softmax 重归一化。

## 5. 本轮的净产出（负面为主，但有条真正的正面解锁）

1. **p35 杀死候选**，并留下一个可复用的**方法学规则**（见 §1 表）：
   > **当扰动按 query 位置不均匀时，"全 query 平均"的扰动量不是匹配轴**；必须按**决定被测输出的那个位置**匹配。
   这条规则对所有"稀疏注意力 / KV 驱逐"的对照实验普遍适用，且我此前三轮都违反了它。
2. **新机解锁**：`vLLM 0.29.0` 在 **sm120 / RTX 6000D / driver 595** 上通过正确性闸门
   （同配置两次逐 token 相同；3 prompt 中 2 个与 HF 前 128 token 逐位全同）。
   ⇒ **三张地图里 69–96% 因引擎不可用而无法验证的格子，现在可测。**
   这是本轮唯一真正的能力增量，也是下一轮的起点。
3. p28 → p31 → p33 → p35 这一串**四次自我更正**（n 匹配 → 质量匹配 → 上下文取样 → 匹配轴）
   本身是一条可复用的教训：**承重数字被复测四次才站不住，说明"最近邻已占位"这类结论也必须按同样标准复测。**
