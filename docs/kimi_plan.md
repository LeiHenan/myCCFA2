## 0. 评估口径

| 维度 | 问什么 |
|---|---|
| **创新性** | 确切机制是否已被发表/ship；剩余增量是科学问题还是工程配置 |
| **可行性** | 硬件门槛、到第一个可信数字的时间、基线是否需自建 |
| **赛道拥挤度** | 2025H2–2026 最新 arXiv/会议论文对该格子的覆盖（本轮实测检索，非凭记忆） |

## 1. 本轮文献扫描带来的关键变化（先读）

以下 5 条直接影响排序，全部经 arXiv 原页核实：

1. **#2（多租户保留准入）降档**。plan.md 判定"server 端机制未被占"已不成立：**Continuum**（arXiv 2511.02230，引擎内 TTL + cost-benefit 模型）、**SAGA**（2605.00528，workflow-aware TTL）、**PrefixShield**（2608.01657，vLLM 内多租户 prefix 准入责任记账）三篇 2025-11～2026-08 先后落地。剩余缝隙收窄为"空闲 gap 预测 × **保留定价/计费**耦合进调度器"——这是经济学问题，MLSys 主会契合度存疑。
2. **#12（MoE EP 不均衡）降档**。2026 年该方向密集出新：UBEP（A2A 延迟 −52.4%）、Gimbal、NanoCP，尤其 **DA-MoE**（2607.23099，NVIDIA）已量化 tile padding 开销且**合入 FlashInfer**——直接威胁"padding-aware all-to-all"半边。"证据最硬"不变，但窗口在关闭。
3. **#4（hybrid 前缀×投机）措辞修正但不改结论**。两侧各自已有论文（Sparse Prefix Caching 2605.05219、DASC 2608.30386、Hypic 2607.01299、ReplaySSM、Nemotron-3-Ultra 技术报告），"全库零论文"要改口为"**交互问题零论文**"；且 vLLM issue #53912（2026-08）证实 prefix cache + MTP 在 hybrid GDN 上**仍产出损坏输出**——这个"生产环境 buggy"状态反而是最好的论文动机。
4. **#18（ragged K / 生成前准入）进一步降档**。新查到 **D-cut**（2607.14647）已做跨请求验证预算重分配（触及 ragged 半边），且 vLLM RFC #48202 正把 per-request proposal_lengths 变成一等接口——算法层和接口层同时被挤。
5. **#1（投机 KV 分级）维持但论据增强**。新确认 **VeriCache**（2605.17613）在 limitation 里把"由早期 accept/reject 驱动的自适应策略"**自己列为开放问题**——既是空白的第三方证词，也是最危险的占位候选人。`2606.29223` 仍是必须关闭的藏身处。

另：plan.md 引用的 **AngelSpec、LibraSpec 无法在任何来源核实**；"SpecTool" 疑似引用有误（2411.13547 是 2024 年工具调用 benchmark）。引用清单需清洗。

## 3. 第一梯队详评（排名 1–4）

### 🥇 #6 drafter 内部深度/宽度自适应 —— 主线候选 A

- **创新性 ★★★★**：本轮检索再次确认空缺——AdaEDL/SpecDec++/Pacer/SVIP/LTD/TALON 全部只调**草稿长度或树拓扑**；DSpark（2607.05147）的消融扫了 drafter 层数 1–5 并证明 2 层可超 5 层，但只做**离线静态选择**。**运行时对独立 drafter 做层数/宽度弹性缩放，零论文。**
- **为什么是真科学问题而不是工程配置**：Graft（2605.20104 §4.4）明确记载他们**因 CUDA graph 静态形状与切换成本而放弃动态深度**——这恰恰是这个方向的论文钩子：别人绕着走的硬约束就是你的贡献点（多形状 graph 池 / 子网络切换的摊销策略）。
- **实测锚点硬**：DFlash DT=4 在 ~185k 上下文下 16.0 tok/s vs 关投机 71 tok/s（**4.4× 损失**），drafter 全上下文重扫占 ~182 ms FA。长上下文场景下 drafter 成本模型错了，这是可复现、可归因、可修复的完整故事。
- **可行性**：1–2 卡，2 周到第一个数字。与 self-speculation 的结构性区别已核验（机制不可迁移，无混淆风险）。
- **风险**：自适应收益可能集中在超长上下文区间，需在 (bs, ctx) 平面上画出收益等高线，避免"只在角落赢"。
- **MLSys 契合度：高**。机制清晰、基线现成（固定深度 drafter）、故事完整（现象→归因→机制→收益）。

### 🥈 #4 hybrid Mamba/GDN 前缀保留 × 投机 —— 主线候选 B

- **创新性 ★★★★**：措辞修正为"**交互问题零论文**"：prefix cache 侧（DASC、Hypic、Sparse Prefix Caching）与投机侧（SGLang MambaRadixCache、ReplaySSM、Nemotron-3-Ultra）各自有进展，但**树验证下多分支 SSM 状态快照的内存放大、接受率依赖的检查点淘汰、快照与 RadixCache 协同**无人研究。
- **最好的动机是现成的**：vLLM #53912（2026-08）——prefix caching + MTP 在 hybrid GDN 上**至今产出损坏输出**；SGLang `unified_tree_core.py:402` 对 MAMBA 类**显式禁用**投机。"最高代价的模型类上机制被禁用/有 bug"是 MLSys 审稿人无法拒绝的开场。
- **赛道时机**：Qwen3-Next / Nemotron-H / Falcon-H1 这一波 hybrid 模型正在上量，系统侧论文窗口刚开，**6 个月后大概率被填**。
- **可行性 ★★★★**：dual RTX 5090 即可跑三臂消融，1–2 卡 2 周。
- **风险**：⚠️ 引用纪律——"~20%" 不得引用（#43559 实测 −0.67%/−2%/−4.8%）；vLLM 侧 RFC #50438 被维护者接管、11 位 code owner 待审，工程落地节奏不可控，论文须定位为机制研究而非 PR。
- **MLSys 契合度：高**。模型类新、问题真实、机制空缺、硬件便宜。

### 🥉 #3 约束解码 dynamic × complex × concurrent —— 快速判定，赢则发

- **创新性 ★★★★**：三交集确认仍空，但**邻域 2026 年突然涌入 4+ 篇**（XGrammar-2 动态语法、PSC 复杂语法×batch 256、Trie Automata batch 256 下 29×、gproj 动态语法）——每篇各占两维，三交集被填只是时间问题。**这是四个头部方案里时间压力最大的。**
- **实测落差是现成的**：同引擎 JSON +5.3% → C++ +50.7% → Bython +802.9%。XGrammar-2 的 Earley 缓存在复杂语法 × 大 batch 下的 CPU 瓶颈、PSC 预处理成本（0.5–1 分钟 + 3–6 GiB/schema）在动态语法下不可摊销——两个冲突的交叉就是论文。
- **可行性 ★★★★★**：1 周、单卡、不改代码，先出扫描数据。Go 判据：class-4 @batch≥32 ≤0.85× 无约束。
- **风险**：若扫描结果显示瓶颈可用工程手段（缓存/预编译）直接抹平，则退化为 measurement paper——需在第一周就判断"瓶颈是否结构性"。
- **MLSys 契合度：高**（XGrammar 是 MLSys 2025，场地已被验证接受此类题）。

### 第 4 名 #1 投机 KV 分级 state —— 1 天 E1 判定后定生死

- **创新性 ★★★**：本轮新确认的 VeriCache limitation（"accept/reject 驱动的自适应策略是开放问题"）是空白的第三方证词，但也意味着**想到这个格子的人已经存在**。
- **结构性天花板仍在**：SpecMemo 的"累积验证要求高精度"论证 + "被拒 token 的 KV 本就丢弃"+ 未提交 KV 占比从未被测过——三个论证都指向**量级可能很小**。
- **但它有全组合里独一无二的性质**：**E1 只需 1 天、不用建任何东西**，且产出的是有效的 V2 型（自测）证据。无论生死都划算。
- **必须先关闭 `2606.29223`**（《Depth Exploration for LLM Decoding》，摘要提及 commit position 与 exploration lattice——最可能的藏身处）。
