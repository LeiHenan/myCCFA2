**⇒ 4 个里 3 个不进入抽象阶段。** 与案例研究 #1 的 0/4 相比，本轮至少有 1 个存活——**但死因分布不同**：#1 是 4 个全死于同一约束（单卡/无生产轨迹），本轮死于**占位 1、效应量 1、自身缺陷 1**，**不是同一个分母问题**。故 #1 §6.4 的"换分母"建议在此**不适用**。

### 2.1 为什么 γ 必须并入而不是单独立项

γ 的效应量（2–4%）**低于方法论 §3 闸 3 的门槛**（"足以改变他人的判断"）。而且 v9 已定位到更上游的机制：
块粒度 `528→544` 与 `MambaManager` 忽略 `drop_eagle_block`。γ 极可能是**同一机制的吞吐侧表现**。
⇒ 单独立项会把一个机制的两种表现拆成两篇，且弱的那篇撑不起来。

## 3. 占位核查（§5：三通道、限时，只给两种结论）

### 3.1 候选 α：**框架未被占**

检索（引用图谱 + 精确短语）**没有**找到把"接受率"与"正确性"**解耦**的工作。最接近的三条都在讲别的事：

- [vLLM #56101](https://github.com/vllm-project/vllm/issues/56101)：`mean_acceptance_length` 在 EOS 落在被接受的草稿前缀内时**多数 token** —— 这是接受率的**计数错误**，不是"接受率对正确性失明"；
- [vLLM #48970](https://app.semanticdiff.com/gh/vllm-project/vllm/pull/48970/overview)：为 `#43559` 加 **e2e hybrid-Mamba prefix-cache 损坏回归测试** —— 它占的是**bug 的回归测试**，不是"代理量失效"；
- [RetryTrigger](https://ieeexplore.ieee.org/document/11479682/references)：用"关采样"建立确定性无故障基线 —— 与我 §2 的 U 类相关，但不涉及接受率。

**⇒ 框架未被占。** 但按 §5.5，这只说明"我没搜到"，**具体主张仍须实验判定**（§6）。

### 3.2 候选 β：**框架已被占**

"LLM 推理不确定 / 贪心不保证确定"已被多篇占位：

- [Defeating Nondeterminism in LLM Inference](https://simonwillison.net/2025/Sep/11/defeating-nondeterminism/)（Thinking Machines Lab, 2025-09）
- [Deterministic Inference across Tensor Parallel Sizes](https://icml.cc/virtual/2026/poster/66224)（ICML 2026）
- [Understanding and Mitigating Numerical Sources of Nondeterminism in LLM Inference](https://slideslive.com/39055149/understanding-and-mitigating-numerical-sources-of-nondeterminism-in-llm-inference?locale=cs)
- [From Accuracy to Auditability: A Survey of Determinism in Financial AI Systems](https://arxiv-org.ezproxy.obspm.fr/html/2605.23955v3#3)（含"T=0 不保证确定性"）

**⇒ 框架已被占。** 但**注意 §5.5 的反向警告**：框架被占 **不能**据以否定具体主张。
"同实例冷/暖基线是 `gen` 的函数，因此任何分歧率闸门不声明 `gen` 就不可比"这一**具体**陈述，
检索无法判定，**须由实验判定**。⇒ 降级为 α 的一个子条款，不单独立项。

## 4. 抽象（§4：收敛成带基线的陈述）

散点是 M1–M10 + A3。按 §4.1「成组异常背后的不变量才是」，不变量是：

> **在 LLM 推理引擎的正确性测试里，三个被当作"便宜的替代量"的指标——接受率、跨配置分歧率、prompt 计数——同时偏高（乐观）地估计了测试的功效，且偏高方向一致。**

但 §4.3 要求"抽象后的陈述必须能推出一个可检验的设计含义"，且 §2 的教训（案例 #1 §6.2）要求**原料与目标同轴**。
上句横跨"质量代理 / 基线口径 / 样本量"三个轴，**违反同轴要求**。⇒ 收敛为一条**同轴**陈述：

> **陈述 S（α 的可检验形式）**
> 投机解码的**接受率**与**输出正确性**在**状态损坏类**缺陷下解耦。已实测的配置点：
> `Qwen3.5-4B + MTP(K=2) + APC`，PC off `0.8533` vs on `0.8512`（相对 −0.25%），
> 同臂贪心输出分歧 `243/320 = 75.9%`（95% CI [71.0, 80.3]），配对 McNemar `179 vs 22, p=9.0e-32`。
> **设计含义**：任何以接受率为唯一质量信号的 spec-decode 评测/部署，对这类缺陷的检出力 ≈ 0；
> 正确性闸门必须是**同实例冷/暖的输出一致率**，且**必须同时声明 `gen`**（因为该基线是 `gen` 的函数，见 M4）。

**S 自带三个参照系**（§4.2）：同实例 nospec 基线（`8.4% @gen=64`、`26.9% @gen=256`）、
跨配置基线（`17.8–20.5%`，四臂同量级）、以及 A3 自身的配对检验。**⇒ 可判断量级，不是描述。**

## 5. 先证伪（§6：最便宜的杀死实验，判据先写死）

### 5.1 第 0 步（**零 GPU**，必须先做）：溯源审计

**我在 §6 之前的自查发现了一个我自己的 §7 违规**：

> `0.8533 / 0.8512` 这个数字，**只出现在三份散文中**
> （`README.md:77`、`prereg.md:363`、`Phase0_R0_MTP复现_2026-09-15.md:30,229`），
> **在任何已入库的数据文件里都不存在**。三重核查：
> ① 仓库里仅有的数据文件是 `analysis_phase0_r0{a,b,c}.json` 与 `manifest_phase0-r0.json`，
> 逐文件扫描**没有任何一个含 `accept` / `acc_` 字段**；
> ② 唯一的结果表生成器 `probes/c1r_paper_tables.py` 里**连 `accept` 这个词都不出现**，
> 即它**在结构上无法产出接受率那一行**；
> ③ 原始 run JSON（真正带引擎计数器的那批）**未入库**，只在 `/root/autodl-tmp/` 上。
> ⇒ 它**没有分母、没有 n、没有来源 JSON**，且**生成器也不支持它**——是一个**孤儿数字**。

按 §7.1「任何将写入结论的数字，都必须能追溯到采集方式、口径与环境条件」，这个数字**当前不合格**。
它又恰好是候选 α 的**一半证据**。⇒ **在花任何 GPU 之前，必须先把它接回原始 run JSON**，
并回答：分母是 `draft_tokens` 还是 `drafts`？n 是多少？两臂是否**同一批 prompt**？

**杀死判据（先写死）**：
- 若溯源发现两臂**不是同一批 prompt**，或分母口径在两臂间不一致 ⇒ **α 的这条证据作废**，退回重测；
- 若溯源通过，则进入 5.2。

### 5.2 第 1 步（≤1 GPU·h）：跨引擎检验

**判据（先写死）**：
- **α 成立**：在**≥2 个引擎**上，同一状态损坏缺陷能同时满足「接受率变化 `<1%`」且「输出分歧 `>20%`」；
- **α 降级**：在任一引擎上接受率**同步下降 `>10%`** ⇒ α 是 vLLM 特有观察，**不得**写成普遍性质（§7.3）；
- **α 死亡**：若"接受率不变 + 分歧高"在任何引擎上都**不可复现**，或该组合只在我这一个配置点上出现（§9.3）。

**预算上限 1 GPU·h**。超限即说明问题未收敛（§6.2），归档。

## 9. 对方法论的 3 条修订建议（全部来自本现场）

### 9.1 §2「四类原料」应把**"代理量失明"**单列，它是独立的一类

案例 #1 的 §7.2 把"代理量"列为**隐性口径问题**的一种。本现场表明它值得单列：
A3 里接受率**不是**"口径写错了"，而是**它本身与目标量解耦**——口径再规范也测不到。
⇒ **加一条**：*当一个量被长期当作另一量的代理时，必须显式测一次"两者在已知缺陷上的相关系数"；
若相关≈0，则该代理不是口径问题，是**失明**。*

### 9.2 §4.2「自带参照系」要补一句：**参照系本身可能是自变量的函数**

M4：同实例 nospec 基线从 `8.4%`（gen=64）漂到 `26.9%`（gen=256）。
⇒ **加一条**：*参照系必须先做一次"它对哪些自变量敏感"的扫描；未扫描前，不得把它当常数写进闸门。*

### 9.3 §7.3「标注配置点」应升级为**可执行的阻断**

我这次违反的正是 §7.3（把"我没测"写成"不可测"），而它**没有任何机制能拦住我**——
因为我核的是自己的记忆，不是 `config.json`。
⇒ **加一条**：*凡结论中含"某能力不存在/不可测"的，必须附一条可复现的**否定性取证命令**及其输出；
没有这条取证的，该结论不得进入报告。*
