## 2. A 级候选详述

### A1. 约束解码：dynamic × complex × concurrent

**增量**：**动态（逐请求）且复杂（C++/Python 级）且并发（batch ≥32）**的语法——**这个交集在五篇 2026 工作里是空的**。

**在先工作为何没覆盖**：
- **PSC**（arXiv `2608.03065`，ISSTA 2026）：在 batch 1→256 上解决复杂 PL 语法，mask 快 700×——但价格是 **"half to one minute per schema"** 预处理 + 每 schema **3 GiB（Llama 3 / Qwen2.5）到 6 GiB（Gemma 3）**。**这笔账对逐请求动态语法不可支付**，而那正是 XGrammar 2 的动机场景。
- **CFGzip**（`2605.29986`）：只支持离线，自述 *"negates the advantages in dynamic contexts requiring small, single-use CFGs"*。
- **Gram2Token**（ICML 2026）：只支持确定性语法。
- **XGrammar 2**（`2601.04426`，**MLSys 2025**）：唯一的动态引擎，但**从未离开过简单 JSON**。

**实测差距**（CFGzip Table 3，**同一个引擎**）：

| 语法类 | XGrammar2 vs 无约束 | 差距 |
|---|---|---|
| JSON（Llama-3B） | 3.60 / 3.42 | **+5.3%** |
| C++（Llama-3B） | 2.14 / 1.42 | **+50.7%** |
| **Bython（Llama-3B）** | 12.55 / 1.39 | **+802.9%** |
| Bython（Qwen-4B） | — | **+733.3%** |
| Bython（GPT-20B） | — | **+631.1%** |

**决定性实验**（vLLM/SGLang，**不改代码**）：
batch **1 / 8 / 32 / 128 / 256** × 四个语法类 **{BFCL JSON, 200 行 schema, C++ 子集, 50-schema 动态并集}** × spec-decode **开/关**。
**Go 判据**：**class-4 在 batch ≥32 时吞吐 ≤0.85× 无约束 ⇒ 进入**；否则杀。
**成本**：**1 周**。

> ⚠️ **场地轴更正**：复审已证 "目标系统会议 0 篇" 是**假阴性**——**XGrammar 就是 MLSys 2025**（`proceedings.mlsys.org/paper_files/paper/2025`，Dong/Ruan/Cai/Xu/Zhao/Lai/Chen）。已有 MLSys 先例说明**场地契合度更好，不是更差**。

### A2. hybrid Mamba/GDN 下的前缀保留 × 投机（**全库零论文**）

**这是本合集里唯一"零论文 + 机制在最高代价的模型类上被显式禁用"的格子。**

**机制在两个引擎里的真实状态**：

**(a) 一般机制已在 SGLang ship**（所以"lookahead-aware hashing"本身不是增量）：SGLang ship 的是**bigram radix key**——`radix_cache.py:59-60`（`is_bigram=True: token_ids holds raw tokens (N+1 for N bigrams)`）、键迭代 `(t[i], t[i+1])`、由 `kv_cache_builder.py:305 is_eagle=spec_algorithm.is_eagle()` 启用，**即"键承诺到下一个 token"**。SGLang 还把被拒草稿 KV 挡在 radix 树外（`kv_committed_len` 只按被接受的 token 前进）。

**(b) 但那条已 ship 的路径对 hybrid Mamba 模型是显式关闭的**：
```python
unified_tree_core.py:402
self.is_eagle = params.is_eagle and ComponentType.MAMBA not in components
```
**而那恰恰是边界丢弃代价最高的模型类**（一个对齐单元 ≈ 1k token）。

**(c) vLLM 那侧离落地远得多，且被接管**：`#50438` 是 ISSUE、OPEN，维护者 `ZJY0516` 当天自己 assign 并把 PR `#50897` 连了上去，**原 RFC 作者公开抗议反馈期未满**（*"would have appreciated coordination"*）。`#50897` OPEN、**needs-rebase**、17 commits/50 files、**11 位 code owner 处于 "Awaiting requested review"**，且有未解决的 reviewer 报的 bug（冷启动 prefill 空 hash 列表；两个 MooncakeStoreScheduler 崩溃）。另有**第二个 RFC `#52817` 独立提出同一想法**。

**(d) flag 是真的，但只是 JSON-only 实验开关**：`config/speculative.py:440` 默认 False；由 **PR `#53388`（MERGED 2026-09-01）** 引入；**没有顶层 CLI flag**。交互逻辑**不在** `gpu_model_runner.py`，而在 scheduler + KV coordinator。

**(e) 那个著名数字站不住**：`#43559` 已 CLOSED/COMPLETED。读完 **68 条时间线项**：`shaharmor98` 实测 **−0.67% / −0.67% / −2%**，并写道 *"I couldn't reproduce anything remotely close to the 20% degradation observed here"*；`dribnet` 实测 ≈**−4.8%**；报告者本人从未跟进。
> **不得引用 "~20%"。**
> 现象本身另有佐证：*"MTP + APC on hybrid models is still not production-safe on 0.26"*；TensorRT-LLM `#11533`：*"not production quality for hybrid models due to prefix caching and spec decoding missing"*。
> 另：那条 *"Comment retracted: measurement was invalid"* 在 **PR `#50897`** 上，**不在 `#43559`**——避免交叉归因。

**(f) 全库零论文**：11 次 arXiv API 查询，**五次精确短语查询在全库范围内返回字面零**——`all:"EAGLE" AND all:"prefix cache"` → **0**；`all:"radix attention" AND all:"speculative"` → **0**；等。
**该机制只存在于工程产物中**——这是支持"研究缺口"的论据，也是"已被占"这一击杀前提的反证。

**收窄后的增量（三条）**：**(i) hybrid full-attention + Mamba/GDN 类；(ii) 复用-vs-重算的保留策略；(iii) MLA。**

### A3. rank-imbalance-aware dispatch + padding-aware all-to-all

> **这已不是一篇投机解码论文。** 投机的那一半被独立证伪，机制本身独立成立。

**投机部分：失败。**
- 消息数轴**独立确认死亡**：batch 级 rank 并集在 **γ=0 时就已经饱和（127.9 / 127）**，比值 **1.00×**。原筛出的"1.16×"是算术，其"<1%"并不从它自己的数字推出（`0.20 × 0.16` 被标为"dispatch+combine 的 3%"，**量纲错**）。
- 扇出那一列**等于一个已发表的闭式**：`2607.05876v2` §3.4，`r = n(1−(1−1/n)^k)`，*"expected number of distinct expert ranks touched by a token's top-k selection"*。**零新颖性。**
- 成本模型类别也已存在：**TerraceMoE `2608.27874`**（per-peer 消息大小 + per-token 扇出 + dedup 配额，Hockney 形式）。
- ⚠️ **"投机改变路由"这一前提无任何来源支持**——Cascade 的 "3.5× unique expert activations" 是在 *"Assuming uniform random selection of experts by the router"* 下的解析值，**不得当作 skew 证据引用**。

**幸存机制（独立成立）**：

| 证据 | 数值 |
|---|---|
| 真实 trace 的 per-rank skew（DeepSeek-V3 decode，100k 请求 / 300h / 8×H100） | **5–25×**；Llama-4-Maverick GSM8K **>80×**；Qwen3-235B 2–9× |
| 不均衡 → 延迟（`2604.23150` Fig. 1，IF=128） | **3.28× 归一化解码层延迟** |
| EPLB 状态 | **两个引擎都默认关闭**，且以 **1000 步**为窗口 |
| 厂商与 SGLang 自己的文档 | *"Even with EPLB, some imbalance is inevitable"* |
| 现成 kernel 的行为 | **padding 到最大 rank 的载荷** |
| 已测的转化率 | 消息体积降 **20%**，但 **all-to-all 时间只降 9%** |

**决定性实验（两臂，≤2 周）**：
- **(i) 证伪投机前提** —— instrument `|⋃ dest_ranks|`、消息数、**每 rank 收发 token 数**，扫 γ × batch × EP，用真实路由；**每 rank 占用率与 p99 不随 γ 移动即杀掉耦合**。
- **(ii) 机制独立测试** —— 在人为 skew 下 A/B **padding/rank-balance 感知的 all-to-all** vs 现成实现；**若把 20% 消息体积削减转化不成 >9% 时间，即杀**。
- **臂 (ii) 在 (i) 失败时依然成立**——这是它比其它候选安全的地方。

### A4. drafter 内部深度/宽度自适应

**增量**：**drafter 自身网络的深度/宽度**（在 drafter 内部跳层/早退），**不是它的长度**——per request，在一次批量 draft pass 内。
**经核验的空缺**：AdaEDL、SpecDec++、Pacer、SVIP **全部只调长度/停止，从未调过 drafter 的深度**。

**对应的大格子（实测）**：**DFlash DT=4 在 ~185k 上下文下 16.0 tok/s，而关掉投机是 71 tok/s（4.4× 损失）**（`#54691`）；其中 drafter 的全上下文重扫占 **~182 ms 的 FA**。
已部署的控制是**一个 batch 级数字**，而自适应表**默认关闭**。

**注意与 self-speculation 的区分**：self-speculation（DEL/SpecBound/DSSD/LayerSkip）退出的是**目标模型自己的浅层**；本候选是**独立 drafter 的内部深度**——前者的机制（复用 verifier 的计算前缀）**在结构上无法迁移**到后者。
