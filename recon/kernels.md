# Tree-Attention Kernels & Shared-Prefix-KV Exploitation — Evidence Recon

Date: 2026-09-14. Method: `curl` with browser UA (see FETCH DISCIPLINE). Raw HTML + stripped text in `recon/raw/`.
Every entry below was fetched; the title was read back from the fetched page. Zero entries are from memory or search snippets.

**Headline result up front:** Across FlashInfer, xgrammar, vLLM, SGLang, and every verified paper, **no source claims that tree attention can SKIP attention computation or KV reads for nodes whose KV sets are subsets of other nodes.** The universal mechanism is a **dense (optionally bitpacked) custom/topology-aware mask** plus a **shared prefix KV list**. What *is* exploited is **KV*load* deduplication** for prefixes shared across queries (SpecInfer DFS-reuse, DeFT KV-Guided Grouping, CoDec/FlashForge, PAT, Hydragen, FlashInfer composable formats) — i.e. IO reuse, not arithmetic sparsity. No source uses set-nesting language ("nesting", "subset", "ancestor") to justify skipping KV reads.

**Two premise corrections to the task brief:**
1. **Hydragen is NOT arXiv 2401.14351.** 2401.14351 is *ServerlessLLM: Low-Latency Serverless Inference for Large Language Models*. Hydragen is **arXiv 2402.05099** — verified.
2. **Hydragen is NOT "Tri Dao et al."** The verified author list is Jordan Juravsky, Bradley Brown, Ryan Ehrlich, Daniel Y. Fu, Christopher Ré, Azalia Mirhoseini.

## 6. Does anyone claim tree attention can SKIP attention computation / KV reads for subset nodes?

**No.** Exhaustive search across all verified sources found **zero** claims that a node whose KV set is a subset of another node's can skip attention computation or KV reads. The evidence, in decreasing strength:

1. **DeFT, explicitly, on the state of the art** (VERIFIED, https://arxiv.org/html/2404.00242v4): *"it is not IO-aware for KV cache as it will load KV cache of the entire tree for each query."* — i.e. prior tree attention reads the **whole tree's KV for every query** and relies on the mask. No subset skipping.
2. **SpecInfer, on its own design** (VERIFIED, https://arxiv.org/abs/2305.09781): *"SpecInfer takes both verified tokens (i.e., t2) and all speculated tokens (i.e., t3, t4, ..., t9) as inputs"* and then *"updates the causal mask based on the token tree's topology"* because fusing *"results in attention scores that violate the causal dependency."* — the entire tree KV is read; correctness comes from masking.
3. **Bole, on existing tree-speculation systems** (VERIFIED, https://arxiv.org/abs/2608.01651): *"they traverse recurrent layers branch by branch and materialize a full state for every proposal node."* — per-node materialization, no subset skipping.
4. **FlashInfer's merge math is incompatible with nested sets** (VERIFIED, https://raw.githubusercontent.com/flashinfer-ai/flashinfer/main/docs/tutorials/recursive_attention.rst): `s(I∪J) = log(exp s(I) + exp s(J))` holds only for disjoint `I, J`; nested sets would be double-counted. No dedup path is provided.
5. **SGLang's mask shape proves density** (VERIFIED, https://raw.githubusercontent.com/sgl-project/sglang/main/python/sglang/srt/speculative/eagle_info.py): `mask_numel = (paged_kernel_lens_sum * self.draft_token_num + (self.draft_token_num**2) * batch_size)` — dense prefix × draft mask; a single `kv_indices` per sequence, no per-node KV sets to nest.
6. **vLLM explicitly lists the missing work** (VERIFIED, https://github.com/vllm-project/vllm/pull/17560): `- [ ] Attention metadata & attention mask` and `- [ ] KV cache & CUDA graph (future PRs)`, PR closed unmerged.

**What IS exploited (the real, defensible claim):** *KV-load deduplication over shared prefixes across queries* — SpecInfer's DFS-shared KV cache; DeFT's KV-Guided Grouping ("only loads the prefix KV cache KV_0 once for attention computation", "reducing 73-99% KV cache IO"); CoDec/FlashForge's shared-prefix attention kernel; PAT's "packs queries by shared prefix to reduce repeated memory accesses"; Hydragen's prefix/suffix split; FlashInfer's composable block-sparse formats ("3 queries can share the same KV cache in high-bandwidth shared memory") and cascade/multi-level cascade; SpecSA's "exact merged schedule that deduplicates overlapping selected blocks". Every one of these is **IO reuse / mask compression**, not arithmetic skipping of subset KV sets.
