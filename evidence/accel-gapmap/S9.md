# S9 — Model-side acceleration that needs no training: weight repacking, layer fusion, fusion passes, graph-level rewrites

Rig for relevance: ONE GPU, **RTX PRO 6000 Blackwell 96 GB, sm120** (CC 12.0; `is_device_capability_family(100)`
is FALSE on sm120 — sm120 is NOT sm100), driver 580, 208 CPU cores, single node, no NVLink/IB/cluster.
Software: vLLM 0.29.0, SGLang 0.5.19. Target model: **Qwen3-4B** dense, full attention, NOT MoE, NOT MLA.
Out of scope here (owned by sibling maps): KV-cache management and speculative decoding; cited only as
adjacent context in one clause where unavoidable.

All quotes in this file were re-checked mechanically with
`python3 verify.py quote "<url>" "<quote>"` (whitespace-normalised substring test against the retrieved
page). Verdicts were MATCH or MATCH-FRAGMENTS for every quote below; the four composite ones carry an
explicit `COMPOSITE:` field (five rows carry one). Every arXiv ID cited was read back with `fetch.py arxiv <id>`.

READ THIS BEFORE RE-RUNNING THE CHECKER: `QUOTE:`, `STATED_REASON:`, `ASKING_QUOTE:` and `HARDWARE_QUOTE:`
values are wrapped in the block format's own double quotation marks, exactly as `RESEARCHER_BRIEF.md` and
`S0.md` specify. Feeding the whole field value (including those two boundary characters) to
`verify.py quote` therefore returns **NEAR with `missing_tail: '"'`** for rows whose source text does not
itself begin and end with a double quote — that is the format's own punctuation, not a text mismatch. To
reproduce a MATCH, strip the wrapping quotes from the field value before checking. Rows A9.8, B9.2 and D9.5
