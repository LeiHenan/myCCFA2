## Confirmations (rows I checked and could not falsify)

### The two known-thin claims called out for attack

- **A1.3 — `_is_fa4_supported()` accepts only 90/100/110. CONFIRMED, not falsified.**
  `verify.py quote` on the v0.29.0 raw URL → `MATCH` (ratio 1.0). Corroborated three ways:
  (a) raw GitHub URL, (b) the local mirror `/tmp/vllm-0.29.0/vllm/vllm_flash_attn/flash_attn_interface.py`
  lines 72-86 (identical), (c) `fa_utils.py::get_flash_attn_version` lines 94-130, where the FA4 branch
  is `elif device_capability.major == 10 and is_fa_version_supported(4)` — sm120 (`major == 12`) cannot
  enter it. **I tried to break the "silently degrades to FA2" half and could not; it is stronger than
  the row states.** There is **no environment variable** that turns FA4 on: a whole-tree
  `grep -rn "VLLM_FLASH_ATTN_VERSION"` and `grep -rn "VLLM_ATTENTION_BACKEND"` over `/tmp/vllm-0.29.0`
  return **zero** hits, and the only `*ATTENTION*` key in `vllm/envs.py` is
  `VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION` (the A1.1 note is correct). The one remaining lever,
  `AttentionConfig.flash_attn_version = 4` (`vllm/config/attention.py:41`), does **not** work either:
  `get_flash_attn_version()` ends with `assert is_fa_version_supported(fa_version)` inside a
  `try/except (ImportError, AssertionError): return None`, so on sm120 an explicit `flash_attn_version=4`
  trips the assert, is swallowed, and the function returns `None` (no version pin) after logging an
  error — it does not select FA4. On the *default* path nothing is logged at all, so "silently
  degrades to FA2" is exactly right.

- **A1.2 — sm120 falls into the `else` branch, so `FLASH_ATTN` is tried first. CONFIRMED.**
  `verify.py quote` against the raw URL initially returned `MISMATCH (0.21)` **because of a defect in
  the checker, not the row**: `fetch.py::strip_html` applies `re.sub(r"(?s)<[^>]+>", " ", s)` to raw
  source files, and a stray `<` in the Python source swallows everything up to the next `>`. Against
  the un-stripped raw bytes the quote is a continuous run. Local mirror `vllm/platforms/cuda.py`
  lines 148-163 is byte-identical to the quoted if/else.

- **A1.1 — `VLLM_ATTENTION_BACKEND` is absent at v0.29.0. CONFIRMED** by whole-tree grep over
  `/tmp/vllm-0.29.0` (0 hits) and by the `envs.py` grep above. The remaining claims in that row
  (`AttentionConfig.backend`, `backend_per_kind`, `flash_attn_version: Literal[2,3,4] | None`,
  `use_trtllm_attention`) are all present in `vllm/config/attention.py`.

- **A1.8 — page sizes `[16, 32, 64]` on sm120. CONFIRMED** at source level:
  `get_supported_kernel_block_sizes()` returns `[16, 32, 64]` unless `use_large_pages`, and
  `use_large_pages` requires `current_platform.is_device_capability_family(100)`. The quoted comment
  re-locates verbatim.

## Method notes (reusable)

`verify.py`'s `page-text` corpus is unsafe for two source classes and produced false MISMATCHes here:
(1) `raw.githubusercontent.com/**.py` — `strip_html`'s `<[^>]+>` rule deletes real source between a
stray `<` and a later `>`; (2) `github.com/.../blob/...` — the file body is not contiguous in the
rendered HTML. Re-checking against un-stripped raw bytes resolved both. This is a checker limitation,
not an S1 defect; no S1 row needed a content change because of it.
