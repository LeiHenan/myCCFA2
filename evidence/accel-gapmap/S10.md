# S10 — Measurement methodology for acceleration claims, and the negative / methodological results that undercut them

Target rig this map serves: **ONE RTX PRO 6000 Blackwell (96 GB, sm120), 208 CPU cores, single node, no
NVLink/IB; vLLM 0.29.0, SGLang 0.5.19; Qwen3-4B dense full-attention.** Every item below is about *how a
speedup number is produced*, not about a technique. KV-cache management and speculative decoding are **not
the subject of any row** (two sibling maps own them); where such a paper appears it appears only because the
*measurement practice* it documents is the subject.

Fetching was done **only** with `python3 fetch.py gh|arxiv|get|raw <url>` from this directory (raw HTML cached
in `/tmp/accelsrc/`). No `api.github.com`, no `web_fetch`. Every arXiv ID below was read back with
`fetch.py arxiv <id>` and its `ARXIV_ID_READBACK`/`TITLE` pair is reproduced in the row.
`S3B` on every B/C row is an **independent** status search (GitHub repo issue/PR lists and arXiv search),
run fresh and not derived from this file's own citations.
Source-code quotes are from the rig's own version where possible
(`https://raw.githubusercontent.com/vllm-project/vllm/v0.29.0/...`).
