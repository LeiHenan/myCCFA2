Verifier: V2 (adversarial). Method per `VERIFIER_BRIEF.md`. Every URL was re-fetched with
`python3 fetch.py gh|raw|get|arxiv` (curl -sL --retry 4, browser UA, `/tmp/accelsrc` cache); every
claimed quote was re-located with `python3 verify.py quote "<url>" "<fragment>"` plus two
adversarial variants layered on top of it:

* `vcode.py` — code-aware match: deletes `"`, `#`, `\` and whitespace from **both** page and quote
  before testing containment. This is how a Python *comment or adjacent string literal* is quoted
  word-for-word without being one continuous run. It still fails if any word is added or removed.
* `vraw.py`/`check_raw` — continuous-run match against the **un-stripped** file. `fetch.py`'s
  `strip_html` deletes every span between a `<` and a later `>`, which silently destroys large
  regions of any `.py`/`.md` source file; several "MISMATCH" verdicts produced by the stock checker
  on raw source URLs are artefacts of that, not defects (see Notes).

Authoritative GitHub state was read from the page's embedded payload (`"state"`, `mergedTime`)
rather than `fetch.py`'s `STATE-TOKEN` regex — that regex reported `merged` for **#44405** and
**#41316**, both of which are CLOSED with `mergedTime: null` (the word comes from timeline
cross-references). This is a checker defect worth fixing in `fetch.py`.

## Notes

- **Systematic (not corrected row-by-row):** source-file quotes that join wrapped Python comments or
  adjacent string literals are word-exact but are not one continuous run, so the stock checker
  returns MISMATCH. Affected rows: A5.1 (envs.py comment), A5.2 (topk_topp_sampler comment),
  A5.4 (`# NOTE(nick)` comment), A5.6 (comment/constant), A5.8 (wrapped comment). All were verified
  with the code-aware checker (`MATCH-CODE-NORMALISED`); no word differs. Recommend either the
  composite label or a file-level "source quotes join Python comment lines" convention — S7 already
  has such a convention.
- **Non-standard field names:** A5.11 uses `QUOTE (vLLM config)`/`QUOTE 2…5` and A5.14 uses
  `QUOTE (vLLM)`/`QUOTE 2 (SGLang …)`; because `verify.py` keys on the bare `QUOTE` token, both rows
  are invisible to `checkall` (`NO-QUOTE-FIELD`). Field names should be normalised so automation sees
  them.
- **Scope-note inconsistency:** the header names `/tmp/vllm-0.28.0` as the greppable verification
  tree while the rig (and every cited URL) is v0.29.0; `/tmp/vllm-0.29.0` exists and was used here.
  No claim depends on the 0.28.0 tree, but the note invites a wrong-tree grep.
- **Checker defect (`fetch.py`):** `STATE-TOKEN` is extracted from loose JSON fragments and picks up
  the word `merged` from *cross-referenced* PRs in the timeline. It returned `merged` for #44405 and
  #41316, both CLOSED-unmerged. Use the payload object keyed by `"number": <n>` (`"state"`,
  `"mergedTime"`). A helper (`vstate.py`) was written for this verification pass.
