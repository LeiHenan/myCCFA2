# S11 — ATTEMPTED-AND-ABANDONED mining in vLLM and SGLang (inference acceleration only)

Researcher S11. Scope: attention kernels/backends, compilation & CUDA graphs, weight/activation
quantization, batching & scheduling, sampling/logits/structured-output/tokenizer, CPU/host overhead,
long-context attention (non-KV), serving-layer/API, model-side fusion/repacking, benchmark methodology.

**Excluded by scope** (owned by sibling maps, not a row's subject here): KV-cache management
(paging, prefix caching, eviction, KV quant, offload, disaggregated P/D) and speculative decoding
(drafters, verification, n-gram drafting, acceptance length). Where a dropped candidate was excluded
for one of those reasons it is recorded in NEGATIVE FINDINGS.

**Evidence rules applied.** Every C row carries a verbatim, continuous closure/failure sentence read
from the PR/issue page, and its state token was re-read from the fetched payload
(`"mergedTime":...,"number":N,"relayId":"PR_...","state":"..."`) rather than assumed. Rows whose only
closure text was an automated notice (`github-actions` / `stale[bot]`) were dropped. Rows whose only
"reason" was authored by the automated `vllm-agent` CI-failure auto-reverter are NOT counted as human
evidence and are segregated in subsection **C12** below, excluded from all counts. Every row carries an
**S3B** field: an INDEPENDENT fresh search for current activity on the same topic (the abandoned item's
own URL is never used as evidence of current activity), plus **REASON-MAY-HAVE-EXPIRED** where the
stated reason depends on an engine version, a GPU generation or a library version.

**S3B decision rule (applied uniformly).** For every C row two fresh repo-scoped list searches were issued
— `.../issues?q=<keywords>+is%3Aopen&page=1..2` and `.../issues?q=<keywords>+is%3Amerged&page=1..2`. Hits
whose number is the row's own PR, or the PR that this row reverts, are discarded (an item is never evidence
about its own current activity). `OCCUPIED` / `SOLVED` are claimed only when a surviving hit's title shares
**at least four significant tokens** with the abandoned item's title; every other outcome is reported as
`NO-ACTIVE-WORK-FOUND` with the exact query URLs recorded inline on the row. The rule is deliberately
conservative, so `NO-ACTIVE-WORK-FOUND` means "no clearly-matching current work was found by these
queries", not "no work exists".

**Drop ledger.** Abandoned rows retained: 106 (43 S11 + 28 S11-A + 35 S11-B). Dropped for having NO human
closure/failure sentence: 334+ (297 by S11-A, 37 by S11-B, plus S11's own drops). Dropped as
machine-authored only: 24 auto-revert PRs (segregated in C12) + 7 by S11-B. Dropped as out-of-scope
(KV-cache management / speculative decoding): 174 by S11-A plus S11's own out-of-scope filter.

**Sections.** A = CLOSED (shipped, for contrast). B = OPEN (verbatim asking quote). C = ABANDONED.
C1–C9 are S11's own vLLM rows; C10 are SGLang rows mined by sub-researcher S11-A; C11 are additional
vLLM rows mined by sub-researcher S11-B; C12 is the segregated machine-authored set.

  The label set in vLLM (`/labels`) contains no `wontfix` / `not planned` label; the closes that exist are
  state-reason based and surfaced through `is%3Aunmerged` and `in%3Acomments` searches instead.
- **Explicit human "won't fix / by design" sentences are rare in both repos** — queries tried:
  `https://github.com/vllm-project/vllm/issues?q=is%3Aclosed+in%3Acomments+%22by+design%22`,
  `...%22we+will+not+support%22`, `...%22out+of+scope%22`, `...%22not+a+bug%22`, `...%22won%27t+fix%22`,
  `...%22no+plans+to%22`, `...%22working+as+intended%22`, `...%22unfortunately%22`,
  `...%22we+don%27t+plan%22`, `...%22decline%22`, and the same set for `sgl-project/sglang`.
  The hits are dominated by *closed-as-completed* issues (the report was a real bug and got fixed), not by
  refusals. Refusal-shaped reasons live almost entirely in *revert* PRs, which is why section C is
  weighted towards reverts.
- **`github.com/search?q=...&type=commits` (global commit search) is unreachable from this environment** —
  `python3 fetch.py raw 'https://github.com/search?q=repo%3Avllm-project%2Fvllm+%22Revert%22&type=commits'`
  times out (no bytes within 60 s; the global `/search` endpoint does not render server-side here).
  Revert mining was therefore done through the repo-scoped list search (`?q=Revert+in%3Atitle`), which works.
- **Local git history was not usable for revert mining** — `/tmp/vllm-0.28.0`, `/tmp/vllm_src` and
  `/tmp/sgl_src` are depth-1 clones (`git rev-list --count HEAD` = 1), so no `git log` revert archaeology.
- **Stale-closed items with a human reason: none kept** — the ~20 candidates whose only closure text was a

  in each sub-researcher's NEGATIVE FINDINGS in C10/C11.
