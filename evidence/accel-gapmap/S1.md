# S1 — Attention kernels & backends on Blackwell **sm120** (what is actually available and selected)

**Researcher:** S1 · **Subtopic:** attention kernels & backends, emphasis on what is available/selected on sm120
**Target rig:** 1× RTX PRO 6000 Blackwell 96 GB, sm120 (CC 12.0), driver 580 · vLLM 0.29.0 · SGLang 0.5.19 · Qwen3-4B (dense, full attention)
**Scope note:** KV-cache management and speculative decoding are owned by sibling maps. Attention **backend selection**, **kernel availability**, and **arch gating** are the subject here. Where an item's artifact is a KV-cache feature request, the row answers only the *attention-backend support posture* question and says so.

**Headline for the rig (one paragraph).** On sm120 the only FlashAttention version that resolves is **FA2**. vLLM 0.29.0's FA4 gate accepts compute capability 9.x / 10.x / 11.x and rejects 12.x; FA3 is Hopper-family-only. vLLM 0.29.0's automatic priority list on sm120 puts `FLASH_ATTN` **first** (the SM10.x list puts `FLASHINFER` first). SGLang 0.5.19 puts `flashinfer` first on sm120 because `trtllm_mha` is SM100/SM103-only. `trtllm-gen` attention does not exist for sm120 and NVIDIA states there is no plan for it; sm12x gets the XQA **decode-only** kernel through FlashInfer, and only if the NVIDIA artifactory (cubin download) is reachable.

### A1.12 | CLOSED
QUESTION: Is sm120 architecturally equivalent to sm100 for attention kernels?
WHO: NVIDIA (pengbowang-nv, COLLABORATOR) in TensorRT-LLM #11799; blake-snc in flashinfer #2560; vLLM RFC #43235 author
ARTIFACT: TensorRT-LLM issue #11799; flashinfer PR #2560; vLLM issue #43235
URL: https://github.com/NVIDIA/TensorRT-LLM/issues/11799 ; https://github.com/flashinfer-ai/flashinfer/pull/2560 ; https://github.com/vllm-project/vllm/issues/43235
STATUS: documented
EVIDENCE: READ BODY
QUOTE: "2. **SM120's ISA differs from SM100.** SM120 (consumer Blackwell) does not have `tcgen05` instructions or TMEM — it uses `mma.sync.aligned.block_scale` instead of `tcgen05.mma`. The SM100 FMHA kernel source cannot simply be recompiled for SM120; it requires architectural adaptation for SM120's instruction set."
NOTE: Corroborated independently: flashinfer #2560 ("SM12x lacks the tcgen05 MMA instructions required by the CUTLASS FMHA SM100 kernel") and flashinfer #2555/#2598 ("SM120 uses SM80-era MMA instructions (`mma.sync.aligned.m16n8k16`) with 99 KB shared memory"). vLLM RFC #43235 independently states "On SM120, these units do not exist — the sparse indexer falls back to software paths that are both slow and correctness-problematic."
