### Your current environment

vLLM version: 0.15.1
PyTorch: 2.9.1+cu129
CUDA: 12.9
GPU: NVIDIA B200 (SM100, Blackwell)
OS: Linux (Docker, vllm/vllm-openai:latest)
Python: 3.12


### Model

Qwen/Qwen3-30B-A3B (MoE), quantized to W4A8 (int4 weights + fp8 activations) using llm-compressor `oneshot()` with `scheme="W4A8"` via compressed-tensors format.

### 🐛 Describe the bug

Loading a W4A8 compressed-tensors checkpoint into vLLM on a Blackwell B200 GPU (SM100) fails during model initialization. vLLM cannot find any mixed-precision linear kernel that supports SM100 for the W4A8 scheme.

All six registered kernel implementations reject SM100:

| Kernel | Rejection reason |
|--------|-----------------|
| CutlassW4A8LinearKernel | Requires compute capability of 90 (Hopper) |
| MacheteLinearKernel | Requires compute capability of 90 (Hopper) |
| AllSparkLinearKernel | Does not support device_capability = 100 |
| MarlinLinearKernel | Quant type (int4) not supported |
| ConchLinearKernel | Weight type (int4) not supported |
| ExllamaLinearKernel | Only supports float16 activations |

The same checkpoint works correctly on Hopper (SM90) GPUs. Quantization (export) succeeds on all architectures — only serving fails on SM100.

### How to reproduce

```python
from vllm import LLM

# Assumes a W4A8 compressed-tensors checkpoint at ./w4a8-int4fp8/
llm = LLM(
    model="./w4a8-int4fp8/",
    dtype="bfloat16",
    tensor_parallel_size=1,
    gpu_memory_utilization=0.85,
)
# Raises ValueError: Failed to find a kernel that can implement the WNA16 linear layer.
```

To produce the checkpoint with llm-compressor:

```python
from llmcompressor import oneshot
from llmcompressor.modifiers.quantization import QuantizationModifier

oneshot(
    model="Qwen/Qwen3-30B-A3B",
    recipe=QuantizationModifier(targets="Linear", scheme="W4A8", ignore=["lm_head"]),
    output_dir="./w4a8-int4fp8/",
)
```

```
 CutlassW4A8LinearKernel cannot implement due to: CUTLASS W4A8 requires compute capability of 90 (Hopper)
 MacheteLinearKernel cannot implement due to: Machete requires compute capability of 90 (Hopper)
 AllSparkLinearKernel cannot implement due to: AllSpark currently does not support device_capability = 100.
 MarlinLinearKernel cannot implement due to: Quant type (int4) not supported by Marlin, supported types are: [ScalarType.uint4b8, ScalarType.uint8b128, ScalarType.float8_e4m3fn, ScalarType.float4_e2m1f]
 ConchLinearKernel cannot implement due to: Weight type (int4) not supported by ConchLinearKernel, supported types are: [ScalarType.uint4, ScalarType.uint8, ScalarType.uint4b8, ScalarType.uint8b128]
 ExllamaLinearKernel cannot implement due to: Exllama only supports float16 activations
```

### Expected behavior

W4A8 compressed-tensors checkpoints should load and serve on Blackwell (SM100) GPUs, Blackwell hardware supports both INT4 and FP8 tensor core operations, so W4A8 mixed-precision GEMM should be achievable on SM100 with dedicated kernel implementations. Currently no registered kernel in choose_mp_linear_kernel() covers SM100 for this scheme.

### Relevant context

- Related tracking issue: [RFC: Blackwell Enablement for vLLM (SM100) #18153](https://github.com/vllm-project/vllm/issues/18153)
- Similar SM100 kernel gaps reported for other schemes: [NVFP4 MoE #33416](https://github.com/vllm-project/vllm/issues/33416), [FP8 MoE #32109](https://github.com/vllm-project/vllm/issues/32109)
- The issue is in `vllm/model_executor/layers/quantization/kernels/mixed_precision/__init__.py` — `choose_mp_linear_kernel()` iterates all registered kernels and none accept SM100 for W4A8.
  The existing W4A8 kernels (Cutlass, Machete) use Hopper-specific wgmma PTX
  instructions that don't carry forward to SM100. This isn't a version check
  oversight — SM100 needs its own kernel implementations. W4A16 works on
  Blackwell via Marlin because those kernels use more portable instruction paths.
