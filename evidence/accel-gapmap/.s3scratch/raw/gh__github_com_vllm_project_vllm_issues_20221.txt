## Root cause of the problem
This error occurs when using the Qwen2.5-VL-72B-Instruct-FP8-Dynamic model. vLLM encounters a data type mismatch during the profile_run process during the initialization phase. Specifically:

- Data type mismatch: Your model uses FP8 quantization (compressed_tensors_w8a8_fp8), but the cutlass_scaled_mm operation expects the input tensor data type to be torch::kInt8, and actually receives a FP8 type tensor. 

- GPU architecture support issue: You are using an NVIDIA RTX PRO 6000 Blackwell Workstation Edition GPU, which is a GPU based on the Blackwell architecture (SM 10.0). Although vLLM supports the Blackwell architecture, there may be compatibility issues in some quantization operation paths. 
- Quantization scheme selection problem: The error occurs in the w8a8_scaled_mm_func function, which selects the appropriate quantization implementation based on the hardware capabilities, but in your case may have selected an incompatible implementation path.

## Possible solution
- Solution 1: Use INT8 quantization model (recommended)
As you mentioned, the most direct solution is to use the INT8 quantization version of the model instead of the FP8 version:
```
llm = LLM(
model="./Qwen2.5-VL-72B-Instruct-INT8", # Use INT8 version
trust_remote_code=True,
max_model_len=4096,
)
```
INT8 quantization has better support on all GPU architectures, avoiding FP8-related compatibility issues. compressed_tensors_w8a8_int8.py:1-50

- Solution 2: Disable CUTLASS backend
Try disabling CUTLASS backend and using another quantization implementation:
```

```
- Solution 3: Check and update the environment
Make sure the CUDA version is compatible: Blackwell architecture requires CUDA 12.8+, which your environment already meets. cuda.inc.md:1-50

Update vLLM: Check if there is a newer version of vLLM that fixes the FP8 support issue for the Blackwell architecture:
