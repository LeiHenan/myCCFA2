## Summary

PTX ISA 9.4 (CUDA 13.4.0 Developer Preview) exposes a new `ldmatrix` variant that performs **in-flight sign extension of packed INT4 to INT8 during the shared-memory matrix load**:

```
ldmatrix.sync.aligned.m8n16.{x1,x2,x4}{.shared{::cta}}.s8.s4  r, [p];
```

Source data is densely packed signed 4-bit elements; the hardware expands them to signed 8-bit values in the destination fragment. This can eliminate the register-level INT4→INT8 unpack sequences (`lop3`/`prmt` bit tricks and PRMT LUTs) in our W4A8-INT8 kernels, and potentially the dequant-oriented weight interleaving in repack.

Doc: PTX ISA 9.4, §9.7.16.5.15 (`ldmatrix`), https://docs.nvidia.com/cuda/developer-preview/13.4/parallel-thread-execution/index.html

## Hardware verification (already done)

Verified with `ptxas`/`nvdisasm` from CUDA 13.4.0 preview (`V13.4.46`), no GPU required:

- `ptxas` accepts the instruction for **sm_90a, sm_100a/f, sm_103a, sm_107a/f, sm_110f, sm_120f, sm_121a** (PTX targets per doc: `sm_90a, sm_100f, sm_110f, sm_120f`).
- SASS is a **single LDSM instruction** on every architecture — no unpack sequence is generated. The encoding is bit-identical across all seven targets (opcode `0x783b` = LDSM, modifier `0x9000/0x9100/0x9200` for x1/x2/x4; cf. `LDSM.16.M88` = `0x0000`, `LDSM.U4x16P64TO8.M816` = `0xa800`, `LDSM.U6x16P32TO8.M816` = `0xb000`).
- Notably **Hopper (sm_90a) is supported** — the datapath appears to have existed in silicon since GH100; PTX 9.4 merely exposes it. Existing H100/H200 fleets benefit immediately.
- `nvdisasm` 13.4 does not yet print a mnemonic for this modifier (hex only); expect this to be fixed in the GA release.

## Affected code paths

(vLLM @ `76bf55240`, 2026-07-23)

### 1. Marlin W4A8-INT8 — replaceable (bit-exact)

- `csrc/libtorch_stable/quantization/marlin/dequant.h:494` — `dequant<int32_t, kU4B8>`: unpacks two nibbles per pass with `(q & 0x0F0F0F0F | 0x80808080) - 0x08080808) ^ 0x80808080`, i.e. u4-with-bias-8 → s8.
- `csrc/libtorch_stable/quantization/marlin/marlin_template.h:945` — `frag_b_quant` is loaded from shared memory with plain 128-bit loads over Marlin's dequant-interleaved layout, then dequanted at `marlin_template.h:1163` (`dequant_data`).
- `csrc/libtorch_stable/quantization/marlin/gptq_marlin_repack.cu` — repack currently bakes in the dequant interleave.

**Equivalence:** for `kU4B8`, stored nibble `v ∈ [0,15]` yields output `v − 8`. Storing `s4 = v XOR 0x8` at repack time (free) makes `sign_extend(s4) == v − 8` **bit-exact**. The ALU sequence (≈6 ops per 32-bit word × 2 fragments) disappears, and the B-fragment interleave in repack can be dropped in favor of the canonical 8-bit `ldmatrix` tile layout.

### 2. Machete W4A8-INT8 — replaceable (bit-exact)

- `csrc/libtorch_stable/cutlass_extensions/vllm_numeric_conversion.cuh:213` — `NumericArrayConverter<int8_t, vllm_uint4b8_t>` implements the identical `[-8..7]` mapping via a PRMT LUT (`lut_4bit_to_8bit_convert`, line 158). Used by the Machete mainloop's register-transform stage.
- Replacement means moving the conversion out of the CUTLASS transform pipeline into the smem→rmem copy atom; requires a new copy atom + prepacked-layout adjustment in `machete_prepacked_layout.cuh` rather than a converter swap. Larger change; track separately as phase 2.

### 3. Marlin W4A8-INT8 with runtime zero-point — partially replaceable

- `csrc/libtorch_stable/quantization/marlin/dequant.h:570` — `sub_zp_and_dequant<int32_t, kU4>` (asymmetric AWQ-style zp, see #24722). Pure sign extension can't absorb a runtime zp, but `ldmatrix.s8.s4` + one packed s8 correction add (`zp − 8` per group) still beats the current mask/sub/xor sequence. Lower priority.

### 4. Out of scope

- `cutlass_w4a8/` (W4A8-**FP8**, `MmaType = e4m3`): target type is FP8, not covered by this instruction.
- `moe/moe_wna16_utils.h`, AWQ/GPTQ FP16 paths: dequant target is FP16/BF16.

## Proposed plan

- [ ] **Phase 0 — layout verification**: confirm the `m8n16.s8.s4` output fragment layout matches `mma.m16n8k32.s8` operand-B fragments (the `m8n16`/`m16n16` 8-bit ldmatrix shapes were introduced in PTX 8.6 for exactly this pairing; verify the s4 source packing order within each 8-byte row against our repack output). Only `m8n16` is available for `.s8.s4` (no `.trans`), so B must be stored K-major in smem.
- [ ] **Phase 1 — Marlin symmetric path (`kU4B8`)**:
  - repack: store `v XOR 0x8` nibbles, drop dequant interleave for the `is_a_8bit && !has_zp` configuration;
  - kernel: replace `frag_b_quant` plain loads + `dequant` with `ldmatrix.m8n16.x4.s8.s4`, guarded by `__CUDA_ARCH_FAMILY_SPECIFIC__` / arch macros for {90a, 100f, 110f, 120f} and `CUDA >= 13.4`;
  - keep the existing lop3 path as fallback for sm_80/86/89 and older toolkits.
  - **No on-disk/checkpoint format change**: repack runs at weight-loading time (`process_weights_after_loading` → `ops.gptq_marlin_repack`); both transforms live inside the repack kernel and only affect the in-GPU-memory layout.
  - The in-memory Marlin layout becomes kernel-variant-dependent (ldmatrix layout vs legacy interleave). Repack must take a layout-variant flag driven by the same arch/toolkit predicate as kernel selection; if repacked-weight caching across processes is ever introduced, the layout needs a version tag.
- [ ] **Phase 1.5 — benchmark**: microbench LDSM-expand vs LDS+lop3 (MIO-pipe pressure vs ALU pressure; note Marlin is often ALU-bound in the dequant stage at high occupancy), plus end-to-end gptq W4A8-INT8 throughput on H100/H200, B200, RTX 5090.
- [ ] **Phase 2 — Machete**: smem→rmem copy atom using `ldmatrix.s8.s4`, prepacked layout update.
- [ ] **Phase 3 — zp path**: evaluate `ldmatrix.s8.s4` + packed correction add for `sub_zp_and_dequant`.

## Caveats

- CUDA 13.4 is currently a **Developer Preview**; land behind a build-time gate and revisit at GA. Instruction availability/targets could still shift (precedent: a→f promotions between 8.6 and 8.8).
- `nvdisasm` cannot yet name the instruction; debugging SASS requires reading hex until tooling catches up.
- Ada (sm_89) and Ampere keep the existing path permanently — the instruction is sm_90+ only.

## References

- PTX ISA 9.4 release notes: "Adds support for `.s8.s4` types for `ldmatrix` instruction for `.m8n16` shape" — targets `sm_90a, sm_100f, sm_110f, sm_120f`.
- Existing sub-byte ldmatrix formats (`.b6x16_p32`, `.b4x16_p64`, unsigned, padded) introduced in PTX 8.6 for the f8f6f4 MMA path — the new `.s8.s4` differs in being **densely packed** and **sign-extending**.
- #24722 (Marlin W4A8-INT8 dequant tricks this would supersede on sm_90+).
