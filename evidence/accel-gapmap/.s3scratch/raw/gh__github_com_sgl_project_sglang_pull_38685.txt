TITLE: [Feature] Add flashinfer_b12x NVFP4 backend and tiny_gemm decode path for SM120/SM121 (RTX 5000) by zachma082 · Pull Request #38685 · sgl-project/sglang · GitHub

--- COMMENT 1 ---
Motivation

 SM120/SM121 (Blackwell consumer / RTX PRO, e.g. RTX 5000 48G) has no dedicated NVFP4 GEMM backend, and Qwen3.5 GatedDeltaNet 's tiny decode b/a GEMM ( M<=8, N=48, K=5120 , bf16) runs through the generic in_proj_ba linear, under-utilizing the GPU at small batch.

 Modifications

 A. flashinfer_b12x NVFP4 GEMM backend (SM120/SM121, CUDA 13+) 

 arg_groups/choices.py + arg_groups/fields/exec_.py : register flashinfer_b12x in FP4_GEMM_RUNNER_BACKEND_CHOICES and the --fp4-gemm-backend help.

 layers/quantization/fp4_utils.py : add FLASHINFER_B12X to Fp4GemmRunnerBackend .

 test/.../test_nvfp4_linear_backends.py : add test_flashinfer_b12x (SM120/121 only, k % 32 == 0 shapes); _run_backend gains a shapes arg.

 B. tiny_gemm decode path for Qwen3.5 GatedDeltaNet (default OFF) 

 models/qwen3_5.py : _use_tiny_ba gate on SGLANG_OPT_TINY_BA + CC major == 12 + non-deterministic; _forward_ba_proj dispatches to the upstream tiny_gemm_bf16 kernel for the matched shape, else falls back to in_proj_ba ; _forward_input_proj gains is_decode from _forward .

 Accuracy Tests

 tiny_gemm computes the same bf16 GEMM as in_proj_ba for the matched shape (numerically equivalent); gated OFF by default.

 Follow-up: flashinfer_b12x vs flashinfer_cutlass accuracy comparison.
