## Background ##
In the past, the observer abstraction was mostly useful for computing quantization parameters during QAT, where each forward pass of training generated a new set of qparams which affected gradients for future passes. However, this technique might be overkill for techniques like PTQ. From a research philosophy perspective, QAT is performed with the goal of modifying weights to be "aware" of quantization, while PTQ aims to replicate the original unquantized weights as closely as possible.

As of now, each calibration batch triggers a new set of activation qparams to be calculated. For the QuantizationModifier (RTN), these new qparams are used to perform quantized forward passes which affect subsequent modules. However, this is not true for GPTQ, AWQ, and AutoRound (see [DISABLE_QAC_MODIFIERS](https://github.com/vllm-project/llm-compressor/blob/7461d02b9bf9edc35f3be9effdaa97d6639baf1f/src/llmcompressor/utils/helpers.py#L177)).

Either way, the calculation of qparams at every batch step is very expensive. It would be more performant (and I hypothesize, more accurate) to keep running min/max values, then only calculate qparams once calibration has finished. However, there is a risk that this algorithmic change affects accuracy.

## Requested Changes ##
1. Modify `QuantizationMixin` to NOT calculate qparams on each batch in the hook, and instead calculate qparams once on (sequential) calibration epoch end. Remember to [disable quantization in all cases](https://github.com/vllm-project/llm-compressor/blob/main/src/llmcompressor/pipelines/sequential/pipeline.py#L125), only during calibration (keep enabled during propagation)
2. Modify observer subclasses to add a `calibrate_module` method which uses its running statistics (min/max) to calculate qparams which are used to update module qparams. After the qparams are updated, the running statistics should be deleted off of the observer to reduce memory usage
3. Run regression tests to see the effect of these changes compared to the original implementation. You can run lm_eval regressions with the following commands:
```bash
CADENCE=weekly TEST_DATA_FILE=tests/lmeval/configs/fp8_static_per_tensor.yaml python3 -m pytest tests/lmeval/test_lmeval.py -sx
CADENCE=weekly TEST_DATA_FILE=tests/lmeval/configs/w4a16_awq_sym.yaml python3 -m pytest tests/lmeval/test_lmeval.py -sx
CADENCE=weekly TEST_DATA_FILE=tests/lmeval/configs/w4a4_nvfp4.yaml python3 -m pytest tests/lmeval/test_lmeval.py -sx
```
