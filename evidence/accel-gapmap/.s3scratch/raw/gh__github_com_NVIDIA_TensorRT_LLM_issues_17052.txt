### Reproduction

## Summary

I am trying to serve a Gemma NVFP4 vision-language model on an NVIDIA RTX PRO 5000 Blackwell GPU. The same model can be served and benchmarked successfully with vLLM, but TensorRT-LLM `release:1.3.0rc22` fails during executor warmup before the OpenAI-compatible HTTP server becomes ready.

The main release-image failure is:

```text
RuntimeError: Error in function 'TllmGenFmhaRunner' at
/usr/local/lib/python3.12/dist-packages/flashinfer/data/include/flashinfer/trtllm/fmha/fmhaRunner.cuh:37:
Unsupported architecture
```

I also tried the `devel:1.3.0rc22` image and attempted to build TensorRT-LLM from source for `sm_120`, but could not produce a usable runtime image.
## Model

Local model path:

```text
nvidia/Gemma-4-26B-A4B-NVFP4
```

Model config summary:

```json
{
  "model_type": "gemma4",
  "architectures": ["Gemma4ForConditionalGeneration"],
  "dtype": "bfloat16",
  "quantization_config": {
    "quant_algo": "NVFP4",
    "quant_method": "modelopt",
    "producer": {
      "name": "modelopt",
      "version": "0.43.0rc2.dev91+gc79ebc014"
    },
    "kv_cache_scheme": {
      "dynamic": false,
      "num_bits": 8,
      "type": "float"
    }
  }
}
```

The release image appears to load the NVFP4 weights before failing during warmup. The log repeatedly shows:

```text
[TRT-LLM] [W] [quantize] Inline 'config.json.quantization_config' diverges from 'hf_quant_config.json':
  - group_size: file=16, inline=None
```


### Expected behavior


`trtllm-serve` should start successfully on SM120 and serve the Gemma NVFP4 model, or the documentation should state that this model/GPU/quantization combination is unsupported and provide the recommended image/configuration.
The same model can run through the OpenAI-compatible API with vLLM on the same server. A small vision request benchmark used one inline 1x1 PNG image, `temperature=0`, `max_tokens=64`, 64 measured requests per worker setting, and 4 warmup requests excluded from timing.

Results:

| Framework | w1 QPS | w2 QPS | w4 QPS | w8 QPS | Abnormal outputs |
|---|---:|---:|---:|---:|---:|
| vLLM | 6.37 | 10.77 | 21.73 | 41.51 | 0 |
| TensorRT-LLM | N/A | N/A | N/A | N/A | 0 |

This suggests the model files are usable and the failure is specific to TensorRT-LLM runtime/configuration/support.


### actual behavior

With `release:1.3.0rc22`

The service fails before becoming ready. The default path enters FlashInfer/TRTLLM-gen FMHA and fails with `Unsupported architecture`:

```text
Model init total -- 21.36s
[TRT-LLM] [W] [_torch] KVCacheV2Scheduler only supports MAX_UTILIZATION for now, got GUARANTEED_NO_EVICT, setting to MAX_UTILIZATION
flashinfer.jit: Fetching .../fmha/trtllm-gen/checksums.txt
flashinfer.jit: File downloaded successfully ...
flashinfer.jit: Fetching .../fmha/trtllm-gen/include/flashInferMetaInfo.h
flashinfer.jit: File downloaded successfully ...
[TRT-LLM] [E] [executor] Failed to initialize executor on rank 0:
Error in function 'TllmGenFmhaRunner' at
/usr/local/lib/python3.12/dist-packages/flashinfer/data/include/flashinfer/trtllm/fmha/fmhaRunner.cuh:37:
Unsupported architecture
```

The full traceback ends with:

```text
File "/usr/local/lib/python3.12/dist-packages/flashinfer/prefill.py", line 264, in _paged_run
  op.trtllm_paged_attention_context(
File "python/tvm_ffi/cython/function.pxi", line 923, in tvm_ffi.core.Function.__call__
RuntimeError: Error in function 'TllmGenFmhaRunner' at
/usr/local/lib/python3.12/dist-packages/flashinfer/data/include/flashinfer/trtllm/fmha/fmhaRunner.cuh:37:
Unsupported architecture
```

Then the server exits:

```text
[TRT-LLM] [E] [executor] Executor worker died during initialization.
RuntimeError: Executor worker died during initialization
```

## Workarounds Tried

I tried forcing different attention backends and explicit KV cache limits:

```yaml
max_input_len: 2048
attn_backend: VANILLA
kv_cache_config:
  max_tokens: 32768
```

```yaml
max_input_len: 2048
attn_backend: TRTLLM
kv_cache_config:
  max_tokens: 32768
```

The recorded result was that these avoided the first `TllmGenFmhaRunner` failure, but still entered `flashinfer.py` and failed with a metadata mismatch:

```text
swap_paged_kv_indices_for_layer missing on Vanilla/TrtllmAttentionMetadata
```


### additional notes

I also pulled `nvcr.io/nvidia/tensorrt-llm/devel:1.3.0rc22`, but it is not a drop-in replacement for the release image:

```text
which trtllm-serve -> not found
python3 importlib.util.find_spec("tensorrt_llm") -> None
bash: line 1: trtllm-serve: command not found
```

The `/workspace` directory in the devel image contained README/tutorial/docker example files, but no TensorRT-LLM source checkout.

## Source Build Attempt From Devel Image

I uploaded a TensorRT-LLM source checkout under:

```text
/root/workspace/test_script/build/TensorRT-LLM
```

The README in the checkout identifies the release as `1.3.0rc22`. I attempted to build for:

```text
--cuda_architectures=120-real
```

Important observations:

```text
-- TensorRT LLM version: 1.3.0rc22
-- CUDA compiler: /usr/local/cuda/bin/nvcc
-- The CUDA compiler identification is NVIDIA 13.2.78 with host compiler GNU 13.3.0
-- GPU architectures: 120
-- Excluding SM 80
-- Excluding SM 86
-- Excluding SM 89
-- Excluding SM 90
-- Excluding SM 100
-- Excluding SM 103
-- Excluding SM 100F
```

So CMake did accept SM120 at configure time.

Build attempts:

1. Full `build_wheel.py` with `requirements-dev.txt`: container exited with code 137 during pip dependency installation.
2. Runtime-only requirements: container also exited with code 137 during pip dependency installation.
3. No-requirements build using preinstalled packages plus Conan: reached CMake configure and accepted SM120, but `FetchContent[pybind11]` GitHub clone hung/killed.
4. GitHub mirror/ghproxy: `git ls-remote` worked, but actual `git clone` still exited 137.
5. Minimal URL/tarball build with `BUILD_DEEP_EP=OFF`, `BUILD_DEEP_GEMM=OFF`, `BUILD_FLASH_MLA=OFF`, and pip-installed `nanobind`: nanobind resolved, but CUTLASS tarball download failed:

```text
-- FetchContent[cutlass]: clone start
-- Using src='https://ghproxy.net/https://github.com/NVIDIA/cutlass/archive/v4.4.2.tar.gz'
CMake Error at .../download-cutlass-populate.cmake:163 (message):
  error: downloading 'https://ghproxy.net/https://github.com/NVIDIA/cutlass/archive/v4.4.2.tar.gz' failed
  status_string: "Stream error in the HTTP/2 framing layer"
...
HTTP/2 stream 1 was not closed cleanly: INTERNAL_ERROR (err 2)
...
CMake Error at /usr/local/cmake/share/cmake-4.0/Modules/FetchContent.cmake:1918 (message):
  Build step for cutlass failed: 2
```

No usable TensorRT-LLM image with `trtllm-serve` was produced.
## Questions

1. Is RTX PRO 5000 Blackwell / SM120 officially supported by `nvcr.io/nvidia/tensorrt-llm/release:1.3.0rc22` for Gemma NVFP4?
2. Is `TllmGenFmhaRunner ... Unsupported architecture` expected on SM120 in this image, or is this a missing FlashInfer/TRTLLM-gen FMHA cubin/kernel support issue?
3. What is the recommended attention backend and `trtllm-serve` configuration for Gemma NVFP4 on SM120?
4. Is the `swap_paged_kv_indices_for_layer` metadata mismatch with `VANILLA`/`TRTLLM` attention backends a known issue in `1.3.0rc22`?
5. Which image should be used to build and run TensorRT-LLM for SM120 + Gemma NVFP4? Is there a newer internal/nightly image or documented source build path that includes all required dependencies?
6. Are there any required flags for NVFP4 acceleration on Blackwell that are not automatically enabled by `trtllm-serve`?
