# [Bug] SM120 grouped FP8 DeepGEMM weight preparation skips UE8M0 requantization

## Checklist

- [x] I searched related issues but found no solution for this specific guard.
- [x] Reproduced with the latest SGLang main checked out for this test.
- [x] Environment and a minimal reproduction are provided.
- [x] This is a bug report, written in English.

## Describe the bug

On NVIDIA RTX PRO 5000 72GB (SM120), SGLang enables DeepGEMM and UE8M0 scales when a compatible DeepGEMM build is installed. However, `should_deepgemm_weight_requant_ue8m0` unconditionally returns False for SM120, including grouped MoE weights.

`Fp8MoEMethod.process_weights_after_loading` calls `requant_block_scale_ue8m0_for_deepgemm` for w13/w2, but that helper therefore skips conversion. Passing non-power-of-two FP32 block scales to the grouped FP8 DeepGEMM path then triggers its scale-layout assertion.

This report is based on a **single-GPU weight-preparation + grouped-GEMM reproduction**, not a full-model startup or accuracy run. The motivating workload is GLM-5.3-Flash blockwise FP8 MoE. No checkpoint download is needed for the reproduction.

## Versions

- SGLang main: `ad5af539cd39e9af10ef318d3f8a50f5d6f9c153` (fresh checkout, production source unmodified).
- DeepGEMM nv_dev: `572557e7ae9ad5331b81a1c250f141fba2c57962`, package `2.6.1+local` with SM120 grouped FP8 support.
- GPU: NVIDIA RTX PRO 5000 72GB Blackwell, capability `(12, 0)`.
- PyTorch: `2.13.0+cu130`; CUDA runtime: `13.0`.

## Reproduction

Run in an environment with the above SGLang and DeepGEMM installed:

```bash
SGLANG_ENABLE_JIT_DEEPGEMM=1 python repro.py
# Run the control in a NEW process after the device assertion:
SGLANG_ENABLE_JIT_DEEPGEMM=1 REPRO_MODE=explicit_requant_control python repro.py
```

```python
import os
import torch
import sglang
import deep_gemm as dg
from sglang.srt.layers import deep_gemm_wrapper as wrapper
from sglang.srt.layers.quantization.fp8_utils import (
    requant_block_scale_ue8m0_for_deepgemm,
    requant_weight_ue8m0_inplace,
)

print("SGLang source:", sglang.__file__)
print("DeepGEMM source:", dg.__file__)
torch.manual_seed(123)
w = torch.nn.Parameter(
    torch.randn(2, 256, 256, device="cuda").to(torch.float8_e4m3fn),
    requires_grad=False,
)
ws = torch.nn.Parameter(
    torch.full((2, 2, 2), 0.03, device="cuda", dtype=torch.float32),
    requires_grad=False,
)
print(wrapper.ENABLE_JIT_DEEPGEMM, wrapper.DEEPGEMM_SCALE_UE8M0)
print(requant_block_scale_ue8m0_for_deepgemm(
    w, ws, [128, 128], use_deepgemm_runner=True,
    output_dtype=torch.bfloat16, weight_shape=(256, 256),
))
q = torch.randn(256, 256, device="cuda").to(torch.float8_e4m3fn)
qs = torch.full((256, 2), 0.03125, device="cuda", dtype=torch.float32)
idx = torch.arange(2, device="cuda", dtype=torch.int32).repeat_interleave(128)
out = torch.empty(256, 256, device="cuda", dtype=torch.bfloat16)
if os.environ.get("REPRO_MODE") == "explicit_requant_control":
    requant_weight_ue8m0_inplace(w, ws, [128, 128])
dg.m_grouped_fp8_gemm_nt_contiguous((q, qs), (w, ws), out, idx)
torch.cuda.synchronize()
print("finite:", torch.isfinite(out).all().item())
```

## Actual results

Unmodified upstream weight-preparation path:

```text
FLAGS True True
GUARD False
PREPARE False
Assertion failed: deep_gemm/impls/smxx_layout.cuh:131,
condition: (values[j] & 0x807fffffu) == 0
CUDA_ERROR_LAUNCH_FAILED
```

Separate-process control explicitly calling the existing requantization helper:

```text
FLAGS True True
GUARD False
PREPARE False
MODE explicit_requant_control
PASS finite= True
```

The control establishes successful execution and finite outputs only; it is not an end-to-end numerical accuracy claim.

## Expected behavior / suggested direction

Preserve the SM120 dense Linear guard for CUTLASS/Triton consumers, but allow supported grouped MoE weights to follow the existing UE8M0 requantization path when DeepGEMM is selected. Merely removing the SM120 guard globally would risk converting scales for dense kernels that still expect FP32 scales.

Relevant pinned sources:

- [Capability detection](https://github.com/sgl-project/sglang/blob/ad5af539cd39e9af10ef318d3f8a50f5d6f9c153/python/sglang/srt/layers/deep_gemm_wrapper/configurer.py)
- [Unconditional SM120 guard](https://github.com/sgl-project/sglang/blob/ad5af539cd39e9af10ef318d3f8a50f5d6f9c153/python/sglang/srt/model_loader/utils.py#L265)
- [MoE weight preparation](https://github.com/sgl-project/sglang/blob/ad5af539cd39e9af10ef318d3f8a50f5d6f9c153/python/sglang/srt/layers/quantization/fp8.py#L1809)
