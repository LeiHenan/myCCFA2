### CLOSED-1: SGLang session-reference-aware Unified Radix Cache
- URL: https://github.com/sgl-project/sglang/pull/29173
- Evidence: READ BODY
- Detail: Merged by hzh0425 on 2026-08-02, titled "feat: Session-reference-aware Unified Radix Cache for agentic multi-turn workloads". This is the single most on-topic shipped artifact for "session-level KV management" and "KV cache growth across multi-turn agentic sessions". The stated motivation: "In multi-turn inference workloads such as agentic workflows and RL rollouts, active sessions accumulate reusable KV prefixes across turns. Under memory pressure, the standard radix cache evicts entries using only the configured cache policy, without considering whether a prefix is still referenced by an active session. This may evict an active session's prefix while unrelated, unreferenced KV remains cached, causing unnecessary recomputation in later turns and reducing cache hit rate and throughput." The mechanism: "Applications pass a stable top-level session_id with each request. When a request finishes, SGLang registers its reusable KV under that session. When the session ends, the application calls /close_session to release those references." Eviction ordering is "(is_referenced, session_ref_count, base_eviction_priority)" with "two LRU passes: unreferenced nodes first, then referenced nodes if more space is required." Importantly it is explicitly not a pin: "Referenced KV is soft-protected, not pinned. If unreferenced KV is insufficient, referenced entries remain evictable." It covers FULL attention ("tracks the reusable prefix path"), SWA ("reusable sliding-window tail") and Mamba ("reusable state at the session frontier").

### CLOSED-5: AgentKVShift — KV reuse for agentic memory units
- URL: https://arxiv.org/abs/2607.21604
- Evidence: READ BODY
- Detail: Published 2026-05-15 (submitted), cs.AI. Directly addresses "tool-calling KV reuse / retrieval-triggered re-encoding" in agentic memory. Problem statement: "every retrieval triggers a full re-encoding of these structured memory units into Key-Value (KV) states, which dominates prefill latency. Existing training-free KV reuse methods mitigate this by selectively recomputing a small fraction of tokens, but were designed for RAG-style raw passages and degrade on structured agentic memories." Result: "AgentKVShift achieves near full recompute performance while refreshing only 10-30% of the cache... delivers prefill speedups of 2-3.5x over no-KV-reuse on a single A100." Setup verified in the full HTML: "All experiments are run on a single NVIDIA A100 GPU, except for Qwen3-32B AMA-Bench evaluation and throughput profiling, which use a single NVIDIA H200 GPU due to memory and compute requirements."

### CLOSED-6: SideQuest — model-driven KV management for long-horizon agentic reasoning
- URL: https://arxiv.org/abs/2602.22603
- Evidence: READ BODY
- Detail: Published 2026-02-26, cs.AI. Answers "how to bound KV for long chain-of-thought + retrieval-driven agentic loops". The paper states: "In such tasks, the LLM context is dominated by tokens from external retrieval, causing memory usage to grow rapidly and limiting decode performance. While several KV cache compression techniques exist for long-context inputs, we find that existing heuristics fail to support multi-step reasoning models effectively." Method: "we frame KV cache compression as an auxiliary task executed in parallel to the main reasoning task" and "Our evaluations, using a model trained with just 215 samples, show that SideQuest reduces peak token usage by up to 65% on agentic tasks with minimal degradation in accuracy". Full HTML confirms explicit compatibility with the engine's reuse machinery: "ensuring full compatibility with prefix caching to enable efficient context reuse across multiple ReAct iterations", and the serving testbed: "we compare Sidequest against the uncompressed baseline for gpt-oss-20b (Medium Effort) on the FRAMES benchmark using a single NVIDIA H100 GPU."

### CLOSED-7: FlowKV — multi-turn isolation for KV compression
- URL: https://arxiv.org/abs/2505.15347
- Evidence: READ BODY
- Detail: Published 2025-05-21, revised v2 2025-10-08, cs.CL. The canonical answer to "repeated compression of early turns destroys multi-turn coherence". Text: "existing eviction strategies often degrade performance by repeatedly compressing early conversational context, leading to information loss and context forgetting. This paper introduces FlowKV, a novel multi-turn isolation mechanism for KV Cache management, which can be applied to any KV Cache compression method without training. FlowKV's core innovation is a multi-turn isolation mechanism that preserves the accumulated compressed KV cache from past turns. Compression is then strategically applied only to the newly generated KV pairs of the latest completed turn, effectively preventing the re-compression of older context and thereby mitigating catastrophic forgetting."

### CLOSED-8: EpiCache — episodic KV management for long-term conversation under a fixed budget
- URL: https://arxiv.org/abs/2509.17396
- Evidence: READ BODY
- Detail: Published 2025-09-22, cs.CL. Answers multi-turn LongConvQA under a bounded KV budget without unbounded prefill peak. "EpiCache bounds cache growth through block-wise prefill and preserves topic-relevant context via episodic KV compression, which clusters conversation history into coherent episodes and performs episode-specific KV cache eviction. Across three LongConvQA benchmarks (LongMemEval, Realtalk, and LoCoMo), EpiCache improves accuracy by up to 30%, achieves near full-cache accuracy under 4-6x compression, and reduces latency and peak memory by up to 2.4x and 3.7x, respectively."

### CLOSED-9: GrowPage — on-demand KV budgeting that preserves prefix caching
- URL: https://arxiv.org/abs/2609.03494
- Evidence: READ BODY
- Detail: Published 2026-09-03, cs.AI — inside the target window. Answers reasoning/thinking-model KV growth on a single GPU. "GrowPage maintains lightweight dual-timescale query summaries to capture recent and long-term attention behaviors, and uses their relative attention working sets to estimate demand evolution. ### CLOSED-10: SAECache — semantic-adaptive prefix-cache eviction with a multi-turn queue
- URL: https://arxiv.org/abs/2605.18825
- Evidence: READ BODY
- Detail: Published 2026-05-12, cs.LG. Answers "which eviction policy should a prefix cache use for agentic/multi-turn traffic". It documents the reuse-rate variance across token roles: "different token types within a prompt, including system prompts, user queries, tool outputs, model responses, and chain-of-thought reasoning, exhibit up to 756x variation in reuse rates, yet no existing eviction policy exploits this signal." Design: "a multi-queue architecture that routes KV blocks to task-specific queues with tailored priority metrics, capturing both session reuse in multi-turn requests and structural reuse in templated single-turn requests". Also records the failure mode of fixed policies: "fixed-parameter alternatives can degrade by up to 2.7x under workload mismatch". It also reports a negative integration result: "Under low-to-moderate concurrency with a single small model, vLLM's aggressive memory management rarely fills the KV cache to capacity, leading to limited eviction activity." Testbed from the HTML: a single NVIDIA A40 GPU, vLLM v0.8.5 (V0 engine), Qwen2.5-1.5B-Instruct.

### CLOSED-11: KVCache Cache in the Wild — production KV reuse characterization
- URL: https://arxiv.org/abs/2506.02634
- Evidence: READ BODY
- Detail: Published 2025-06-03, cs.DC. Canonical production measurement that bounds how much multi-turn reuse there really is. Abstract: "KV$ reuses are skewed across requests, where reuses between single-turn requests are equally important as multi-turn requests; the reuse time and probability are diverse considering all requests, but for a specific request category, the pattern tends to be predictable; and the overall cache size required for an ideal cache hit ratio is moderate." The HTML gives the more actionable finding for a single GPU: "The lifespan of KV$ is ephemeral: the P99 lifespan of KV$ in to-B workloads is 97 seconds, so a small cache is typically sufficient for the KV$ cache." Trace source: "we collected and characterized two representative production serving workloads from one of the world's largest cloud providers (Aliyun)".

### CLOSED-13: SONIC — segment-level compression of dialogue history
- URL: https://arxiv.org/abs/2601.21927
- Evidence: READ BODY
- Detail: Published 2026-01-29, cs.CL. Answers multi-turn history compression with learned rather than heuristic eviction. "The linear growth of Key-Value (KV) cache remains a bottleneck for multi-turn LLM deployment. Existing KV cache compression methods often fail to account for the structural properties of multi-turn dialogues, relying on heuristic eviction that risks losing critical context. We propose SONIC, a learning-based framework that compresses historical segments into compact and semantically rich Nexus tokens." Reported result: "at compression ratios of 80% and 50%, SONIC consistently outperforms baselines such as H2O and StreamingLLM on four diverse multi-turn benchmarks."
