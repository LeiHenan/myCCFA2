# S12: Hardware-ruled-out cells: KV techniques whose published evaluation or design REQUIRES more than one GPU, more than 96GB VRAM, NVLink, InfiniBand, or multi-node. Find the canonical reference and the exact verbatim sentence stating the hardware requirement from the paper's experimental setup section, or the issue/repo where the multi-GPU requirement appears. Also cover: context parallelism, tensor/pipeline parallelism, disaggregated multi-node clusters.

**Scope note.** Every row below was retrieved by me from the live URL shown, using `curl` through the host proxy. Local source trees (`/tmp/kvsrc/vllm-main`, `/tmp/kvsrc/sglang-main`) were read directly from disk. Where a closure was performed by the `github-actions` stale bot rather than a human maintainer, that is stated explicitly in `Closure status` (Hard Rule 6). No URL, PR number, or arXiv ID below was guessed.

**Canonical hardware requirement for this subsection (short form).** The single most load-bearing statement is from the merged vLLM DCP-for-MLA PR: *"tp_size needs to be divisible by dcp_size, because the world size does not change by dcp, it simply reuse the GPUs of TP group"* — i.e. **every context-parallel KV technique in vLLM is defined as a re-partitioning of an already-multi-GPU TP group, and is therefore structurally unavailable on one GPU.** The second is the hard validation in `vllm/config/model.py`: *"Decode context parallelism for GQA/MQA requires `--tensor-parallel-size` ({tensor_parallel_size}) to be greater than the model's total number of KV heads"* — for a GQA model with 8 KV heads this demands TP ≥ 9 (in practice ≥ 16), i.e. 9–16 GPUs minimum.

### CLOSED-5: vLLM Context Parallel Deployment doc — the written multi-GPU contract

### CLOSED-8: SGLang — shipped decode context parallelism (`--dcp-size`) with an explicit MNNVL hardware gate
- URL: https://docs.sglang.ai/advanced_features/dcp.html
- Evidence: READ BODY
- Detail: Shipped and documented. The page's own definition: "Decode context parallelism (DCP) stripes a request's MLA KV cache across ranks in an existing tensor-parallel group. With DCP size c, rank r owns position p when p mod c = r, so each rank stores and reads roughly 1/c of the cache." Its containment rule is a hard topology constraint: "A DCP group must fit inside one attention-TP group and one attention-DP replica: Topology / attn_tp_size = tp_size / attn_dp_size / attn_tp_size % dcp_size == 0. For example, TP=64, DP=4, DCP=16 creates four valid 16-rank attention replicas. DCP=32 would cross replica boundaries and is invalid." It also documents an unfixed validation gap: "Startup currently checks only tp_size % dcp_size == 0, not the stronger condition above. Until that check is fixed, DPA+DCP deployments must enforce containment when choosing the topology." The canonical multi-GPU example: "MLA decode on DeepSeek-V3.1 with DCP 8 inside TP 8: sglang serve --model-path deepseek-ai/DeepSeek-V3.1 --trust-remote-code --tp-size 8 --dcp-size 8". And a 32-GPU example: "Kimi K3 on 32 GPUs with DPA and DCP 8. The model override enables replicated Q by default; the communication backend resolves generically to fi_a2a on MNNVL systems, otherwise a2a".

- What specifically is missing: sequence parallelism for the GatedDeltaNet/linear-attention layers, and an implementation PR. The RFC is design-only: there is no merged code.
