Purpose

Text watermarking in vLLM (see #54053) currently uses a short context (4 tokens, by default) before each generated token to create the pseudorandom noise that we use to watermark its sampling. It is possible for multiple positions in a sequence to have the same context, and thus have the same watermarking bias applied. This makes gumbel watermarking single-token non-distortionary instead of single-sequence non-distortionary: expectation of token distribution, over all keys, is unchanged, but expectation of sequence distributions, over all keys, is changed. In practice, this leads to:

  • a reduced diversity of generations within a sequence, and
  • increased likelihood of poor behaviour such a repetition and infinite generations

A solution to this is context masking, or context deduplication: if a context has already been watermarked in a sequence, we do not watermark it again. This allows for single-sequence non-distortion (see section G.3 of SynthID-Text supplementary materials). An initial instinct may be that reducing the amount of tokens we watermark within a sequence will reduce the strength of our watermarking signal, but we actually already deduplicate contexts during detection to avoid biasing repetitions: we only score the first instance of a repeated context, matching what we propose for generation here. In practice however, we may imagine a case where a user will manipulate watermarked text to excluse an initial watermarking of a repeated context, only keeping the subsequent unwatermarked repetitions: this would indeed lead to a reduced watermarking signal, but this is already expected with a tampered text, and we propose that this is acceptable if it allows for increased guarantees of non-distortion.

Test Plan

Measuring impact, using standard models and methods, on:

  • degenerate generations (repetition, infinite generations)
  • output length, intra-sequence diversity
  • output quality
  • inference performance

_repeated_context_mask_kernel: serial history rescan, and a block-parallel replacement

Problem

The kernel runs one Triton program per sampled row with a scalar while loop over every previous output position, so each decode step does O(output_len · W) serial work per row with no parallelism inside the row. all_token_ids is a UVA view of pinned host memory, so every scalar load also crosses PCIe. Latency is set by the longest row and is nearly flat in batch size, so one long request taxes every co-scheduled request.

Mask kernel alone, ms per decode step, H200, W=4, production memory layout:

output_len rows=1 rows=256 rows=1024
2048 0.47 0.52 0.74
8192 1.79 2.00 2.88
32768 7.10 7.95 11.41

For scale, philox_gumbel_sample over the full 151936 vocab costs 0.04 ms at 1 row and 0.62 ms at 1024 rows.

Fix: block-parallel scan with identical semantics

Each iteration tests BLOCK candidate positions at once and reduces with tl.max. Output is bit-identical to the current kernel for W in {1, 2, 4, 16}, including padding rows (req_idx < 0) and output_len == 0. Launch with BLOCK=512; the wrapper is otherwise unchanged.

@triton.jit
def _repeated_context_mask_kernel(
    output_ptr,
    all_token_ids_ptr,
    all_token_ids_stride,
    req_indices_ptr,
    prompt_lens_ptr,
    total_lens_ptr,
    contexts_ptr,
    context_stride,
    CONTEXT_WIDTH: tl.constexpr,
    BLOCK: tl.constexpr,
):
    row = tl.program_id(0).to(tl.int64)
    req_idx = tl.load(req_indices_ptr + row).to(tl.int64)
    valid = req_idx >= 0
    safe = tl.maximum(req_idx, 0)
    plen = tl.load(prompt_lens_ptr + safe, mask=valid, other=0).to(tl.int64)
    tlen = tl.load(total_lens_ptr + safe, mask=valid, other=0).to(tl.int64)
    olen = tlen - plen
    base_ptr = all_token_ids_ptr + safe * all_token_ids_stride + plen

    repeated = False
    for start in range(0, olen, BLOCK):
        # Each lane tests one previous output position p in [start, start + BLOCK).
        pos = start + tl.arange(0, BLOCK)
        in_range = pos < olen
        match = in_range & valid
        for offset in tl.static_range(CONTEXT_WIDTH):
            # Token at output position p - CONTEXT_WIDTH + offset, -1 before output start.
            hp = pos + offset - CONTEXT_WIDTH
            tok = tl.load(
                base_ptr + tl.maximum(hp, 0),
                mask=in_range & valid & (hp >= 0),
                other=-1,
            )
            ctx = tl.load(contexts_ptr + row * context_stride + offset)
            match &= tok == ctx
        repeated |= tl.max(match.to(tl.int32)) > 0
    tl.store(output_ptr + row, repeated)

Two small things worth folding in: hoist the ctx loads out of the start loop (loop invariant, and the compiler does not hoist them), and add the contexts.stride(-1) != 1 guard that philox_gumbel_sample already has, since both kernels assume a unit last-dimension stride.

ms per step, H200, production memory layout:

output_len rows W current blocked speedup
8192 1 4 1.71 0.031 56x
8192 256 4 1.92 0.18 11x
8192 1024 4 2.87 0.72 4x
8192 1024 16 10.13 0.82 12x
32768 1 4 6.80 0.11 64x

What remains at large batch is PCIe bandwidth from scanning UVA memory; the same blocked kernel on device memory is another 10 to 40x lower. An incremental per-request context-hash array, appended to in _post_update_kernel, would make the per-step check O(1) and remove the PCIe reads entirely, but that is a larger change and the blocked scan is enough for this PR.

End to end

With the current kernel the regression grows with output length: -7% tok/s at 1500-token outputs, -18% at 6000, -21% at 8192. The residual 3 to 7% with the blocked kernel is the always-on fallback gumbel_sample (below) plus the UVA reads.

Accuracy

GSM8K test set, 300 problems, Qwen3.5-2B, temperature 1.0, max 768 tokens, key 42. The blocked kernel produces identical output to the current one, so this covers both.

mode accuracy hit token cap cap hits that are repetition loops detected at p 0.01
unwatermarked 67.0% 27.0% 3 1.3%
watermark, dedup off 68.7% 22.0% 10 71.0%

Accuracy is flat within noise. Dedup removes the repetition loops the single-key sampler introduces (10 of 66 cap hits down to 2, back at the unwatermarked baseline of 3) and detection improves slightly.

Related, independent of the kernel

With deduplicate_contexts=True the repeated_contexts is not None branch in _sample_random is always taken, so the fallback gumbel_sample plus torch.where launch on every step even when no row is masked (about +0.1 ms at 1 row, +0.95 ms at 1024 rows). Folding masked rows into philox_gumbel_sample (seed/pos noise for those rows) would remove the second full-vocab kernel.
