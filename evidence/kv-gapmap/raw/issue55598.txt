 [RFC]: [Tracking] Heterogeneous-TP KV sharing in Mooncake Store Connector #55598 
 Copy link 
 Description
 z-zanez 
 opened on Sep 6, 2026 
 Issue body actions 
 Motivation
 Mooncake Store originally tied object keys and payload layout to the local TP
rank. Two vLLM instances using the same model but different TP sizes therefore
produced different shard counts, KV-head ranges, and namespaces and could not
reuse each other's persisted KV cache.
 The long-term goal is a stable Store representation that is independent of an
endpoint's local TP layout. Compatible Prefill and Decode instances should be
able to load and extend the same prefix through one Store pool, including
Decode writeback and deployments with more than one Prefill TP size.
 This issue tracks heterogeneous-TP sharing in MooncakeStoreConnector , from
Full Attention to hybrid Attention + Mamba/GDN caches.
 Progress
 [KV Connector] Add decode offloading to Mooncake Store consumers #52466 adds Decode-side Store writeback, which is required for a Decode
instance to extend a prefix in the shared Store namespace.
 [KV Connector] Support heterogeneous TP sharing in Mooncake Store Connector #53129 adds a common Store TP layout for Full Attention. Local TP ranks
map to stable Store shards, allowing supported TP4/TP2/TP1 instances and
multiple Prefill TP sizes to reuse and update the same Store entries.
 [KV Connector] Support heterogeneous TP sharing for hybrid KV cache in Mooncake Store #54307 extends the Store representation to unified hybrid KV caches.
Attention uses TP-independent Store chunks, while Mamba/GDN uses complete
recurrent-state checkpoints.
 Proposed approach and currently supported Store sharing model
 All endpoints select the same stable Store TP size and PP size.
 Store TP is at least the local TP size and divisible by it.
 Attention head slots map integrally to Store shards; MQA and replicated GQA
use replication-aware mappings.
 A common Store TP can be selected for several Prefill TP sizes, allowing one
Decode service to reuse entries produced by different Prefill deployments.
 Unsupported configurations fall back to the existing rank-local namespace
instead of sharing Store objects.
 Planned follow-ups
 Land and stabilize hybrid Attention + Mamba/GDN Store sharing in [KV Connector] Support heterogeneous TP sharing for hybrid KV cache in Mooncake Store #54307 .
 Design a finer canonical Store-shard representation for useful
non-divisible TP combinations where Store TP % local TP != 0 .
