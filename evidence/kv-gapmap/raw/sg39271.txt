 Describe the bug
 A request whose input length is close to the KV cache capacity can pass request validation but can never be admitted by PrefillAdder .
 This can permanently block the affected scheduler rank after the request is cancelled. The problem is in CPU-side scheduler admission and state management, so it can be reproduced without a GPU or model execution.
 The production configuration that originally exposed the problem had:
 KV capacity per DP rank: 190,784 tokens
 Page size: 64
 Advertised maximum input threshold: 190,778 tokens
 Stable triggering input range: 190,720–190,777 tokens
 For these requests, init_req_max_new_tokens() clips max_new_tokens to zero. However, PrefillAdder additionally reserves one allocator page and requires:
 input_length + max_new_tokens + page_size < available_kv_tokens 
 For an input length of 190,720:
 190720 + 0 + 64 >= 190784 
 The request therefore returns NO_TOKEN and is not added to PrefillAdder.can_run_list , even though it passed the public input-length validation.
 The scheduler then persists running_batch.batch_is_full=True . On later scheduling iterations, _get_new_batch_prefill_raw() checks this flag before traversing the waiting queue and returns early.
 After the problematic request is cancelled:
 the waiting request is removed,
 the running batch is empty,
 KV usage is zero,
 but batch_is_full remains True . A short follow-up request routed to the same scheduler rank is never considered, and subsequent requests remain queued indefinitely.
 Restarting the server is the only observed recovery method.
 Expected behavior:
 Requests that can never satisfy PrefillAdder admission should be rejected at request intake.
 batch_is_full should be invalidated after the running batch becomes empty.
 Cancelling one request must not permanently block future requests on that scheduler rank.
 Reproduction
 The following state-level reproduction uses the real SGLang request validation, PrefillAdder , and scheduler prefill loop. It does not require a GPU or model weights.

 from types import SimpleNamespace 
 from unittest . mock import MagicMock , patch 
 from sglang . srt . managers . schedule_batch import Req 
 from sglang . srt . managers . schedule_policy import AddReqResult , PrefillAdder 
 from sglang . srt . managers . scheduler import Scheduler 
 from sglang . srt . managers . utils import validate_input_length 
 from sglang . srt . mem_cache . base_prefix_cache import (
 DecLockRefResult ,
 IncLockRefResult ,
)
 capacity = 190_784 
 page_size = 64 
 input_len = 190_720 
 # get_worker_info() previously advertised max_req_len - 5. 
 public_threshold = capacity - 6 
 req = MagicMock ( spec = Req )
 req . rid = "near-capacity" 
 req . origin_input_ids = list ( range ( input_len ))
 req . full_untruncated_fill_ids = list ( range ( input_len ))
 req . prefix_indices = []
 req . output_ids = []
 req . sampling_params = SimpleNamespace (
 max_new_tokens = 0 ,
 ignore_eos = False ,
)
 req . retracted_stain = False 
 req . host_hit_length = 0 
 req . storage_hit_length = 0 
 req . storage_hit_start = None 
 req . host_hit_is_storage = False 
 req . host_loaded_length = 0 
 req . last_node = MagicMock ()
 req . needs_host_load_back . return_value = False 
 validation_error = validate_input_length (
 req ,
 public_threshold ,
 allow_auto_truncate = False ,
)
 tree_cache = MagicMock ()
 tree_cache . disable = False 
 tree_cache . supports_mamba . return_value = False 
 tree_cache . evictable_size . return_value = 0 
 tree_cache . full_evictable_size . return_value = 0 
 tree_cache . inc_lock_ref . return_value = IncLockRefResult ()
 tree_cache . dec_lock_ref . return_value = DecLockRefResult ()
 allocator = MagicMock ()
 allocator . available_size . return_value = capacity 
 running_for_adder = MagicMock ()
 running_for_adder . reqs = []
 adder = PrefillAdder (
 page_size = page_size ,
 tree_cache = tree_cache ,
 token_to_kv_pool_allocator = allocator ,
 running_batch = running_for_adder ,
 new_token_ratio = 1.0 ,
 rem_input_tokens = capacity ,
 rem_chunk_tokens = None ,
)
 result = adder . add_one_req (
 req ,
 has_chunked_req = False ,
 truncation_align_size = None ,
)
 # Reproduce the state after NO_TOKEN, cancellation of the long request, 
 # and arrival of a short follow-up request. 
 scheduler = object . __new__ ( Scheduler )
 scheduler . grammar_manager = SimpleNamespace (
 has_waiting_grammars = lambda : False 
)
 scheduler . enable_hierarchical_cache = False 
 scheduler . enable_unified_cache_external_linker = False 
 scheduler . enable_priority_preemption = False 
 scheduler . is_hybrid_swa = False 
 scheduler . chunked_req = None 
 scheduler . waiting_queue = [
 SimpleNamespace ( rid = "short-follow-up" ),
]
 empty_running_batch = SimpleNamespace (
 batch_is_full = ( result == AddReqResult . NO_TOKEN ),
 is_empty = lambda : True ,
)
 with patch (
 "sglang.srt.managers.scheduler.get_memory" ,
 return_value = SimpleNamespace ( enable_flexkv = False ),
):
 batch_to_run , _ = Scheduler . _get_new_batch_prefill_raw (
 scheduler ,
 None ,
 empty_running_batch ,
 )
 print ( f"public_threshold= { public_threshold } " )
 print (
 "input_validation=" 
 f" { 'accepted' if validation_error is None else 'rejected' } " 
)
 print ( f"prefill_result= { result . name } " )
 print ( f"request_admitted= { req in adder . can_run_list } " )
 print ( f"follow_up_scheduled= { batch_to_run is not None } " )
 print (
 "batch_is_full_after_empty_iteration=" 
 f" { empty_running_batch . batch_is_full } " 
)
 assert validation_error is None 
 assert result == AddReqResult . NO_TOKEN 
 assert req not in adder . can_run_list 
 assert batch_to_run is None 
 assert empty_running_batch . batch_is_full 
 print ( "BUG_REPRODUCED" )

BUG_REPRODUCED
 A sweep of the original triggering interval produced the same admission mismatch for all 58 input lengths from 190,720 through 190,777.
 For comparison, the proposed fix changes the effective threshold to 190,720 and clears the stale state after the running batch becomes empty:
 public_threshold=190720
input_validation=rejected
prefill_result=NO_TOKEN
request_admitted=False
batch_is_full_after_empty_iteration=False
FIX_CONFIRMED

 This state-level reproduction does not load or execute any model. It directly exercises the CPU-side scheduler admission and stale-state logic using mocked KV/cache objects.
